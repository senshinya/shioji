# 会话反馈

原生会话底部按状态面板、待处理请求、消息输入框排列；首页的状态也位于输入框上方。输入框下方不再放提示文字。审批、提问、权限、MCP 表单与恢复共用单层中性灰表面，真实输入控件保留边界。恢复的进程列表直接用行和分隔线组织；停止确认替换详情，仍须执行原有 worker 核对。

| 内容 | 位置与操作 |
| --- | --- |
| 提交结果待核对 | 状态分页；只查询原操作 ID，保留原文及附件，不重发 |
| 历史操作待核对 | 状态分页；查询或取消原操作 |
| 分叉已保存、尚待完成 | 状态分页；继续完成或取消 |
| 原消息消失后的修改稿 | 状态分页；复制或放弃独立修改稿 |
| 会话归档 | 紧凑状态行；恢复会话 |
| 工作区归档 | 紧凑状态行；恢复工作区 |
| 持续断线 | 400 ms 后先显示等待消息，5 s 后迁入状态分页；重连或设备详情 |
| Agent 未就绪 | 状态分页；所属设备详情 |
| 执行分支改变 | 状态分页；核对所属设备的分支 |
| 附件／引用准备失败 | 状态分页；重试失败附件，正文保留 |
| 草稿保存失败 | 状态分页；重试保存或复制草稿 |
| 执行恢复 | 状态分页；沿用实际恢复、进程选择、确认和接续操作 |
| 其他执行阻塞 | 状态分页；分支核对与设备详情，保留草稿和队列 |

短暂附件准备、用户提交时的分支核对、一次操作失败、取消结果、复制成功、重连成功和后台来源反馈在右上角展示。摘要使用固定语义文案，任意错误只进入去除认证信息的详情。模型下线仍沿用模型名标红与菜单悬停原因，不新增提示条。

浮层上下内边距均为 8 DIP、左右 12 DIP。图标和设备来源行使用相同字体度量与真实文字基线；标题与操作沿来源文字列排列，文字操作取消按钮默认横向内缩。来源包含实际设备、工作区和会话。消息按完整作用域和操作标识更新，最近消息最多保留 30 条。最近消息列表采用无分割线的紧凑行，只显示单行标题和单行摘要，超长省略，完整来源在悬停及辅助说明中提供。点击或用方向键与 Enter 选择条目会关闭列表并重新弹出该消息，不跳转会话、不复制或重排历史；成功和解释类消息重新按原时长计时。成功 4 s、解释 6 s，失败由用户关闭；悬停、键盘聚焦和回看期间暂停计时。关闭消息不解除权威状态。背景回执不改变当前草稿和导航。浮层按来源／标题、说明、展开详情、操作组织；操作位于底部同一行，详情在其上方展开。长说明在有界区域滚动，标题和操作保持可见；没有正文和操作时不保留空内容区。

状态与请求各使用自己的分页，一次各显示一项。手动选定的状态不会因新项目插入而跳页；正在回答时新状态默认收起。普通提交等待回执时不显示“结果待核对”，仅断线、未知结果或重启后未核实的操作进入该状态。

## 原生验证

`conversation_feedback_test.go` 覆盖位置、作用域、原操作查询、普通提交、延迟连接迁移、等待结束、去重与有界记录、悬停计时、状态分页、草稿与答案保留以及浮层上下间距。请求与恢复沿用既有原生交互回归。`recent_feedback_test.go` 核对缩略行、键盘与鼠标回放、来源及历史保留、重新计时；`feedback_popup_test.go` 核对同排操作、详情顺序、长文滚动时固定操作、空内容等距，并提供展开、收起和快速反向的原生录制。

录制使用生产 `View` 与 MyGo Native Tester，数据来自明确的本地夹具；不连接真实设备、不调用模型、不证明传输或进程恢复能力。浅色 1240×820、深色窄窗口 920×820 的录像覆盖消息关闭、问题选择与分页、状态到达及快速反向折叠、状态解除、恢复详情、进程选择、停止确认取消和最近消息。证据保存在原设计画板的 Verify 页。

复现：

```sh
env -u GOROOT SHIOJI_FEEDBACK_RECORDING=/tmp/shioji-feedback-light go test ./internal/ui -run TestConversationFeedbackNativeRecording -count=1
env -u GOROOT SHIOJI_FEEDBACK_RECORDING=/tmp/shioji-feedback-dark SHIOJI_FEEDBACK_DARK=1 SHIOJI_FEEDBACK_NARROW=1 go test ./internal/ui -run TestConversationFeedbackNativeRecording -count=1
```
