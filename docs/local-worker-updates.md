# 设备执行服务的版本与更新

本机复用自动安全更新；SSH 设备只在明确请求更新后，通过严格 SSH 暂存签名与摘要均通过验证的自有 worker，沿用同一空闲准入和备份流程。连接中断只核对回执，不重发未知更新。设备页显示实际 worker、Agent 与后台服务状态；不推进 Tailnet。

- 握手报告启动时捕获的二进制摘要、构建时间／修订和执行服务能力；不能重读后来被替换的磁盘路径来冒充正在运行的版本。协议版本与构建身份分开。旧服务没有元数据时明确标为旧版／版本未报告，不假定支持新功能。
- 随应用构建的本机 worker 先验证签名和摘要，复制到本机私有的内容寻址更新目录，预检候选协议及数据库 schema。更新仅使用随应用提供的自有二进制，保留实际启动参数和环境，不改 Codex、账号或认证。
- worker 在派发串行边界及更新准入边界内确认没有活动轮、待处理请求、未知投递、未完成历史操作或命名请求；受管进程必须证明没有仍在运行的工具及未知后台后代。忙碌只报告等待，不停止任务。排队项保留，更新接纳时暂停派发。
- 接纳后拒绝新写操作／执行，保存包含 WAL 的一致 SQLite 备份；旧 worker 正常关闭自身资源，再以相同目录和参数执行新二进制。GUI 或连接断开不重复提交输入。失败保持明确恢复状态；迁移后的数据库不交给不兼容的旧版本回退。
- 本机新包比当前服务新时自动尝试安全更新，忙碌后延后重试；设备详情提供实际版本、等待／更新／失败状态及显式重试入口。较新服务不被旧客户端自动降级，未知构建时间只允许显式更新。旧版若不支持安全更新握手，只提示手动更新，不用 PID 信号猜测安全状态。

验证：握手新旧兼容、启动身份不随路径替换变化、不同版本／能力识别；有活动执行、审批、未知投递、后台工具时拒绝；队列和设备／工作区／会话身份保留、数据库备份含 WAL；更新期间并发提交不接纳、丢失回执不重发、重连后草稿与未确认输入仍按既有查询恢复；真实签名开发包的隔离 worker 更新及原生亮暗状态动画。

## Codex 正常升级

Codex 的版本号用于诊断，不作为精确白名单。adapter 在启动时解析实际安装路径，让同一次启动的执行器和 App Server 使用同一份可执行文件；读取该文件导出的 experimental JSON schema，检查实际依赖的方法、上下文字段和安全参数，并继续执行真实 initialize、目录与权限确认。新增可选字段可以直接兼容；缺少可选的 Skill、Steer、计划、历史／分叉能力时关闭对应功能，不以别的操作冒充。必需协议缺失或增加无法提供的必填参数时，明确报告具体方法，不修改或降级用户安装。探测缓存按实际路径、文件身份、大小、修改时间和可执行权限失效。

worker 每 5 秒检查 adapter 报告的安装身份，客户端轮询也可唤醒检查；不依赖 GUI 在线。身份在 adapter 内生成，共享层只比较 opaque 值。目录以 ready／refreshing／unavailable 显式状态切换，真实进程的模型与能力确认后再发布。标题、Skill 和历史读取借用同一目录的读锁，刷新只在无借用时进行；刷新期间保留最近目录，延后队列派发，失败按安装身份限速重试，新安装变化立即重新检查。

正在执行的会话保留原进程与当前轮控制能力；客户端仅查询当前两条会话的实际运行能力。普通下一轮和队列按新目录校验。原模型已下线时保留名称、配置和草稿，模型名标红、发送禁用；悬停说明原因，点击原有模型入口更换，不增加独立提示条，阻止新输入接纳，不自动替换。更换模型后，空闲会话在下一次接纳输入时才切换安装；若仍有轮次、待处理请求或后台工具，不强行关闭旧进程。明确退休的实例关闭事件与新代执行隔离。历史源前缀可由旧进程准备，新输入按最新目录和实际激活进程重新校验，通过后才提交历史替换。

此预检核对请求形状，不承诺任意未来协议的语义兼容；运行时仍验证执行上下文、请求结果和投递是否确认。0.166.0 的冻结录制保持不变，0.167.0 使用真实本机 App Server 与隔离测试 provider 验证，不用模拟进程替代协议和受管执行。


## 设备页与后台服务

设备名称为客户端内的显示别名，本机和远程均可改名并持久化，不修改系统主机名或稳定 DeviceID。本机没有网络连接状态或重连入口；远程保留 SSH 状态、RTT 与按需展开的连接详情。Agent 名称与状态左侧上下排列，开关独立位于右侧；路径编辑、技术详情和错误使用真实高度过渡。

添加 SSH 设备先检查连接，再配置和核验选中的 Agent，成功后才保存连接。配置由所属 worker 原子保存；空选择在设备详情中表示停用全部，不能在重启时变回默认全开。已有活跃会话保留其原运行时及控制能力，路径变更只用于后续启动。安装、认证与协议问题由 adapter 给出中立诊断；远程登录命令始终携带对应 SSH 地址和端口。

随应用签名的 Shioji Runtime.app 使用 SMAppService 用户级 LaunchAgent。开关按实际系统注册状态显示，requiresApproval 不伪装为已授权运行。注销会终止被托管进程，因此协议 minor 17 将关闭准入交给 worker：在维护与派发边界内核对活动任务、请求、未确认执行和工具进程，空闲后保留队列并封闭新执行，再注销服务。应用核对系统确已注销后启动同一设备的独立 worker，不重发任何输入；旧托管版本先升级，不能跳过这道边界。私有开发目录不注册正常系统服务。
