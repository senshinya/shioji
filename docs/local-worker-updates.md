# 设备执行服务的版本与更新

2026-11-17 已在源码接入 Lody 的固定 supervisor、在线准备、业务空闲准入、主动排空、候选提交与一次兼容回退。以下说明当前源码行为；不表示已替换本机、MBP at Work 或 MBA at Home 的正式服务。完整依据见[源码分析](lody-worker-lifecycle-analysis.md)与[实施方案](ryugi/specs/2026-11-16-worker-upgrade-lifecycle-design.md)。

- 固定服务只拥有升级控制与签名制品选择；实际 worker 子进程继续持有原 `owner.lock`，不删除或替换锁文件。正常候选必须等源服务真正退出、最后事件持久化并产生准确 drained 回执后才能打开同一业务库。
- 签名和摘要通过的候选在旧服务工作时准备，并在隔离目录预检。默认等待真实活动轮、初始化、审批／问题和未决投递结束；闲置 MCP、Node 与其他已登记常驻工具是退出目标，不再是等待条件。切换前重新核对业务准入。
- worker 关闭共用 7 秒硬预算；会话、目录、标题执行与资源并行收尾。未在截止内释放或写入失败不报成功 drained，固定入口保留 blocked。候选以暂停接纳启动，真实本地 ready、选中制品与回执落盘后才恢复接纳；普通固定入口升级允许兼容旧版回退一次。
- 本机新包自动尝试更新；SSH 设备只在明确更新操作后，通过严格 SSH 暂存签名制品。客户端发送前持久化稳定 ID，断连或回执丢失只查询原操作；业务 socket 不可用时仍能通过独立控制入口或只读回执查询。不重发未知输入，也不借升级更改 Tailnet、Codex 认证、SSH 权限或设备身份。
- 等待中可直接取消更新，或在一次简短影响确认后立即更新。旧“查看阻塞”、环境选择页、强制恢复页及会话／待核对面板中的强制入口已完整删除；不会隐藏到高级菜单。极端 blocked 保留具体失败原因、重试和可信兼容安装路径。冷修复必须确认原 writer 与登记进程均已退出，不能按名称结束进程或绕过存活候选。
- 旧版首次迁移不要求旧 worker 提供新控制 RPC：签名 helper 先准备，核对实际 Unix endpoint 的内核 peer 身份，结束准确旧 writer 后取得原锁、重读最终状态、回收已登记进程并生成一致备份。历史维护 JSON 原文归档，旧 partial fence 被归档而非伪造成功；未知执行仍按源历史核对。旧版缺少新 paused/drained 协议，因此首次迁移在旧服务退出后失败时进入 blocked 与冷修复，不声称能安全自动回到旧协议。
- 闲置运行环境在 20 分钟后回收，每 30 秒扫描；实际原生后台等待保护至 24 小时。Stop 等待准确轮次及原请求真实收尾，5 秒超时则回收捕获的运行代次。归档接纳同事务保存回收待办并立即异步回收，保留历史／草稿，恢复或阅读不自动启动环境、续答或派发队列。

验证分为正式源码回归、隔离签名 worker 进程迁移及原生 UI 夹具。隔离迁移使用真实 Codex App Server 和本地测试 provider，不使用真实账号／模型网络；未以这些证据宣称三台正式设备已升级。证据与独立审阅结果见本地 `verify/worker-upgrade-lifecycle`。

## 2026-11-15 本机授权重启恢复

本次故障出在一次性开发重启程序 `build/worker-idle-fix/control/main.go`，不是安全更新接口：它保存一致性备份及 active-worker 后发送 SIGTERM，随后只接受 ESRCH／ENOENT 作为进程消失的证据。Darwin 查询已退出 PID 时可以成功返回零字节，`unix.SysctlKinfoProc` 将它转换为 EIO；程序因此在旧 worker 正常退出后提前返回，没有启动候选 worker。现场对旧 PID 13787 的原生 sysctl 查询证实返回零字节，对存活 PID 则返回完整记录。生产进程核对路径已处理此条件（`internal/worker/process_darwin.go`），不能把任意 EIO 都当作进程退出；应使用同时核对 `kill(pid, 0)` 的既有逻辑，或支持空列表的进程查询。

恢复时保留原始失败记录与数据库备份，验证已接纳制品签名后，通过该制品的 `--ensure` 启动原状态目录。真实握手确认构建 `29655f35491d9eee1614b24c2c140a982dc8fa2ce4e94a79cefca4811b8e8bc0` 和原设备 ID，快照请求成功；数据库与备份 quick_check 均为 ok。App 的两个本地 socket 已重新连接新 worker，独立 Tailnet 后台保持运行；2 个工作区、6 个会话仍存在，两段中断会话保持 interrupted，未重发输入。一次性 launchd 任务已自行注销，不应再次运行旧重启程序。GUI 可视状态未核验：电脑控制工具未授权访问 Shioji。

## Codex 正常升级

Codex 的版本号用于诊断，不作为精确白名单。adapter 在启动时解析实际安装路径，让同一次启动的执行器和 App Server 使用同一份可执行文件；读取该文件导出的 experimental JSON schema，检查实际依赖的方法、上下文字段和安全参数，并继续执行真实 initialize、目录与权限确认。新增可选字段可以直接兼容；缺少可选的 Skill、Steer、计划、历史／分叉能力时关闭对应功能，不以别的操作冒充。必需协议缺失或增加无法提供的必填参数时，明确报告具体方法，不修改或降级用户安装。探测缓存按实际路径、文件身份、大小、修改时间和可执行权限失效。

worker 每 5 秒检查 adapter 报告的安装身份，客户端轮询也可唤醒检查；不依赖 GUI 在线。身份在 adapter 内生成，共享层只比较 opaque 值。目录以 ready／refreshing／unavailable 显式状态切换，真实进程的模型与能力确认后再发布。标题、Skill 和历史读取借用同一目录的读锁，刷新只在无借用时进行；刷新期间保留最近目录，延后队列派发，失败按安装身份限速重试，新安装变化立即重新检查。

正在执行的会话保留原进程与当前轮控制能力；客户端仅查询当前两条会话的实际运行能力。普通下一轮和队列按新目录校验。原模型已下线时保留名称、配置和草稿，模型名标红、发送禁用；悬停说明原因，点击原有模型入口更换，不增加独立提示条，阻止新输入接纳，不自动替换。更换模型后，空闲会话在下一次接纳输入时才切换安装；若仍有轮次、待处理请求或后台工具，不强行关闭旧进程。明确退休的实例关闭事件与新代执行隔离。历史源前缀可由旧进程准备，新输入按最新目录和实际激活进程重新校验，通过后才提交历史替换。

此预检核对请求形状，不承诺任意未来协议的语义兼容；运行时仍验证执行上下文、请求结果和投递是否确认。0.166.0 的冻结录制保持不变，0.167.0 使用真实本机 App Server 与隔离测试 provider 验证，不用模拟进程替代协议和受管执行。


## 设备页与后台服务

设备名称为客户端内的显示别名，本机和远程均可改名并持久化，不修改系统主机名或稳定 DeviceID。本机没有网络连接状态或重连入口；远程保留 SSH 状态、RTT 与按需展开的连接详情。Agent 名称与状态左侧上下排列，开关独立位于右侧；路径编辑、技术详情和错误使用真实高度过渡。

添加 SSH 设备先检查连接，再配置和核验选中的 Agent，成功后才保存连接。配置由所属 worker 原子保存；空选择在设备详情中表示停用全部，不能在重启时变回默认全开。已有活跃会话保留其原运行时及控制能力，路径变更只用于后续启动。安装、认证与协议问题由 adapter 给出中立诊断；远程登录命令始终携带对应 SSH 地址和端口。

随应用签名的 Shioji Runtime.app 使用 SMAppService 用户级 LaunchAgent。开关按实际系统注册状态显示，requiresApproval 不伪装为已授权运行。注销会终止被托管进程，因此协议 minor 17 将关闭准入交给 worker：在维护与派发边界内核对活动任务、请求、未确认执行和工具进程，空闲后保留队列并封闭新执行，再注销服务。应用核对系统确已注销后启动同一设备的独立 worker，不重发任何输入；旧托管版本先升级，不能跳过这道边界。私有开发目录不注册正常系统服务。

## 历史：已移除的后台环境人工处理流程

支持 `WorkerBuild.Maintenance` 的设备在“等待空闲更新”旁提供“查看阻塞”。清单由所属 worker 读取：正在执行、等待审批／回答、执行结果未知的会话只能查看；会话已结束但受管环境仍有进程时，可以选择整个会话环境。无法验证归属的对象只提供诊断，不按进程名称批量结束。

1. 打开设备详情，点击“查看阻塞”，核对设备、会话与进程详情。
2. 选择需要结束的后台环境，点击“结束所选环境并更新”。确认框列出范围；内存变量及尚未写入的状态可能丢失，文件不会回滚，历史和草稿保留，所选待发队列暂停。
3. 正常关闭等待 5 秒后仍未退出，面板停在“部分后台进程未退出”。再次核对并单独确认“强制结束”才允许立即终止原运行代次。归属变化时拒绝处理，需要重新检查。
4. 所选环境退出后重新走全设备空闲检查、SQLite 一致备份及候选替换；其他会话可以继续运行，更新等待其真实结束。新 worker 读取同一操作并核对构建后才报告成功。

“取消本次处理”撤销后续更新及尚未发送的关闭动作；已经发出的退出请求无法撤回。待发队列保持暂停。关闭面板、退出 GUI 或网络断开不会取消设备已接纳的操作。客户端持久化操作标识，重连只查询，不重发停止。worker 异常退出及用户取消后，仍存活的原运行代次保留正常／强制授权记录，普通恢复不能绕过第二次确认。

候选二进制在任何停止动作之前检查签名、摘要、协议及 schema；确认范围还要原子核对设备身份、会话与队列修订、运行代次及 OS 进程身份。此功能不控制 Tailnet，不关闭 SSH 桥或无归属进程。维护记录及运行代次保护要求数据库 schema 13（schema 12 已由归档功能使用），不能自动降级到会忽略这些保护的旧版。

旧 worker 未声明该能力时，仍显示其实际等待原因和原有更新入口，不从客户端扫描进程伪造清理能力。首次安装该功能若已经被旧环境阻塞，需要逐项核对具体进程并取得明确授权进行恢复；本功能覆盖 worker 可响应且能够验证其受管进程的情形。

验证包含真实 TERM 忽略进程、正常关闭与显式强制、外部 worker SIGKILL 后重启、取消后再次重启、两个认证客户端查询与取消收敛，以及生产 MyGo View 的亮暗／窄窗口渲染和确认交互。测试使用隔离设备状态，未对用户的执行环境发送停止动作。
