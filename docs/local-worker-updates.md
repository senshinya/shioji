# 本机执行服务的版本与更新

本轮实现用户确认的本机流程，SSH 设备只展示实际版本，不自动部署或更新；不推进 Tailnet。复用原生设备详情的运行环境区域和既有灰阶、基线、实际高度及文字切换动画。

- 握手报告启动时捕获的二进制摘要、构建时间／修订和执行服务能力；不能重读后来被替换的磁盘路径来冒充正在运行的版本。协议版本与构建身份分开。旧服务没有元数据时明确标为旧版／版本未报告，不假定支持新功能。
- 随应用构建的本机 worker 先验证签名和摘要，复制到本机私有的内容寻址更新目录，预检候选协议及数据库 schema。更新仅使用随应用提供的自有二进制，保留实际启动参数和环境，不改 Codex、账号或认证。
- worker 在派发串行边界及更新准入边界内确认没有活动轮、待处理请求、未知投递、未完成历史操作或命名请求；受管进程必须证明没有仍在运行的工具及未知后台后代。忙碌只报告等待，不停止任务。排队项保留，更新接纳时暂停派发。
- 接纳后拒绝新写操作／执行，保存包含 WAL 的一致 SQLite 备份；旧 worker 正常关闭自身资源，再以相同目录和参数执行新二进制。GUI 或连接断开不重复提交输入。失败保持明确恢复状态；迁移后的数据库不交给不兼容的旧版本回退。
- 本机新包比当前服务新时自动尝试安全更新，忙碌后延后重试；设备详情提供实际版本、等待／更新／失败状态及显式重试入口。较新服务不被旧客户端自动降级，未知构建时间只允许显式更新。旧版若不支持安全更新握手，只提示手动更新，不用 PID 信号猜测安全状态。

验证：握手新旧兼容、启动身份不随路径替换变化、不同版本／能力识别；有活动执行、审批、未知投递、后台工具时拒绝；队列和设备／工作区／会话身份保留、数据库备份含 WAL；更新期间并发提交不接纳、丢失回执不重发、重连后草稿与未确认输入仍按既有查询恢复；真实签名开发包的隔离 worker 更新及原生亮暗状态动画。

## Codex 正常升级

Codex 的版本号用于诊断，不作为精确白名单。adapter 在启动时解析实际安装路径，让同一次启动的执行器和 App Server 使用同一份可执行文件；读取该文件导出的 experimental JSON schema，检查实际依赖的方法、上下文字段和安全参数，并继续执行真实 initialize、目录与权限确认。新增可选字段可以直接兼容；缺少可选的 Skill、Steer、计划、历史／分叉能力时关闭对应功能，不以别的操作冒充。必需协议缺失或增加无法提供的必填参数时，明确报告具体方法，不修改或降级用户安装。探测缓存按实际路径、大小和修改时间失效。

已运行的 catalog 和会话不会因为安装目录变化被主动重启；本轮保证新 adapter 启动时重新适配，catalog 运行中自动换版尚未实现。

此预检核对请求形状，不承诺任意未来协议的语义兼容；运行时仍验证执行上下文、请求结果和投递是否确认。0.166.0 的冻结录制保持不变，0.167.0 使用真实本机 App Server 与隔离测试 provider 验证，不用模拟进程替代协议和受管执行。
