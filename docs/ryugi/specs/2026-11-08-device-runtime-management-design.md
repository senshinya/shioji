# 设备运行环境与后台服务

用户授权实施推荐列表的 1、2、3 项。沿用 Go、MyGo 原生界面和所属设备 worker；不推进 Tailnet，不增加 Git 操作或会话导出。

## 交付

1. SSH 设备显示随应用 worker 的可用版本；只在明确点击更新后上传，经严格 SSH、摘要和签名验证暂存。复用 worker 的空闲准入、一致备份和替换握手；忙碌后等待，失去回执只重连检查，不重发用户输入。不降级较新服务，不强停旧服务。上传／更新必须绑定已连接的设备身份和连接代次。远端原桥接路径保留。
2. 设备详情中提供每个 harness 的可执行文件配置、检测状态、重新检测与安装／登录指导。配置由所属 worker 持久化；中间层只包含路径、就绪原因与中立操作，具体协议、认证检查和说明由 adapter 翻译。默认自动发现路径，明确配置路径必须是设备上的绝对可执行普通文件。检测不读取或传输凭据，不以本地路径解析远端目录。不替用户安装、登录或覆盖第三方程序。已有运行保持原进程，配置用于后续轮次。实际认证拒绝与缺失、协议不兼容、一般不可用分别表达；未知原因不猜为认证失败。
3. 随应用包含自有 Shioji Runtime.app，固定安装在所属用户的 Application Support/Shioji/Runtime。通过 SMAppService.agent 注册 bundle 内用户级服务；仅用户点击启用后注册，不绕过 requiresApproval 或用户关闭。区分未安装、未注册、已启用、需要批准、不支持和失败。已启用不等于当前 worker 已受系统管理。注册遇到已有开发 worker 只等待其生命周期结束，不创建第二个 owner 或打断工作。

## 后台宿主

独立 Go 宿主仅负责 ServiceManagement 注册／状态和 launchd 入口，无窗口，不是 Swift 前端。launchd 入口使用当前用户固定 worker 目录，等待已有 owner 退出，再由正常 worker 锁与进程所有权校验接管。设置 Aqua 登录域、RunAtLoad 和失败重启；不承诺登录前、注销后或 FileVault 解锁前运行。SMAppService 实际系统授权由 macOS 决定。

运行中的系统服务保持 launchd PID，worker 更新沿用 exec。成功接受更新时持久化已验证的内容寻址 worker 标识，宿主下次启动验证并执行同一制品；不在启动时回到过期 bundle worker。普通开发／隔离目录不读写正常用户后台服务设置。Runtime.app 的固定服务格式保持有版本兼容检查，不能静默覆盖未知既有宿主或修改签名身份。

## 原生界面

继续使用现有设备集合与详情，运行环境区域增加路径配置及对应操作，后台服务单独一个紧凑分组。灰阶分隔、13px 标签、12px 操作、28px 按钮，使用现有字体度量／图标槽位。不增加高卡片或冗余说明。新增结果、进度、路径编辑展开同步实际高度及文字过渡，切换设备沿用现有行为；减少动态效果直接切换。所有异步完成校验设备／连接代次，不抢会话焦点或清理草稿。

## 检查

回归覆盖远端上传不自动执行、错误主机／设备／代次拒绝、忙碌等待与空闲接续、无重复提交；配置持久化、错误路径、认证分类及真实 app-server 无账号夹具；后台注册状态、既有 owner 保留、制品与重新启动版本、系统拒绝不伪造成功。执行完整 Go 测试、相关 race、vet、冻结稿与录制校验、签名构建；隔离状态验证 SMAppService 真实注册和清理，亮暗原生截图放本地 Ryugi 验收页。不为测试重启用户 Mac 或正常 worker。

参考：Apple SMAppService 与 agent(plistName:) 文档；OpenAI Docs 的 Codex app-server／登录状态文档。技术与平台限制按真实运行结果记录。

## 用户修订：设备的 Agent 配置入口

添加设备采用连接检查→选择和配置 Agent→核验后添加的流程；不能连接成功便直接写入设备列表。设备详情保留添加／编辑 Agent 的入口，与添加流程复用配置表单。详情中的 Agent 行只展示当前已配置集合及状态，不常驻可执行路径编辑栏。可选择多个实际已注册的 harness；当前只有 Codex，不展示虚构的 Claude 等选项。选择和路径由所属 worker 原子持久化，已有会话与其进程不因编辑而停止。已有设备保留原有配置；这台 Mac 的配置也用相同表单。

## 已确认的设备页设计（2026-11-08）

用户在交互设计稿上修订后明确“开始实现”。原生页采用设备集合与详情，顺序为设备身份、Agent、执行服务、工作区、远程连接。名称与状态左侧上下排列，右侧只留动作或开关。“检查更新”“重新连接”等次级文字操作统一 28px、12px、无底色无描边，hover 灰底。登录后保持运行使用与 Agent 相同的灰阶 switch，支持注册与注销；系统批准与失败仍呈现真实状态。点击编辑后，标题在同一行直接变为同字号输入栏，右侧为确认与取消图标，下方分区不位移。本机及远程都能修改应用内显示名称；不改系统主机名、稳定身份或连接。别名沿用客户端连接名称的持久化边界，本机增加同层持久化字段。实际变更即时保存，失败保持可见。

本机没有网络连接状态、RTT、SSH 或重连入口；worker／Agent 的运行状态仍独立展示。远程保留真实连接状态与 RTT，身份、端口和 DeviceID 收入连接详情。图标使用既有字体度量并对齐名称第一行；编辑、技术详情和错误消息通过真实高度动画展开收起，状态文字轻量过渡，尊重减少动态效果。

Agent 的配置由 worker 原子接纳。设备详情允许关闭最后一个 Agent（持久化空选择，不变回默认启用全部），不停止已有会话进程，也保留其活跃控制；添加设备仍至少选中一个通过验证的 Agent。选择来自当前 adapter 目录；路径留空自动发现，错误和登录指导来自 adapter。配置失败不写设备集合，迟到或已取消的添加回执不导航或加入设备。

已保存的单个 Agent 配置失效（例如配置目录被移走）仅将该 Agent 标为不可用，不阻止 worker 和设备管理启动。保留原始配置用于修复；重新检测和后续启动不能回退到默认认证／配置目录，只有明确保存通过校验的修订配置后才解除限制。其他 Agent 及已有进程保持独立。
