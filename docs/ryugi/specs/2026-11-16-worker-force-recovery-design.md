# 执行恢复：警告风险，保留强制关闭

2026-11-16 · 用户已在对话中确认设计并授权实施；以下为实施依据。

用户已确认的原则：以后不能再出现只能查看阻塞、导出诊断，却完全无法介入的状态；可以警告，但必须支持用户强制关闭。本提案扩展同日的 `2026-11-16-worker-update-recovery-design.md`，取代其中“归属不明仅能诊断”“活动会话不提供结束入口”“旧 worker 无新能力只能等待”的产品限制。其余关于设备权限、数据保留、独立 Tailnet、进程身份和操作接纳的约束继续有效。

| 核查小红书与B站 playUrl数据 | 已完成 | Node REPL、code-mode host |

## 2. 产品承诺与边界

**每个阻塞状态都有用户可执行的退出路径。** 正常结束、强制关闭所选环境、强制重启执行服务逐级扩大影响范围；用户可直接选择强制关闭，无须先等待一次正常结束超时。应用不会因为 completed、低 CPU、协议空闲或归属不完整而自动结束进程。

强制关闭表示用户授权停止明确展示的当前进程与环境，可以打断正在运行的会话，也可以覆盖未登记、归属证据不足的进程。它不表示自动获得系统管理员权限、允许杀掉其他用户进程，或可以按名称批量清理整台设备。进程身份变化时跳过旧目标并刷新预览，按钮保持可重新确认，不能退回“只有诊断”。

本提案中的超时、按钮分组、helper 部署方式与通知合并策略是工程建议。Go、MyGo 原生 UI、所属设备执行、现有灰阶组件与独立 Tailnet 是既定约束。此次只交付设计；不关闭现场进程，不更新设备，不修改冻结稿。

## 3. 用户看到的流程

沿用设备详情 → 后台环境处理页，设备列表保持固定。界面无 logo，延续原生紧凑中性表面、13 px 主文、11–12 px 次文、28 px 按钮与水平分隔线。警告使用小型语义色标与局部淡底，不把整页染色。长名称换行，底部操作固定；窄窗口操作可分行，列表内部滚动。

### 3.1 阻塞清单始终可以处理

- 所有会话行都能“查看会话”和选择环境，包括正在回复、等待批准、执行不明的会话。复选框只表示选择范围，不立即授权停止。
- 已完成行显示“会话已完成 · 仍有后台服务”；运行行显示“正在运行 · 关闭会打断回复”；未登记服务显示“部分进程未登记 · 强制关闭可处理”。不再用笼统的“归属不明”吞掉实际会话信息。
- 无法映射到会话的对象放在“其他待确认进程”，列出 PID、进程名、启动时间、来源证据或“来源未确认”；用户可逐项选择并明确授权。默认全部不选。
- 我的建议：候选区默认只显示已登记、实际后代、已有身份记录和旧 worker 关联的对象；提供“选择其他进程…”原生弹窗，列出该设备当前 UID 的全部活进程，支持名称／PID 搜索与多选。逐项展示名称、PID、启动时间与归属证据，路径可展开但不展示 argv／环境。完整列表不是自动清理名单；确认后只处理用户选中的准确对象。看不到可执行文件路径不妨碍以 UID、PID 和开始时间选择。恢复 helper 自身、当前 SSH 控制链与独立 Tailnet 服务可见但不可选，明确标为“恢复控制连接”；按实际身份识别，不能按同名进程猜测。
- 展开详情区分已登记、由当前活进程树观察、历史记录、来源未确认；展示具体对象和采集时间。诊断与警告完整保留部分观察结果，读取失败也显示失败的步骤。
- 底部操作为“正常结束…”与“强制关闭…”，未选择时仅因无目标禁用。进程列表读取失败时仍提供“强制重启执行服务…”的独立入口。导出诊断是辅助操作，不是终点。

### 3.2 一次清楚的确认

正常结束沿用现有确认。强制关闭另开确认框：“强制关闭 3 个会话环境？”逐项列出会话、状态与进程数；涉及运行任务时在这些行上标注“将中断”，不能藏在总警告里。若仅选独立进程，标题与列表改为对应进程，不伪称完整会话。

正文固定说明：Agent 与工具进程将被立即终止；未保存的内存和后台工作会丢失；已写入文件不会回滚，可能保留未完成的文件修改；已持久化的历史、普通草稿与待发消息保留，队列暂停。未登记对象额外说明“这些进程的会话归属未完整确认，可能影响列表中的其他工作”。

正常归属的强制关闭只需一次明确确认，不强制打字、倒计时或先等 5 秒。选择来源未确认对象或设备级重启时，增加一个“我理解可能中断未识别的后台工作”复选框，勾选后启用“仍然强制关闭”或“强制重启执行服务”；不做重复弹窗。默认焦点在取消，Esc 取消，Enter 不得默认触发破坏性操作。

确认框内有“关闭后更新执行服务”复选框：从更新阻塞入口进入默认勾选，从会话强制关闭入口进入默认不勾选。**单独关闭环境不依赖可用升级制品**；未有可用制品时可以关闭，把更新说明为“制品准备完成后再更新”，不能先关闭后偷偷开启无限自动重试。仅在候选完成预检后，才接纳包含更新的组合操作；预检失败保留单独关闭入口。

### 3.3 不必处理整台设备

具备新的会话级派发封锁能力时，就本次四个会话，用户可仅选前三个已完成环境并强制关闭；第四个继续运行，更新仍等待它结束。也可明确选中第四个，确认打断后一次关闭四个。不能在批量操作中默认勾选活动会话。

我的建议：旧 worker 若无法在会话级封锁输入和队列，不承诺选择性环境关闭，直接展示可用的“强制重启执行服务…”并明确将影响第四个运行会话；用户可以立即确认全部重启，或等它结束后执行。这次旧设备必须在首版有此入口。进程选择器仍可作诊断，但在旧 worker 无法配合封锁时，所选执行进程的关闭归入设备级确认，不绕开服务派发直接杀三个 PID。此限制改变影响范围与确认文案，不删除用户的强制操作路径。

每个会话的更多菜单增加“强制关闭运行环境…”，与设备页共用同一确认与权威接纳链路。普通“停止回复”继续只请求 harness 中断，不变成 SIGKILL。会话无常驻环境时该入口显示实际无目标状态，但设备恢复入口仍可达。

### 3.4 执行服务失去响应也有入口

设备详情中的“强制重启执行服务…”是始终可达的次级操作，放在执行服务更多菜单；处理页遇到超时、权限错误、归属缺失、旧版本不支持时也显示。点击先由独立恢复 helper 获取当前服务、受影响会话和候选残留的预览，不能依赖故障 worker 返回数据。

确认显示“此设备的所有执行会话都会断开；N 个正在运行的任务将中断”，独立列出会话来源未确认的候选对象。核心范围为执行 worker、其 Agent/executor、可追踪后代与执行守护；未知候选必须在确认里单独列出并选中，不能悄悄覆盖所有同名进程。明确“Tailnet 与设备 SSH 连接保留”。无需升级也可恢复服务；重启不代表会话自动继续。

若操作系统拒绝结束某对象，显示“关闭失败 · 权限不足”等真实原因，同时保留重试、其他目标关闭和远程设备终端入口。SSH 不可达时，显示“重新连接”及“在该设备执行恢复”说明与可复制命令；网络本身不可达时不能保证远程操作执行。普通用户不需要查找 PID，管理员手动处理属于权限边界的最后路径，不是归属不明的默认路径。

## 4. 处理级别

| 级别 | 可选对象 | 用户授权 | 结果 |
| --- | --- | --- | --- |
| 正常结束 | 有完整或部分观察证据的已选环境 | 一次确认 | TERM / 协议关闭；建议 5 秒后显示仍存活目标，不自动强杀 |
| 强制关闭 | 活动或结束会话；未登记／归属不明的明确对象 | 确认目标；高风险范围勾选警告 | 对已确认对象发送 KILL，逐个证明退出 |
| 强制重启执行服务 | 本设备全部执行环境及明确选择的残留候选 | 设备范围确认，列出活动任务 | helper 在 worker 外暂停重启与派发，关闭执行环境、重启并核对原设备 |

三个级别不是必须按顺序完成的向导。正常关闭超时后直接在原页提升到强制确认；无法得到会话精确范围时可转设备级恢复，不能只剩“重新检查”。

## 5. 归属证据与用户控制解耦

将“该进程能否证明由 Shioji 启动”与“用户是否授权停止这个准确对象”分别记录。已登记环境沿用 generation、anchor 和 launch ticket。未登记对象不伪造 ticket，也不因为名字像 Node 就归属某会话；以可见父子链、UID、PID 与精确开始时间采集证据，保留证据强度。用户显式选择允许停止归属证据不足的当前对象，但不把它升级为自动关闭／空闲证明。

恢复目标包含 DeviceID、观察批次、环境代次、进程 PID＋开始时间、UID、观察到的父进程身份、证据类别与用户选择范围。预览有效期建议 30 秒；过期刷新一次并重新展示差异。不能以仅有 PID 的旧预览发信号。PID 复用、节点身份变更、同名新实例均不得被原确认追杀；界面明确“原进程已退出／已换新实例”，可重新选择当前对象。

对已登记且 anchor 仍有效的进程组可沿用组关闭。对未登记对象以逐 PID 的身份核对与发信号为主，不向整个未验证进程组广播。对用户选中的完整环境，先阻止其新输入，再采集并持久化可验证的后代快照；关闭期间持续识别原环境新后代，不能扩到新的会话／新运行代次。无法证明属于原范围的新对象列为残留，提供下一次强制确认，不无限追杀。观察到的后代可以包含已登记的子工具组，去重后只操作一次。

macOS 的查询与发信号之间存在进程身份变化窗口，不能宣称用户态 PID 检查具有原子性。实现前须验证可用的内核进程事件／身份核验手段；逐 PID 在发送前立即核对、发送后检查原身份退出，竞态不可确认则返回部分结果与新预览，不追随复用 PID。此项列为实现验证，不以进程名替代。

运行环境开启期间持续记录实际后代身份与来源，覆盖 Codex 内建 Node REPL、code-mode host、自定义 MCP 和命令子进程；登记明确可经过托管启动边界的部分，观察与登记分开。监测断档不会制造空闲结论，恢复入口不因断档消失。不能把轮询声称为任意瞬时脱离进程的完整 containment。

## 6. 独立恢复 helper，覆盖旧 worker 和卡死

建议复用已签名 `shioji-worker` 制品的独立 `--recovery-helper` 模式，不新增永久常驻服务。新 GUI 本地直接启动其受信任的候选 helper；远端通过现有已授权 SSH 会话部署并验证签名／摘要后运行，不走旧 worker 的 RPC。Tailnet 设备的 SSH 始终经过嵌入网络的私有桥，不依赖系统 Tailscale 或额外管理令牌。

helper 用受保护的设备状态目录与独立、原子持久化的恢复日志工作，不能把卡死 worker 的 DB、dispatcher 锁、pipe 或同一事件循环作为结束服务的前置条件。设备身份从受保护的已有 metadata／身份记录读取，DB 暂时不可读时使用已建立的受认证设备绑定并标明身份观察来源；无法建立设备身份则重新连接确认设备，不能对一个无法识别的主机静默执行。

为避免当前“安装修复需要先解除旧阻塞”的循环，helper 部署和只读检查不需要旧 worker 空闲。旧版服务可用已有 SSH 权限接收新 helper；恢复动作仍在明确确认后发生。首次新版本发布必须同时携带可用于旧服务的 helper 和 UI 路径，不能把此次受阻设备留给未来版本。

helper 的本地控制口验证调用者签名与当前 UID；远程命令依靠现有 SSH 认证，再验证设备绑定与当前 UID。helper 不接收任意 shell、通配进程名或 root 权限。用户输入与执行诊断保持分离。日志不含凭据、环境变量、原始 argv、授权 URL 或私密路径。

恢复操作建议由 launchd 的一次性用户任务托管，使用每操作唯一标签，不设置 KeepAlive，不属于 Tailnet 服务；允许 SSH／GUI 退出后完成。helper 崩溃重启只按日志查询原操作，不重放未知输入。执行服务的启动器先读取恢复 fence；强制重启先暂挂执行服务的自动拉起，再结束旧 owner；旧启动器不认识 fence 时，helper 使用该执行服务的实际注册信息暂挂对应用户任务，不能按全局名称停止服务。独立 Tailnet 的注册与桥接始终保持。

## 7. 接纳、并发与升级收尾

worker 响应时，所选会话仍在现有 maintenance／dispatch 串行边界接纳，持久化操作 ID、动作 ID、目标快照、风险授权和更新意图，暂停所选队列并阻止其新输入。新会话普通发送继续运行，除非用户选择设备级重启。确认前状态从已完成变为运行、目标增加或代次变化时，返回变更确认页，明确列出新增影响，不自动扩大授权。

worker 不响应时由 helper 的设备恢复锁串行接纳：先持久化设备级 fence，暂挂执行服务的自动拉起，核对并停止具体 owner，然后取得 store owner lock，在无新派发条件下处理剩余目标。取得 owner lock 前不写会话数据库，不允许两个 SQLite 写入者绕过原权威 worker。helper 和所有启动入口必须共享恢复 fence；远程断线不解除它。若 owner 未能退出，停在真实失败阶段，保留强制重试与权限处理入口，不能伪称已独占。

并发客户端共享恢复日志；相同动作返回同一回执，冲突动作返回现有操作。正常结束后强制升级授权是同一操作的新动作；显式 force 首次提交也可直接接纳。断线后只查询，不能因回执未知换 ID 自动再发。取消撤销未开始的动作与自动更新意图，已发送 KILL 无法撤回；关闭面板不等于取消。

建议阶段：已接纳 → 正在封锁派发 → 正在关闭 → 验证退出 → 已关闭／部分未关闭 → 等待其他任务／备份更新 → 重连核对。每目标记录已关闭、已自行退出、身份改变、权限拒绝、仍存活、无法观察。发送信号不是成功。部分未关闭页提供“重试关闭剩余对象…”与“强制重启执行服务…”；新增对象仍需对应范围确认。

强制关闭只代表环境终止。被打断的轮次先保留 execution unknown／待核对；确认进程与投递结果后可标为 interrupted，不能改成成功完成。已完成会话保持终态。历史和附件保留，队列暂停，无输入自动重放、无自动续答。所有客户端清理失效的待处理请求，保留原位置的已失效来源标记；迟到的旧事件不得恢复旧运行状态或替新请求授权。

升级独立执行原签名、协议、数据库兼容性预检和含 WAL 一致备份。强制关闭授权可以替代“等待该环境自然空闲”，不能替代制品校验或 DB 独占证明。仅当全部已授权范围确已退出、其他任务符合当前用户选择并核验通过，才切换服务。未清理的来源不明对象仍可警告并由下一次确认选择，不能无声放行，也不能重回无处理按钮。

新服务必须握手确认原 DeviceID、候选 BuildID 和恢复操作回执；失败则显示“环境已关闭，更新失败／服务尚未恢复”，提供恢复原构建与重试启动。回退程序不覆盖数据库，不将环境关闭的部分成功显示为“全部更新成功”。

## 8. 警告与通知

建议首次进入阻塞或“需要强制确认”时，每设备／事件代次发一次通知：“MBP at Work 的执行服务需要处理”，操作打开对应处理页；用户正在处理此页时不重复系统通知。系统通知遵循授权与现有设置，关闭通知不能隐藏应用内恢复入口。无定时重复轰炸，无倒计时自动强杀。

关闭结果在原页展示；用户离开后可通知“3 个环境已关闭，另有 1 个任务正在运行”或真实失败原因。导出诊断包括采集时间、能力、阶段、SessionID／generation、证据类别、完整进程摘要、每目标错误与部分成功；默认脱敏。进程查询出错时保留已经得到的信息，绝不再仅输出 Processes: null 而丢失阻塞对象。

## 9. 实施范围与验收

这是中等偏大的跨模块改动：原生 UI、domain/protocol、worker 接纳、managedexec、启动器／部署、恢复 helper 与 store 恢复。建议先落地“本次旧版也能强制处理”的最短完整链路，再完善持续观察；两步属于同一个发布验收，不能先发布只有警告而无退出路径的半套功能。预计涉及约 12–18 个实现与测试文件，具体任务拆分交给实施者，不新增 harness 或通用插件框架。

必须使用隔离设备状态和真实 macOS 进程验证：

1. 重现这次 app-server 自建跨组 Node REPL／code-mode 服务；诊断显示实际对象，用户从 unknown 行可到达强制确认并关闭，其他会话与 Tailnet 保持运行。
2. 正在运行、等待批准、问答未提交、执行／投递不明均可显式强制关闭；逐项警告，保留历史、草稿、附件与暂停队列，迟到事件不复活执行。
3. 直接强制无需先试正常结束；正常路径不自动升级 KILL，TERM 忽略者须明确授权；无候选包仍能单独关闭或重启。
4. 旧 worker 无维护能力、RPC 无响应、dispatcher 卡死、DB 忙、服务自动拉起时，独立 helper 仍能预览并接受设备级恢复；取得独占前不得改 DB。
5. 断网、SSH 断线、GUI 退出、helper 崩溃、双客户端、重复点击及回执丢失不会重复输入、扩大范围或自动继续队列；可查询真实进度。
6. PID 复用、父进程退出／改组、代次变化、预览后新任务、新生后代、同名外部程序与其他 UID 均不被旧确认误杀；来源不足仍能重新选择明确对象或转设备恢复。
7. 权限拒绝、无法采集、部分关闭、升级失败均有下一步和真实结果；用状态／操作矩阵检查每个非终态至少一个有效操作，不能只有导出诊断。
8. 设备级重启后原 DeviceID 保持，实际构建核对正确；独立 Tailnet、入站转发、凭据与 SSH 连接配置保持；不把用户网络不可达伪装成执行完成。
9. 原生亮暗模式、窄窗口、长会话名、键盘与减少动态效果截图验收。运行相应 Go、race、真实进程与双客户端回归，以及冻结设计仓库校验。
