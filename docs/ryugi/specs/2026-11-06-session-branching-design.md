# 会话分叉与历史消息修改重开

用户明确要求：分叉创建新会话；修改历史消息在原会话重开，替换该消息与后续对话。Git 操作降低优先级。本轮沿用 Go/MyGo、设备权威 worker、固定 Codex 0.166.0，不新增依赖或运行时框架。

## 行为

- 完成轮次底部复制右侧、时间之前提供“从这里分叉”，会话菜单提供从最新已完成轮次分叉。创建新的 SessionID / ThreadID，保留原工作区、已接纳 CWD、附加目录、运行配置及该轮结束前的历史。新会话无待发队列、待处理请求或运行状态，不自动提交提示。
- 用户消息下方右对齐放置编辑、复制、发送时间，沿用回复 footer 的 11px 字体与紧凑图标，操作行不参与正文选择。时间使用 worker 接纳时持久化的 SentAt，缺失则未知；排队时间不冒充发送时间，历史同步保留已知时间。编辑入口为“修改并重新开始”。原消息就地展开独立编辑框，普通 composer 保持原位与普通草稿、发送语义；取消和切换会话不丢稿。编辑区回车图标确认按钮明确命名“保存并重新开始”。保留原消息附件，不重用过期客户端上传状态。
- 只有已确认发送、存在源 TurnID 的首条用户消息可以修改。轮次内的 Steer 追加输入没有独立的源分叉边界，入口说明该限制，不将整轮截断冒充单条编辑。失败／未知投递不进入重开流程。
- 原会话必须 idle/completed/interrupted/failed，且没有执行保护、未确认操作、待处理请求；编辑草稿可先写，运行时不能确认重开。待发队列保留并暂停，须用户明确继续。归档会话和工作区先恢复。
- 编辑提交在所属 worker 串行边界核对会话 revision、消息 ID、源轮次和工作目录，先创建 beforeTurnId 的真实 Codex fork，确认成功后原子替换当前 ThreadID、移除目标轮及后续投影、接纳修改后的用户输入。再由现有 dispatch 路径提交新轮。原 SessionID 和名称保留。
- 文件状态不随历史重开回滚。按用户后续反馈，编辑框底部不展示说明文案，仅保留取消和回车确认。分叉沿用实际 checkout，不自动创建 Git worktree，也不伪装文件隔离。

## 协议与存储

协议提升为 Major 2 / minor 9，拒绝不理解历史替换的旧客户端，避免其显示被替换的后缀。新增 session.fork、session.restart、session.history-operation。请求使用稳定 OperationID、SessionID、expected revision、源 ItemID 或 TurnID。worker 为每项历史操作持久化 intent、原始输入、结果，重试相同 ID 不重复分叉／发送，不明结果只查询。prepared 未获源结果时不重发；forked 已保存新 ThreadID 但未切换历史时，可显式重试同一操作完成本地事务；complete 已接纳新输入后仅交给现有 operation 核对，不再 fork。旧线程的事件绑定与本地事务在同一 adapter 事件锁内切换，晚到事件不得复活后缀。历史操作不可复用普通提交的 ID。

数据库 schema 6 添加历史操作表。原会话重开以一次事务更新会话／历史／队列和新的普通 submission operation，journal 提供 history.reset 边界事件，使多个客户端和分页补放剔除被替换的后续内容。保留历史前缀原始 item/turn/request ID、用量与位置；已解决的历史请求只作为只读历史，不恢复 pending。新会话复制历史不生成完成通知。

Codex adapter 使用 thread/fork 的 lastTurnId（包含）或 beforeTurnId（排除），显式 deferGoalContinuation，按 ID 操作，禁用任意 rollout 路径输入；核对返回源、目标身份及 CWD。分叉本身不请求模型。创建 fork 时设置零卸载延迟并 unsubscribe，释放创建端的写锁，目标 runtime 再 resume；此交接须真实 app-server 测试。正常提交再绑定目标 session 的执行环境，不继承源 executor 的进程控制身份。

## UI 与动画

沿用现有中性菜单、消息 footer、图标与字体度量。参考 Lody 的原位编辑，编辑框右对齐原消息，最大 676px，输入区随内容增长、最高 320px，焦点在末尾；取消和发送置于底部右侧。原消息容器以 280ms 真实高度过渡展开／收起，固定阅读锚点；底部输入框不参与这次布局变化。

确认修改后保留独立修改稿，编辑框立即以 280ms 真实宽高和表面过渡收回为修订后的消息气泡；与此同时，被替换轮次的后续消息使用真实原生渲染图层分片碎散 520ms：8px 刚性碎片保留清晰原图，旋转分离，末段才淡去，不以收缩和全程淡化造成晕染；然后用 200ms 收拢腾空高度，再发送重开请求。保留轮次的迟到内容不参与退场。reset 与 submission 分别到达时保留本地修订消息气泡，新消息承接原消息同一阅读位置。新回复只能在退场完成且 worker 接纳后启动，仍沿用现有 Markdown 流式渐显。局部动画期间没有 worker 变更；状态变化或提交失败恢复原内容和编辑草稿，未知结果只查询。减少动态效果跳过碎散和高度插值。所有布局保留 768px 阅读列和单一右侧栏。

分叉时所选回复之后的内容渐隐 220ms，所选回复及前文保留原位。worker 确认后，用对应源 ThreadID／revision 的不可变结构化历史前缀预填分叉视图，再由正常权威加载更新；将同一回复锚定在原位置，避免空白加载帧及默认滚到末尾。不可确认前缀时不预填。未打开或无历史缓存的侧栏会话分叉直接提交 worker，不依赖 UI 缓存，也不对无可见内容播放局部退场。

后台历史加载和工具调用默认折叠不得释放阅读锚点；`$select` 与 `$visible` 的首次加载可能分别到达，均应保持位置。只在真正切换阅读会话时释放旧滚动状态，再由此次操作交接新锚点。

## 验证

先写失败回归，覆盖真实 pinned app-server 按 before/last 边界分叉，确认后续模型请求包含应保留前缀且不包含被替换后缀；确定性本地 provider 不调用真实账号。Store 覆盖幂等、revision 冲突、原子截断、附件保留、队列暂停、已答请求只读、跨分页边界与重启。Worker 覆盖 owning-device、busy/guard/pending 拒绝、超时不重发、执行环境不串源、原会话 ID 与名称保持。客户端覆盖 history.reset 的单调事件与快照／分页补放，独立草稿和双会话隔离。原生截图检查亮暗／窄窗、编辑区与 footer 对齐；按用户追加要求录制亮色原位编辑、取消、修改、碎散与新回复的真实 60fps 视频。

## 实施中确认的细节

- 轮次增加 worker 拥有的顺序号，schema 6 对已有记录按原插入次序迁移。分叉／重开按轮次归属选择保留项；迟到的前轮工具输出不因落在后一条用户消息之后而丢失。`history.reset` 带保留轮次上界，多个客户端和分页补放使用同一边界。
- 已保存 `forked` 结果可用相同完整请求显式继续完成，每次重新核对当前目录、Git、配置和附件。`prepared` 在 worker 重启后变为失败，不重发外部操作。`session.cancel-history` 在同一 dispatch 边界仅取消未本地提交的 intent；若已经完成，只返回原结果，不撤销已接纳输入。
- 客户端持久化历史操作标识；重连只查询。修改提交后历史编辑区只读，确认事件直接结束编辑并恢复普通草稿，不依赖普通 Pending submission。已保存的分叉不会因丢失 RPC 回执而再次创建。
- 原生验收使用真实固定版 app-server 和本地确定性 provider，非新账号模型调用。用户消息、流式回复与用量为测试夹具，截图只证明运行中的原生控件和实际流程。
