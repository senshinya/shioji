## 判断与代价

1. 用户明确选 B，覆盖早期 A 推荐。代价是追加时多一次点击，换取日常阅读空间。
2. 问题／授权与普通子消息保持独立，不增加隐式阻塞。实际 harness 若拒绝某次追加，原草稿保留并显示错误。
3. 历史没有匹配记录时保持送达未知。代价是查询可能暂时无结论；不会因此自动重发。已验证停止的旧执行不再阻挡工作区或服务维护。
4. 原生外观与真实 App Server 路径已实际验证；没有新增实机 IME 专项验收，继续使用原生 TextArea。平台 IME 边界仍可能需要后续反馈。
