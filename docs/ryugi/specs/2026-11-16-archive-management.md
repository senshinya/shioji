# 归档会话与工作区管理

用户于 2026-11-16 确认 `artboard/archive-management` 的修订设计并要求开始实现，特别注意对齐。设计源保留在本机 `.ryugi/artifacts/artboard/archive-management/`；不改冻结稿，不启用云发布。

## 已确认的界面与行为

- 工作区标题菜单以“已归档…”打开全量归档页，替换原来“显示已归档”混入侧栏的行为。保留侧栏、首页草稿和会话草稿。
- 会话 / 工作区两个 Tab。会话列表跨已连接/已缓存设备，只有标题与 workspace 两个信息列，悬停或键盘聚焦出现恢复、彻底删除。支持标题/workspace 搜索、虚拟列表与直接打开历史。归档工作区中的会话也包含在会话列表内。
- 工作区列表只有名称、所属设备；可进入查看其中全部会话、恢复、彻底删除。恢复工作区不恢复已单独归档的会话；彻底删除工作区包含其中全部会话。离线保留缓存，禁止设备写操作，已缓存历史仍可读。
- 已归档会话直接进入现有只读会话视图，不自动恢复。保留返回归档列表的入口、查询、Tab、滚动位置。
- 删除使用原生确认，明确不可恢复、工作区内会话数量、项目文件与 Git 不删除。请求核对 owning device、稳定对象 ID 与 revision，异步结果不得修改其他对象。
- 标题右侧为紧凑的灰阶齿轮＋“保留 30 天”入口，“永不”显示“永久保留”，点击设置。无底部脚注和下划线链接。
- 现有设置外观 → 对话新增“归档内容保留”，7 / 14 / 30 天 / 永不，默认 30 天。设置持久化，失败在当前设置窗口显示。现有设置分类不变。
- 会话/工作区分别以 worker 归档时间起算；打开不延长，恢复取消该对象的清理，再归档重新计时。缩短保留期适用于既有归档。旧数据缺少归档时间时从升级首次补记起算。归档工作区到期包含其中会话。
- 清理由 owning worker 后台执行，不依赖 GUI/SSH 生命周期。删除前核对执行/队列/请求/子任务/历史操作及真实托管进程；不停止活动任务以完成清理。恢复和清理共享 worker 串行边界。
- worker 删除以事件同步各客户端，清除其历史、导航、普通/历史编辑草稿和并排选择；别的会话草稿不受影响。保留最小投递 tombstone，防止未知历史输入被重放为新会话。删除 Shioji 记录与自有资源，不删除 harness 自身独立保存的源历史。

## 实现决定与边界

全局客户端保留时间作为新设备的默认值；用户明确变更向已知设备提交持久化策略更新。离线更新保存并在重连后应用；正常重连不覆盖另一客户端明确保存的设备策略。已配置设备以 worker 的 revision 为权威，冲突明确报错，禁止静默重试覆盖。设置显示尚未同步的设备或失败原因，不将本地保存当作远端已应用。

原生使用 MyGo 组件、公共配置控件、`inlineFontMetrics` / `inlineIconText`。列表标题和 metadata 使用同一基线与列宽，28 DIP 动作命中区 / 16 DIP 图标槽位。保持公共齿轮/恢复/删除图标的可见笔画中心。亮暗、中文、英文、混排和窄窗口实测，保留原生截图与交互录像；浏览器设计稿不代替原生证据。
