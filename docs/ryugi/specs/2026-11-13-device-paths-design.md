# 同一设备，多条连接路径

建议：同一设备保留多条已认证连接，支持 SSH＋Tailnet、SSH＋SSH 等组合，自动使用近期延迟更低且稳定的路径。设备、工作区和会话只保留一份。本文于 2026-11-13 经用户确认，开始实施。

## 已经确定与现状

用户确定：同一台机器可以同时保有多条连接，优先低延迟路径；正常添加设备也要自动识别合并，显示识别提示；SSH＋SSH 与 SSH＋Tailnet 使用相同的设备身份判断。项目既有约束：worker 独立运行，路径切换不能停止 Agent、丢失草稿或重复提交。

现有 BindDeviceConnection 按 worker DeviceID 合并设备并保存 OtherSSH；但新路径替换当前主路径，sshController 只使用主路径。其他地址不会持续测量或自动接替。当前设备延迟来自 readiness 整次调用，不能直接与 Tailnet 网络 ping 比较。

## 用户看到什么

UI: .ryugi/artifacts/artboard/tailnet-setup (multi-path / multi-path-states). Approved in chat 2026-11-13; reference includes 8 light/dark/narrow/merge state boards. Preserve monochrome geometry, fixed status columns, 260 ms existing transitions and baseline icon alignment.

设备列表仅一个 MacBook Air，显示当前路径和近期实际延迟，例如“直连 SSH · 4 ms”。设备详情保留原 Agent / 设备设置导航，在设备设置中用“连接路径”替换单一路径地址展示。两条路径各占一行：图标、路径名和地址在左，延迟及“使用中 / 就绪 / 不可用”在右。Tailnet 使用已有官方标志。设备级 Agent、订阅、工作区不重复。

设计取舍：首版默认自动选择，不增加手动固定路径、独立网络优先级或新的一级 Tab。已添加的设备可从其连接路径区域添加路径；正常“添加设备”流程（直连 SSH 或 Tailnet）也使用同一身份合并逻辑，认证并核验同一 DeviceID 后自动将新路径并入已有设备，无额外合并确认页或“添加连接”确认按钮。归入原设备后显示不占用表单布局的紧凑状态提示“已识别为 MacBook Air，连接已添加”；重复添加同一路径则提示“已识别为 MacBook Air，该连接已存在”。沿用中性表面与既有提示动效，显示约 4 秒后退出，减少动态效果时立即切换；短提示消失后，路径列表仍明确保留最终结果。只有持久化成功才出现成功提示，失败留在原步骤并行内显示错误。不在全局网络设备列表增加添加设备入口。

添加第二条路径仍做正常 SSH 主机信任、用户认证及 worker 身份核验。同一 DeviceID 核实后，原子持久化新增路径，再以既有页面转场关闭添加流程并定位原设备详情；沿用原名称、配置和工作区，不重复 Agent 配置、历史导入或新建空会话。两条添加流程并发完成时也按同一身份合并；重复的路径按目标、端口、网络与认证上下文归一去重，仅刷新其连接状态。保存失败留在当前流程重试，不显示合并成功，也不损坏原路径；不能依据新填别名重命名已有设备。欢迎流程若尚未完成初始化，合并设备后进入原本必要的工作区步骤，不再次配置已接纳的 Agent。凭据或主机信任未通过时不合并。身份判定与连接方式无关：SSH＋SSH（不同 IP、主机别名、端口）、SSH＋Tailnet、Tailnet＋Tailnet 均在已认证的 worker DeviceID 一致时归入同一设备。多条 SSH 路径共用同一种 SSH 图标及标题，下一行以实际目标／非默认端口区分；不伪装成两个设备。目标地址相同但未确认同一 worker 身份时不得合并。不能依据 IP、主机名或同名自动合并；相同物理机器的不同用户／worker 身份也不强行合并。

用户后续修订：Tailnet 也是 SSH 路径，使用官方标志并标为“Tailnet SSH”，地址显示有效用户名。每条路径独立展开自己的登录身份、端口和 Tailnet 网络观测；切换活动路径不替换其他路径的展开内容。设备 ID 属于共同设备身份，仅在独立的“设备身份”中显示一次。未显式填写用户名／端口时，后台读取该路径实际 OpenSSH 配置，不从另一条路径、设备 Home 或控制 Mac 名称推断；显示元数据不重写连接目标或改变认证。展开与收起复用现有真实高度动画。

## 如何选择路径

两条可用路径都维持已认证的轻量 worker 通道，但只有一条负责当前业务与权威事件订阅。备用通道仅做身份、能力和只读探测，不订阅第二份事件，不运行部署、升级、队列调度或 Agent 监督。协议 RPC 只通过当前业务通道派发一次。

两条路径各维持独立且同型的轻量只读探测通道，与业务 RPC、事件 watch 分离。protocol.Client.Call 与 worker 同连接命令处理存在串行边界，不能在繁忙业务通道测一边、空闲备用通道测另一边。探测计时从实际发出至匹配回包，不包含本地锁等待、UI 调度和建连耗时；新增无副作用的轻量探测方法，不用昂贵的 readiness，也不与 tsnet ping 混用。tsnet 的直连／DERP／peer relay 数据仅用于路径详情。延迟未知、超时、过期均显示“—”，不当作 0。

我的首版默认值：设备实际连通时每 5 秒探测一次，保留最近 5 次有效样本的中位数；少于 3 个新鲜样本暂不因速度换路，15 秒无成功样本即过期。候选比当前同时快至少 5 ms、30%，连续 3 次评估成立才切换，切换后冷却 30 秒。4 ms 与 5 ms 之类差异不来回跳。所有路径均新连上时先用第一条已核验可用的路径，随后按样本优化；失败优先级高于冷却与速度阈值。

探测失败后立即进行独立健康确认；确认超时或业务通道断开即判为不可用并选择已验证备用，不必等待 15 秒过期。具体探测超时、并发调度及资源上限留给实现根据现有协议确定，但必须有界、可取消且不阻塞 UI。网络、系统唤醒、Tailnet 断开会立即失效相关旧样本，不能用旧 LAN 地址的历史低延迟压过可用的 Tailnet 路径。

## 切换不会重开会话

DeviceID 对应一个逻辑设备连接；持久化两条各有稳定 RouteID 的路径及当前选择，原 ConnectionID 保留为设备连接键，避免迁移队列、草稿与已保存选择。旧主 SSH 和 OtherSSH 迁成路径列表，旧主路径优先用于首次重连。密码和私钥沿用现有安全边界，不复制进路径展示数据。

切换分为准备、交接、完成。先认证新通道并验证同一 DeviceID，读取同一 worker 的 generation、快照和事件序号；只有目标 worker 完整就绪才暂停新业务派发并交接。旧请求有界排空；停止路径不是停止 worker 或 Agent。性能切换期间尽量保持旧业务通道，不把设备变成离线；新路径失败则保留旧路径。

切换与提交在同一设备调度边界串行。性能换路须等待已派发的变更请求完成；若超出有界等待则放弃本次性能换路，继续旧路径。已入队但尚未派发的操作由设备协调器保留，在新通道核对上下文后重新绑定目标 epoch 再派发一次，不能沿用旧 Job.ConnectionEpoch 而丢弃。故障换路时，Submission 与 Steer 等具备稳定 OperationID 的操作查询原接纳结果，不重发用户输入；审批回复、停止、配置修改等没有通用 OperationID 查询能力的变更按各自权威状态核对，无法证明结果时保留待核对状态并禁用相关重复动作，不自动重发。不得声称所有变更均能按统一操作 ID 恢复。提交锁释放和草稿清除以权威接纳结果为准；换路成功不代表操作成功。

权威事件同一时刻仅一个来源。交接以 worker generation / sequence 对齐，旧来源令牌失效后迟到事件丢弃；缺口通过权威快照及序号补齐。worker generation 变化按既有重连规则处理，不声称旧进程内的活动轮必然恢复。审批、问题和队列保留稳定业务标识与草稿，重新核对仍有效的 request / revision；不因客户端通道 epoch 变化清空整张卡或重新发送答案。无法跨通道继续的只读文件／目录查询在同一设备与原草稿仍有效时重新读取，迟到回调不得覆盖新界面。

运行中也可完成安全交接，因为 harness 进程由同一 worker 独立拥有；实现必须先验证 worker 的请求／事件跨客户端语义。首版不提供并行发送、带宽叠加或正在进行的 TCP 字节流迁移。已打开的独立终端／浏览器授权转发／文件流绑定原 RouteID，原路径健康时继续；原路径断开则明确标记该操作断开，依其既有可恢复能力处理，不假装无缝续传。性能优化不关闭仍承载这些操作的旧通道。

## 状态与动画

路径状态显式为：连接中、就绪、使用中、不可用；设备协调器显式为：等待可用路径、稳定、准备交接、交接中、离线。状态与渲染分离；路径测量不能重置配置、页面焦点或会话阅读位置。

路径标签和“使用中”标记沿用现有内容切换动画，延迟数字复用数字翻动；行高固定，不让整页渐隐或重建。只有真正需要等待时在新路径行展示持续旋转的加载图标，状态文案变化不重置旋转。两路都失效才显示既有设备离线状态；备用失效仅改变该行。设备名、会话正文、底部输入框及其动画保持稳定。尊重减少动态效果。

## 验收与实施范围

这是中等规模的连接层改造，不能仅补一个 UI 开关。按设备与路径迁移、双通道及公平测量、安全交接、原生 UI 四部分推进；保持 harness 中立，worker 不获得客户端其他设备的连接目录。

- 通过正常“添加设备”分别覆盖 SSH＋Tailnet（两个顺序均测）、SSH＋SSH 的不同地址／别名／端口，以及相同路径再次添加；核验 DeviceID 后自动合并并出现对应成功／已存在提示，无需额外合并确认；仅一个设备、一套工作区和同一 SessionID。设备内新增路径使用相同结果；重复／并发添加不重复路径，保存失败能重试，重启后仍保持。

- 使用同类 RPC 的真实或受控网络时延验证选择、抖动阈值、过期与冷却；第二路径可用才发生切换，未知不显示为 0。

- 真实回复流中从直连切到 Tailnet，再恢复直连；不重开 Agent、不重复消息／事件／通知、不丢焦点、不跳滚动。

- 请求刚提交后断路、审批／问题待处理、队列派发、目录读取与终端存活时换路；验证未知接纳只查询、旧回调隔离和各独立流的明确中断。

- 错误 DeviceID 不合并、不提交；两路全断时保留草稿；移除一条路径不删除设备或其数据，最后一条路径的移除沿用现有设备移除交互。

- 原生亮暗与窄窗截图核对图标字面基线、左右边缘与数字／标记变化；不把 HTML 设计稿或合成事件声称为实机通过。
