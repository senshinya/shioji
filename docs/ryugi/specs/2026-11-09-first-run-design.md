# 首次启动与添加设备

已批准：本机会话中的 `first-run-and-add-device` 画板，`v3-steps`、`v3-device`、`v3-agent`、`v3-workspace` 和 `v3-flow`，包含 2026-11-09 的间距修订与整体上移 24 DIP。

## 界面

首次启动为无侧栏整窗原生界面：设备 → Agent → 工作区。560 DIP 内容区居中；1100×800 时内容顶部 192 DIP，左边界 270、右边界 830。窗控沿用原生主窗。标题 28/36、常规标签13/20、配置值与模型12/20；紧凑控件28 DIP，普通配置行40 DIP、上下6 DIP；多行项首行对齐。中性灰，无遮挡、无应用 logo，无二级说明。主操作与控件右端一致；hover 向内容左右各延伸8 DIP。

设备选择默认本机；配置可更改应用显示名称与登录后启动服务。SSH 输入地址；连接选项展开名称、端口。只在用户明确点击时检查并准备服务，保留主机验证。检测完成后才配置 Agent；完成真实检查后保存设备。设备管理中的添加设备复用这些步骤，以紧凑浮层呈现。

Agent 列表来自所属设备的中立 catalog，显示实际状态、配置入口、开关。配置页有常规、模型、高级页签，切换不加动画；账号展开、可执行文件、标题模型、收藏/显示/顺序、启动参数、配置目录、环境变量、自定义提示词按能力显示。常规与账号邮箱共用文字左边界。模型列表最多显示 3.5 行（40 DIP 每行、140 DIP 上限），短列表按内容收缩，列表内部独立滚动，不顶走底部操作。取消恢复配置草稿；模型菜单偏好维持现有即时保存语义。只翻译已支持选项，不安装或登录第三方 Agent。

工作区填写名称、所属设备主目录和附加目录；本机使用原生选目录，远程路径通过所属 worker 验证。只在创建成功后进入已有首页，创建过程不生成空会话，草稿保留。失败显示可操作错误，保留表单。

## 生命周期与动画

新 client state 缺失时进入欢迎；已有 client state（即使无新标志）保留原行为。未完成/稍后设置/完成可持久化；快照到达不使流程自动跳过。首次初始化可以稍后设置。所有后端调用异步，防止重复提交和迟到回调抢占已离开的页面。

上下步切换只使用左右滑动，不做淡入淡出；下一步向左、返回向右；其余展开、增删和反馈复用现有设置页与设备页动画，以实际高度过渡；配置展开与关闭保持内容/高度同步；目录和环境变量增删动画；完成后欢迎内容退出、首页与侧栏接续出现。减少动态效果跳过位移。保留原生焦点、IME 和快捷键，不自动发送任何消息。

## 验证

持久化迁移；原生 UI 测试覆盖首次页、侧栏隐藏、取消、真实 Job 的设备/epoch 绑定、失败重试、重复点击、迟到结果、目录验证、原生排版及减少动态效果。运行 Go 测试与冻结稿检查。使用真实 MyGo 渲染截图对照批准稿，并在隔离 client/worker state 的原生实例验证；不改变现有账号或用户节点。
