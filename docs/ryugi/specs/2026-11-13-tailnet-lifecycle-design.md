# Tailnet 后台生命周期修正

状态：已实施；本机授权、原节点迁移和真实 Tailnet SSH 的界面退出／重开验证通过。系统登录自启及通用入站 TCP 仍待实机验收。2026-11-13。

## 原因与目标

当前 `cmd/shioji/main.go` 创建 `tailnet.Node`，`Controller.runDevices` 使用 GUI 上下文运行它；主窗口 `OnClosed` 取消上下文，`Node.Run` 随即 `Close`，销毁节点、入站转发及 SSH 桥。因此即便 `shioji-worker` 仍在执行，关闭主窗口或退出 App 也会断网。`cmd/shioji-runtime --serve` 目前直接 exec worker，没有独立网络宿主。

用户指出这一生命周期有问题。以下为我的实现建议：网络连接不依赖窗口或 App 进程，在本次登录会话中持续；已选择连接的节点在下次登录恢复。明确暂停、登出、系统撤销后台权限时尊重用户选择，不反向自动开启。沿用 Go、官方 tsnet、原生 UI、已存在 Runtime.app 的部署及签名体系。

## 使用行为

| 事件 | 结果 |
| --- | --- |
| 关闭主窗口、退出/重启 App | 不关闭节点，不重置网络，不中断已有入站 TCP 流；新 App 只重新订阅状态 |
| worker 停止、升级或崩溃 | 不停止网络服务；worker/SSH 自身停机导致的目标服务不可用独立呈现 |
| 网络切换、暂时断网、休眠后唤醒 | tsnet 自行恢复链路；应用服务不重新注册或创建节点 |
| 网络宿主意外退出 | launchd 重启同一服务，以原身份和连接意图恢复；已断开的 TCP 流不能承诺无损恢复 |
| 用户关闭 Tailnet 开关 | 持久化 paused，关闭节点及转发；App 重启、服务重启、登录恢复都保持暂停 |
| 用户退出网络 | 持久化 signed-out，终止节点和流；后续加入须用户明确授权 |
| 系统注销/关机 | 不承诺维持网络；下次登录仅 connected 意图恢复。不做系统级/root 守护进程 |
| 关闭执行服务的“登录后启动服务” | 只影响现有 worker 服务，不暗中改变 Tailnet 开关 |

连接意图与实际观测状态分别存储。显示连接成功须来自 tsnet 实际状态，不能以守护进程启动成功代替。加入网络仍独立于添加设备；不引入设备配对流程，不自动授权 SSH。

## 进程与通信

建议在现有签名 `Shioji Runtime.app` 中增加 `shioji-runtime --network-serve` 模式及独立的用户级 LaunchAgent，与执行 worker 分进程。复用宿主签名/安装校验，但不增加通用插件或服务框架。不直接塞入 worker，因为 worker 的停止和升级不应导致全部 Tailnet 端口离线。

网络宿主持有 tsnet、加密状态、意图、入站转发与 SSH 桥。GUI 的 controller 改持有小型网络客户端，保持现有 Action/Snapshot/Route 语义，只通过本机 IPC 发送操作、读取快照并订阅更新。断开 GUI 订阅只释放客户端，不停止节点。节点暂停/退出只来自明确操作。

IPC 使用仅当前用户可访问的 Unix socket（目录 0700，socket 0600），服务端校验对端 UID；客户端核验同 UID 和部署签名/实际服务身份，不接受 TCP、SSH 远端或普通 worker RPC 控制本机网络。协议带版本、实例代号、操作 ID，限制消息大小、连接数和等待时间。操作 ID 在服务生命周期内去重；断线后先查询，不盲目重新发起加入/登出。浏览器 URL 仅向发起该授权操作的本地客户端暂存交付，不持久化或写日志。重连后的快照按服务实例与操作归属接纳，旧节点结果不可覆盖新状态。

SSH Route 返回服务拥有的私有 socket，不是 GUI 临时监听器。桥仍固定可见 peer ID/IP/端口，保留 netstack-only 拨号与既有关闭/访问校验。GUI 离开不删桥；peer 不可达、暂停、登出、服务结束时关闭流。长期运行的桥数量须有界：客户端断开后可回收无活动且无引用的桥，不关闭已有流；现有连接可向同一服务重新索取 Route。具体索引与回收实现交给 builder，不建立通用代理服务。

## 身份、部署与迁移

1. 先验证真实签名宿主可读取现有 Keychain 项，或由用户通过系统原生提示授予该签名宿主访问。保留 `Shioji.Tailnet` 的项名/原目录派生键、密钥与原加密 identity。不得把密钥放入 argv、环境变量、文件、日志或普通快照，也不放宽到任意程序可读。**此前隔离可执行文件读取返回 -25308，不能假定后台读取必然可用，也不能误诊为钥匙串未解锁。**若签名授权无法成立，停止迁移并明确报告，不能创建替代节点绕过。
2. 每个身份目录以进程锁保证唯一拥有者。先给旧 GUI 节点加相同锁，再切换所有权；多个 App 不可各启动一份 tsnet。旧版本不支持锁时，明确识别并要求退出，不能仅凭新锁判断不存在旧拥有者。
3. 候选服务先完成签名、协议、目录和钥匙串预检；之后停止旧节点、释放锁，由服务取得锁并打开同一加密身份。只有权威快照确认同一节点成功恢复后才标记迁移完成。切换存在一次短暂断流，不承诺迁移期间连接无损。
4. 预检失败不停止旧节点。交接后失败须先确认新拥有者退出并释放锁，再允许兼容旧实现恢复；任何恢复都不得出现双拥有者、改身份或重置 paused/signed-out。交接状态要可恢复，不因 App 崩溃遗留“已完成”假状态。
5. 服务注册与首次启动属于用户现有的加入/重新连接操作；遇到系统后台运行批准要求，沿用现有操作行/错误区显示真实状态。保持现有网络管理、欢迎及添加设备的布局，不增加新的设置分类、额外授权流程或二级注释。执行服务自启与网络服务配置分别归属，不能一个开关暗中管理两者。
6. 每个 client-state 身份保持独立：已有节点文件位置和派生 key ID 不改变。生产使用已校验签名宿主和固定用户目录；隔离测试使用独立目录、socket 与可回收子进程，不注册生产服务、不接管真实节点。

节点启动失败不能像当前 `lc == nil` 路径那样永远停住：对可恢复的启动失败做有上限间隔的退避重试，例如 1、2、4、8、16、30 秒并加抖动；成功后清零，暂停/登出立即取消。钥匙串权限、损坏/缺失身份、需要登录归为需用户介入，不自动重新授权、轮询弹系统提示或生成新身份。运行中的链路恢复交给 tsnet，不叠加周期性重启。

## 范围与验收

这是跨进程迁移，非一次局部重连修复。建议先完成签名宿主与 Keychain 可行性探针，再实现服务、客户端替换与迁移；最后做真实生命周期验证。探针失败是明确阻塞，不能以模拟用例替代生产支持。

- 回归：GUI 客户端关闭不调用节点 Close；worker 生命周期独立；唯一身份锁竞争；旧实例迟到快照；加入操作断线不重发；paused/signed-out 跨重启不自动启动；可恢复启动故障退避与取消；Keychain 错误不创建身份；桥/订阅长期数量有界。
- 迁移：保留节点 ID/IP、Keychain 项、入站开关、全部设备路径/DeviceID/工作区/会话；注入各交接阶段崩溃，核对只有一个拥有者并可恢复。此项若需改动真实身份访问授权，由用户在系统窗口执行，不导出密钥。
- 真实连通：用独立、经用户授权的节点和已批准的远端，建立入站长 TCP 连接，关闭窗口、退出 GUI 后验证旧流及新连接；重开 App 核对节点身份不变；分别重启 worker 和网络服务，明确网络服务重启会断既有流但可恢复新连接。
- 故障：网络离线再恢复、休眠唤醒、服务异常退出；明确暂停后重复以上事件均不自动连网。登录恢复需实际登录验证；未完成不声明通过。
- 运行 `go test ./...`、相关 race 检查及冻结设计验证。保持现有原生布局与动画；若新增失败/批准态，使用真实原生截图核对亮暗模式和对齐。验收资源与端口按用户规则回收，正式用户选择保持运行的网络服务不属于临时资源。
