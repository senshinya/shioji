# 子 Agent 的提问与授权：实现设计

这是当前会话侧栏功能的后续补齐，中等规模：适配层请求归属、worker 持久化与回答校验、原生请求区与侧栏状态共用同一份请求信息。设计已确认，本轮按此实现。

## 来源与取舍

当前 Lody 的 FloatingPermissionRequest 共用 composer 尺度的权限／问题界面，分页保存各表单状态，展示实际请求内容与选项。所查看的源码没有证明它具有与 T3 相同的独立子会话授权聚合。当前 T3 Code 的 ChildThreadApprovals 明确带子会话标题和独立环境／线程路由；应用托管子任务提问还可以通知父 Agent，由父 Agent 决定回答或询问用户。具体 commit、文件链接、截图渲染边界见 sources.md。

Shioji 沿用已确认的统一底部请求区，正常 composer 始终独立可用。新增部分只有来源链接、子 Agent 等待状态和来源关联；不加入自动代答、额外独立请求卡组或新的会话导航。

## 交互

- 主会话及子 Agent 的所有待处理问题／授权共用现有 pager，一次展示一个页面。一个请求的多题一起提交；明确选择和提交分离，选中不发送、不自动翻页。
- 子 Agent 请求的标题旁展示其名称，长名称截断可查看全名。点击打开同一右侧栏里的对应详情；详情中的轻量请求来源可定位回底部。主会话自身的请求沿用原标题。
- 侧栏将该子 Agent 的状态替换为灰色问题／授权图标与等待回答／等待授权。其他工作继续自己的状态和输出；父回复已完成也保留子请求与待处理入口。
- 新请求只追加，不替换当前页、答案草稿、折叠状态或焦点。不在输入时强制展开。沿用右侧新增 N 项提示，展示后回收并清零；折叠时只显示最右总数，不显示无意义页码与翻页箭头。
- 仅在确认接纳对应回答之后，原来源标记已处理，在最新位置追加小型结果回执，之后才继续展示该子 Agent 的新文字。回答一个请求不解决其他请求。
- 断线保留所有草稿，禁用提交；失败保留当前页并允许重试。由实际 resolved／失效事件撤销请求，父轮完成不替代其生命周期。跨客户端以 worker 状态为准。

## 动画与布局

沿用请求卡 12/14 px 内缩、紧凑标题、原生选择项和 28 px 操作高度；使用既有灰阶，不新增装饰标签或说明段落。

请求区沿输入框顶部以真实高度展开／收回，内容同步移动，没有整体淡入淡出。页间 240 ms 左右移动，实际高度同步；来源跳到详情沿用同栏 260 ms 水平移动。新增提示从右侧移入并移出。轻量回执先完成出现动画，再开始子输出渐进。所有动画尊重减少动态效果。侧栏图标、文字和等待标签对齐首行，状态切换不改变槽位。

## 接入约束

共享请求增加中立的工作来源引用，以 worker 所属 Session / Work / Request 关联；具体子线程和原生 request 编码由 adapter 保存，不交给 UI 解析。进入表单与回复时都重新核对当前实例、来源、请求状态与权限范围；不扩大原请求的授权。

实现前用隔离真实 Codex App Server 验证子 Agent 提问、执行／文件授权、请求早于启动结果、父轮结束后的请求、原生 resolved 与断线失效。只有已由结构化来源确认归属的请求才能进入主会话；不能将未知子线程冒充为主线程或直接绑定到任意会话。缺少实际能力时明确保持不可用，不用父 Agent 中断／回答替代。

worker 保存来源、草稿关联与有序回执，界面投影不控制执行。历史重开、运行实例替换及停止证明继续遵守当前独立工作归属边界。

## 设计预演

artboard/subagent-requests：proposal 为亮暗提问与授权，flows 为多个请求、折叠、回执、父回复完成、窄窗口和离线，references 为 Lody／T3 当前源码片段与 Shioji 方案。所有数据与响应为本地隔离样例，无真实模型或设备操作。

## 实际运行时验证

Codex 0.167.0 的隔离 App Server 与本地确定性 Responses provider 验证了：子命令授权具有子 thread/turn 来源，主回复完成后仍可独立确认；原始 resolved 产生回执并继续子输出。部分子 request_user_input 被运行时转发为主 thread/turn 请求，未携带子来源，此时按主请求展示，不推断子归属。该行为无法用共享层猜测弥补。真实运行时、测试样例与设计稿数据的证据边界分别保留。
