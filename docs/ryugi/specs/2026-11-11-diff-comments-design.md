# 任意分支比较、精确文本评论与输入引用

状态：2026-11-11 用户已批准，进入实现。用户已明确移除辅助上下文，增加工作目录/分支及任意分支间比较。

## 目标与已确认交互

用户在现有单一右栏的 Diff 中选择文本，松手后选区旁浮现一个 28 DIP 的评论按钮；点击按钮才在所选片段下方展开评论框。单击代码、行号或悬停均不展开评论，不保留行号旁的加号入口。支持行中的一个表达式，以及起止都位于行中的跨行选区，不要求选满整行。

右栏顶部固定“基准 → 目标”两个版本选择器，文件列表与详情共用；支持当前提交、工作目录、本地分支和已获取的远程分支。默认比较 HEAD → 工作目录。用户可以将任意分支作为基准或目标，也可以将工作目录与任意分支比较、交换方向。比较是只读查看，会话实际 checkout 和执行分支保持独立。

“加入消息”将评论引用放入原消息框，保留原有文字和光标位置；多条引用随普通消息一起发送。草稿、待发队列、已发送消息、历史编辑和分叉均保留引用内容与位置。点击引用回到原选区；评论只提供代码反馈，不自动发起模型请求或文件修改。

视觉保持 Shioji 当前中性灰、紧凑排版和单一右栏：代码旁小按钮，原位评论，行内“图标＋文件:行号”引用；不新增审查管理页。Lody 参考评论与会话联动，T3 Code 参考本地评论草稿和代码片段快照。

## 设计稿与原生差距

- Artboard：`artboard/diff-comments`，目录 `.ryugi/artifacts/artboard/diff-comments`。
- 局域网链接：通过本地 Ryugi launcher 获取；不在源码中保存访问凭据。
- `proposal`：亮暗模式可操作原型；`states`：局部文本选中、编辑、引用、发送、版本变化、窄窗口；`references`：隔离宿主下的上游组件 JSX 实渲，非完整应用截图。
- 新增 `comparison` 页：基准/目标选择、工作目录与分支、分支与分支、评论分支归属及模型输入。分支名、提交和差异均为样例数据，不是实际仓库的支持证据。
- 当前 MyGo `DiffState` 只有 `SelectedLines` / `OnLineSelection` 公共接口；底层编辑器的文本偏移使用 UTF-8 字节。统一视图的删除块目前会截获指针输入。实现必须补实际字符级选择，不能用整行回调代替。
- 当前 worker 的 `changedFiles` 固定执行 HEAD → 工作目录比较，`fileVersions` 固定读取 HEAD blob 与磁盘文件；协议 `GitQuery`/`FileQuery` 没有比较两端。因此必须先扩展真正的只读比较能力，不能仅增加前端分支选择器。
- 原型只展示行为，不建立原生选区、worker 快照或真实模型发送的支持证据。

## 比较语义与设备边界

基准为左侧旧版本，目标为右侧新版本，直接比较两端的实际内容。分支与分支默认比较两个 tip，不隐式改为共同祖先口径。工作目录包含暂存、未暂存和未跟踪文件，保留现有忽略规则；当前提交不存在时保留原有空版本比较能力。

比较局限于会话已接纳执行目录所属的同一仓库，不把工作区多个目录视为共享 Git 历史。远程查询、分支目录和文件读取全部由 owning worker 完成。远程分支指所属设备本地已经获取的 ref，本轮没有自动 fetch、checkout、stash、reset、merge 或 worktree 创建。

请求使用中立的、类型化的两端描述；分支名称由 worker 在读取时解析为实际提交。文件列表和文件内容必须沿用同一组解析后的版本，不能列表比较 A/B、正文却读取 HEAD/工作目录。读取提交版本使用 Git 对象；工作目录读取沿用现有路径、常规文件、大小与文本限制。新增/删除文件的一侧为空；保留当前重命名按删除/新增表达的策略，不加入不可靠推断。

分支结果以两端提交固定；刷新才采用新的 ref 位置。工作目录是活动文件，不承诺整仓库原子快照，文件打开时由 worker 固化该文件实际读取的版本。已有结果在新比较读取期间继续显示原来的比较名称和内容，使用同一个旋转指示表示读取；新选择和结果一起接纳。快速选择/反向选择以最后的请求为准，迟到响应不能覆盖。失败保留已显示的比较与草稿，在选择器附近给简短重试反馈。

切换比较保留普通草稿和已有评论引用；未完成的评论输入按比较及文件保留，返回时恢复。不同比较产生的评论可以同时放入同一条消息，每条引用独立保存自己的来源。相同内容比较为空时显示“没有文件差异”。点击已有评论引用恢复其已固定的比较版本，而不是按当前同名分支重新解析。

## 精确选区与快照

新增中立的代码评论引用，独立于文件与 Skill 的含义，复用现有行内引用位置和资源生命周期。最小数据包括：稳定评论 ID、所属设备/工作区/会话上下文、相对文件路径及明确行号、比较双方的名称/类型与固定版本、选中侧、worker 提供的快照引用、评论内容，以及有序的文本片段。分支名称与提交一起保存；工作目录额外记录所属分支、基于的提交和该文件快照标识。

每个片段记录旧/新侧、原始缓冲区的 UTF-8 起止字节偏移（左闭右开）、精确选中文字和辅助行列位置。UI 的换行、Tab 宽度、缩放、折叠与行号不改变源文本偏移。中文、emoji、组合字符和 CRLF 必须保留原文，不按浏览器 UTF-16 偏移截 Go 字符串。

连续选择若穿过新旧侧，按视觉选择顺序保存各自来源的片段，不伪造成某一侧连续文件内容；原生复制结果和被记录的选中文字必须一致。选择不能夹带行号、增删标记或评论框文字。处理只扩展 Diff 组件的选区、几何与复制能力，不建立通用选择框架。

评论引用只保存并发送精确选中文字，不为 AI 提取周边辅助代码。界面恢复原 Diff 所需的两侧文件快照由 worker 单独保留，不编码进评论或模型输入；它们沿用现有资源的引用保护和回收规则。选中原文不做静默扩展或截断。文件标明实际选中版本的行号，字符偏移辅助精确定位。最多 8 条评论；普通文字、评论、版本/位置元数据与选中文字合计计入现有 128 KiB 文本输入限制，超过时保留草稿并明确反馈。

快照由所属 worker 管理：在返回 Diff 内容时标识实际比较版本，添加评论时将该版本内的片段固化为不可变资源。复用现有引用资源的保存、保留与清理机制，不新建独立持久化服务。远程路径始终在所属设备解析。代码在选中后变化，不重读当前文件替换旧选区；无法取得原始快照时保留评论草稿，要求重新选择，不冒充当前文件内容。

## 实际提供给 AI 的内容

例如原行是 `root.Right = next.Left`，用户仅选择 `next.Left`，评论为“先判断 next 是否为空”。模型输入应明确包含：

```text
比较基准：main @ a41d9c2
比较目标：feat/rotation @ e9f3028
文件：rotation.go:13，第 16–24 列
选中侧：目标侧，feat/rotation @ e9f3028
选中文字：next.Left
评论：先判断 next 是否为空
会话工作目录分支：main
```

这里是语义示例，不是固定 wire 格式。工作目录目标应写明所属分支、基于的提交及所选文件快照。会话实际执行分支与评论目标分支分开描述，不能让 Agent 误以为比较目标已经被检出。普通消息和类型化评论引用一起由 worker 接纳；适配器转换为对应 harness 支持的输入，除选中文字外不附加文件代码。共享层不引入 Codex 的方法名或 wire 结构，也不将 UI 标签名称当作实际代码内容。选中文字属于用户提供的代码数据，不再解析为 Skill、斜杠命令或权限指令。

## 分步实施与验收

1. **只读比较基础。** 扩展中立比较两端与结果类型，实现分支目录、两端解析、文件列表及固定版本读取；覆盖分支/分支、分支/工作目录、反向、相同版本、未跟踪/新增/删除、分支移动与原会话目录边界。断言真实仓库、HEAD、index、工作目录和正在运行会话不被改变。
2. **原生选区基础。** 在 MyGo Diff 提供精确片段、选中文字及可见选区矩形；补统一视图删除文本的字符级选取。覆盖局部、跨行、反向拖选、键盘扩选、换行、Tab、中文/emoji、折叠及滚动。证明选区记录与原生复制一致后再接 UI。
3. **比较选择与评论交互。** 两侧搜索选择器固定在右栏顶部，列表/详情共用，交换只改变比较；处理迟到响应和比较内草稿。选区稳定后按钮渐显，拖选中不显示；点击冻结选区，再交接评论焦点。原位框在最后选中片段下方做真实高度动画。
4. **中立引用与 worker 快照。** 增加具体的评论引用类型和快照接纳，校验 owning device、已接纳目录、比较双方的固定版本和精确片段；明确文件/行号及选中侧。不为 AI 额外提取周边代码；恢复界面的完整 Diff 快照独立保存。持久化引用身份和输入位置，沿用现有 journal/资源存储；已有客户端/worker 能力不足时不显示可提交入口。
5. **完整发送链路。** 草稿、队列新增/编辑/发送、普通发送、Steer、历史编辑重开和分叉都保留同一不可变引用；仅评论也构成非空输入。仅在 worker 确认接纳后清理对应草稿；失败恢复评论及普通文字，重连查询原操作而不重复投递。核对适配器实际收到选中文字、评论、文件/行号、双方分支版本和实际执行分支，无辅助代码。
6. **展示与定位。** 草稿和消息使用同一引用排版；预览展示比较双方、选中侧、文件/行号、评论及精确选中文字。点击恢复原比较并平滑定位；分支移动或文件变化时显示已有快照，不按新版本的同一行号高亮。去掉引用不会删除已发送历史。
7. **真实验证。** 运行全量测试、相关竞态、冻结稿校验和开发构建。用隔离本机/SSH 仓库覆盖真实分支比较与模型输入，证明比较不切分支、旧引用不被新比较污染；展示亮暗、窄窗口原生截图与短交互回放，明确夹具与真实发送边界。

## 动画与阅读位置

源与目标交换时，两个分支名称沿相反弧线移动互换位置，260 ms EaseOut；交换控件、箭头和其余顶栏保持原位。快速反向操作承接当前位置，减少动态效果立即完成。

按钮 140 ms 渐显/渐隐，评论 220 ms EaseOut 真实高度展开/收起，引用 180 ms 入场；文件与标题沿用 260 ms 横移，固定操作保持原位。只有一个高度动画负责者，后续代码同步移动。滚动、重绘和焦点交接不重播已有内容，不丢选区或改变草稿；减少动态效果立即完成。

## 本轮边界

本轮是代码评论输入，不包括 GitHub 发评论/认证、自动审查代理、结构化 AI 问题清单或自动判定修复完成。不上线第二种 harness，不改 Git 历史，不扩大已有会话的目录权限。UI 标签样式和布局以此稿为准，原生 API 的具体命名与内部实现由实施者按现有组件决定。
