# 归档管理 · design / unslop 精修

范围：本轮已实现的原生归档会话页、归档工作区、删除确认与保留设置。用户要求审查并解决全部发现的问题；沿用既有方向直接修正。

## 方向

- 产品：开发者跨设备找回与管理已归档工作。
- 性格：克制、准确、紧凑。
- 材质：macOS 原生系统字体与既有冷灰表面，保留中英文系统回退度量。
- 内容重点：真实标题、所属 workspace、明确的恢复与删除反馈。
- 一致细节：两列共同基线，28 DIP 操作命中区、16 DIP 图形槽位；行内操作只在悬停或聚焦时出现。

视觉：平面列表、清晰文字层级、轻分隔，不加卡片、插图或强调色。
内容：归档标题 → 会话/工作区 → 搜索 → 全量列表。
交互：共用 Tab 滑动、整行打开、独立操作按钮、查询与列表位置保留；减少动态效果沿用项目设置。

## 审查与修正

1. 信息层级：顶部 `Shioji / 已归档` 与正文标题重复，移除重复路径，保留窗控拖动区域。
2. 间距：标题、Tab、搜索与列表之间层层留白，压缩为 24/12/16/8 DIP；列表从 46 调整为公共表单节奏的 40 DIP，计数与表头使用可读的 12 DIP 字号。
3. 列与图标：动作列改为真实的 `28 + 4 + 28 = 60` DIP，列间距使用 16/8 DIP；统一表头与行内边距，保留原生基线度量，不用逐条文字偏移。
4. 行内行为：Workspace 一列原来不可点击，改为标题与 metadata 共用打开控件，恢复与删除保持独立；统一整行悬停，并提供键盘焦点环。整行按钮为辅助技术描述所属工作区或设备，避免子文本被按钮语义合并后丢失归属。
5. 搜索与返回：工作区进入/返回、Tab 切换原来清空条件，改为每个列表保留查询；补充清除按钮并将焦点交回输入框。
6. 禁用状态：离线恢复/删除、旧 worker 不支持永久删除时提供具体悬停原因；归档工作区内的会话继续提示先恢复工作区。
7. 删除确认：收短重复文案，保留对象与会话数量、不可恢复及项目/Git 边界；请求中显示“正在删除…”，不允许 Escape 隐藏未完成操作，失败使用既有错误色并保留重试。
8. 设置：将重复的两行说明合为一个完整句子，沿用现有窗口、表单列和四个选项。
9. 验收资料：旧夹具使用 `/var` 临时目录而 worker 规范化为 `/private/var`，导致无关的目录身份错误提示遮挡画面。夹具改用规范化路径，重新录制真实原生证据，不修改生产目录验证。
10. 工作区标题：最终截图检查发现名称与设备名的文字基线相差 3.023 DIP，改用内层共同基线布局；新增回归先失败后通过，长名称仍为保留设置让出空间。
11. 确认文案换行：截图出现句尾“除。”孤行，将记录清理与项目文件边界分成两行，保持 24 DIP 内边距与对齐的底部操作。

检查后保留：原生字体与灰阶对比度符合既有设计；未发现渐变、发光、Emoji、卡片堆叠或装饰动画；长名称与保留控件的边界、设置入口已有回归通过，不为变化而重做。

行为修正先由原生测试重现，再修实现。最终检查亮暗、中文/英文/混排、820 DIP 窄窗口、长列表、键盘、过滤/返回、删除取消与失败。验收证据保留在原画板 Verify 页，最终视觉结果由用户确认。精修提交为 `eeb2de4`、`0e758f4`、`5fcaab2`。

审查方法使用 design 与 unslop；unslop 方法由 Damir Sokolovsky（[@heydamir](https://x.com/heydamir)）创作，CC BY 4.0。保留项目现有设计系统优先于通用网页 token。

## 验证

原生行为回归先后重现 metadata 点击死区、工作区返回丢查询、缺少清除入口、删除无进度反馈以及 Escape 隐藏请求中的确认窗，再修复为通过。键盘行操作顺序、长标题、亮暗与窄窗口列/基线检查均通过；归档 UI race 通过，UI 整包回归通过（285.182 秒），最终辅助描述微调再次通过归档回归、race、vet 和开发构建。冻结稿 6 个文件仍匹配基线。

实际 MyGo 窗口核对了搜索、清除、打开归档历史、返回保留查询、工作区过滤/进入/返回、Tab 访问独立操作、删除取消、四档保留设置和辅助描述。没有删除用户数据；永久删除成功/失败/进行中状态由原生回归测试覆盖。原生证据与前一版对照保留在原画板 Verify 页。

本轮变更为 UI 精修，没有改动 Codex 执行链；上轮记录的既有沙箱集成测试限制仍见 `docs/archive-management.md`，不作已解决声明。
