## 1 确认的目标与范围

用户停止全部会话后，常驻 MCP／Node 内核不再阻止 worker 更新。闲置到期由后台主动回收整套会话环境，归档立即开始回收；保留历史、普通草稿、队列、设备与工作区身份。更新、停止和恢复由后台完成，不要求用户选择会话环境、PID 或进程组。

完整删除原后台环境处理页、强制恢复页、设备“查看阻塞／强制重启”、会话及待核对面板的“强制关闭运行环境”，不能仅藏进高级菜单。新后台链路与删除同一交付，不能留下无限等待或不可操作失败。

本方案的“无感”与 Lody 相同：准备、排空、切换和重新连接自动完成；不承诺保留 Agent 内存与管道跨 worker 升级。当前任务需要等待结束，或者用户在普通更新动作中选择立即更新；源历史与文件保留，未知输入不重发。

明确不做：独立会话 host、host 事件 spool、跨 host writer epoch、通用进程管理器、完整后代扫描、新的运行环境页面。未登记后代的完备覆盖不作为发布门槛，不按进程名扩大清理。业务中确实未确认的输入／请求仍按原有防重放规则处理，不能以这次范围选择伪造完成。

继续遵守 Go、原生 MyGo、Apple Silicon macOS、自有 worker、harness 中立边界、独立 tsnet 服务与现有签名身份；不引入 Lody 的 Node／ACP／SEA／Electron 运行依赖，不复制其云认证。最低 macOS 版本仍未定，不直接套用其 Node 对系统版本的要求。

## 2 依据与职责

基线为 Lody `fb05adc646f02762a62c19cf8e9dadd9f765a3e0`，Codex adapter `f2a140b5a630454f3707c48d93ea162ecbad82e7`。完整调用链、源码链接与验证见[源码分析](../../lody-worker-lifecycle-analysis.md)。旧独立宿主草案保留于本地研究归档，已经撤回，不再是实施要求。

| 组件 | 采用 Lody 的职责 | Shioji 中的落点 |
| --- | --- | --- |
| 原生 App | 显示真实阶段、提交明确操作、重连查询 | 现有设备执行服务行和会话 Stop；不直接管理工具 PID |
| 固定执行服务 supervisor | 拥有服务控制、候选准备、持久操作与选中版本，替换 Worker | 复用 `cmd/shioji-runtime` 与已签名 Runtime.app；直接 SSH 设备使用同职责的持久入口 |
| worker | 唯一业务 writer、派发与 Git 串行化、会话／adapter 所有权、停止和最终落盘 | 现有 `internal/worker`；adapter 继续在 worker 内，不迁到独立宿主 |
| 会话 runtime | 每会话一套 app-server、exec-server 与登记工具；可按需退休重建 | 现有 harness adapter、executor、managedexec |
| 网络服务 | 保有 Tailnet 身份、连接与转发 | 现有独立网络服务，升级不注销、不停止、不重新授权 |

固定 supervisor 拥有服务控制锁；worker 继续取得原 `owner.lock` 后才可打开可写业务库。两者不是两个业务 writer。禁止删除或替换 owner 锁文件伪造独占；禁止新进程继承不属于自己的 writer FD。固定入口保持历史签名与注册身份，按摘要暂存版本，不原地覆盖运行中的映像。

## 3 统一的会话回收操作

在现有 runtime／managedexec 上统一一个直接的退休实现，接收 SessionID、原 runtime 实例／Generation、原因（idle、archive、update、stop-timeout 等）及正常／强制模式。多个入口共用它，避免各页面各造一条关闭程序；不设计通用插件框架。

先与派发共用串行边界，封闭本代新启动、捕获已登记对象、保存退休意图，再执行退出。删除 runtime 映射与处理迟到回调都核对原实例和代次；旧回收不能杀新 runtime、清掉新引用或让旧事件恢复被替换内容。并发回收共享进行中结果；失败可重试，不永久缓存失败 promise。

按 Lody 直接采用：闲置 GC、归档、更新排空和取消超时走强制退休，主动结束登记的会话进程范围；默认 KILL 后最多观察 5 秒。正常关闭路径可先调用 adapter 原生 close，再 TERM 最多 5 秒、KILL 最多 5 秒。不能声称 force 分支执行了它实际跳过的原生 close。

Shioji 必须覆盖自己实际拥有的 app-server 与独立 exec-server，并等待两者及已登记组的最终结果；不能只关 app-server stdin 就报告整套环境回收成功。保留现有进程身份、UID、启动时间和控制组保护；根退出后仍保留未清空的登记组。ESRCH／实际退出视为收敛，单次信号错误后重新观察；僵尸不当成仍有执行。EIO 只有结合现有准确消失检查才能判退出。

回收失败保留原句柄、登记与失败原因，后续重试原对象；不按同名进程重扫。登记缺失的后代不扩大本轮范围，也不单独制造全设备等待条件。区分“登记范围已回收”与“全部 OS 后代已消失”，不写超出实际范围的退出证明。

## 4 闲置回收：20 分钟闲置，每 30 秒检查

采用 Lody 的闲置回收机制，Shioji 参数按用户确认设为 **20 分钟闲置、每 30 秒扫描**，原生后台任务仍保护至闲置 **24 小时**。这替换 Shioji 当前 10 分钟／5 秒检查的设置。Lody 源码的扫描默认值仍为 60 秒；Shioji 使用本次确认的 30 秒，不为参数增加选择页。

资格看业务与原生工作：没有活动／初始化轮次、待处理请求、未决投递、待发队列、活动历史操作或仍需要本环境的目标；原生实际状态不是 running。仅等待后台任务时按 Lody 保护；超过保护期且其他条件通过才回收。真正执行不因静默或 CPU 很低而被当作闲置。

MCP 服务、Node 内核和其他健康常驻工具的“进程仍存在”不等于实际工作，不再使用当前 `FenceIfIdle` 的“必须没有额外子进程”作为 GC 资格。adapter 报告中立的实际活动／后台工作分类，worker 使用已接纳轮次、请求、操作与队列补足；没有上报原生活动能力时按这些权威业务事实判断，不另加 OS 存活兜底把所有环境永久判忙。准确已知的投递未知仍保留。

候选筛选后，在同一派发边界复核最新状态与最后活动时间，封闭本代启动，再持久退休和回收。单个资格读取错误只保留该会话，其他候选继续；不得通过渲染、查看会话或客户端掉线重置执行空闲时钟。

成功回收只释放进程与运行期内存，保留 SessionID／ThreadID、历史、附件、草稿和 Git 上下文。下一次用户实际发送按原线程启动新代次并重新验证配置；不因阅读历史重新建环境。失败保留可重试对象，不能反复重置计时掩盖从未尝试清理。

Lody 的内存压力回收可以提前释放等待后台任务的闲置环境，但不释放 running。Shioji 若复用这一分支，只使用 macOS 真实压力信号与同一有界回收实现，不引入 Loro Wasm 堆阈值、Linux cgroup 或新的内存配置页面；这不作为修复本次升级阻塞的额外交付前提。

## 5 Stop 与恢复

普通 Stop 针对准确轮次，保存取消意图、暂停该会话队列，发送 adapter 原生 interrupt。等待真实轮次／原始请求及已发送配置收尾，不能只等取消 ACK；预算按 Lody 为 5 秒。正常收尾后保留健康 runtime 供下一轮使用。

5 秒仍未收尾则自动退休该轮对应运行环境，不再进入“先去查看阻塞、再选择 PID、再单独强制”的页面链。记录停止超时与实际物理结果，禁止复用未释放的旧实例。初始化阶段停止要分离卡住的创建任务，迟到创建结果只清理原实例，重试不能拿回同一个卡死 promise。

运行环境退出不代表已执行外部命令成功，也不代表未知输入可以重发。后续按原线程核对来源历史；原失败输入保留结果，队列保持用户暂停状态。Lody 可见执行槽释放与物理终止分别记录的原则照搬，Shioji 的输入接纳／防重放规则继续有效。

2026-11-17 对照修订：清理失败后立即分离旧 Agent，清除其对新轮次的逻辑阻塞，保留按 Generation 的持久清理记录并独立重试。新实例可沿原历史继续，不再要求旧实例物理退出才能取得执行槽；旧操作记为 abandoned，结果仍明确未知，旧输入不重发、队列不自动继续。旧事件、启动回调和 finalizer 均绑定原实例，不能修改新实例。共享 checkout 的实际分支切换仍受未确认旧执行保护。

## 6 更新接纳与在线准备

supervisor 接受稳定 OperationID、原版本、目标 BuildID／版本及策略；同设备一个切换操作。多客户端查询同一结果，重复同 ID 绑定同意图，已经终结的 ID 不作为新更新重放。远端继续使用已有严格 SSH 或私有 Tailnet 认证，本机沿用已授权自动更新范围。

默认 `when-idle`：只等待本 worker 实例持有的派发／初始化 reservation、实际会话轮次及原始请求；历史未知回执、未决历史操作、孤立请求、标题任务与后台等待记录不单独构成升级 reservation。停止初始化会立即解除创建等待及本轮 reservation，迟到对象由原实例 reaper 清理。不等待闲置 MCP／Node 自行退出。普通更新可提供 Lody 相同的 `immediate` 策略，明确一次说明会结束运行任务，然后暂停并中断；不是新加强制环境菜单。

先在线完成候选复制／下载、签名、摘要、darwin/arm64、协议与数据兼容检查，并在隔离状态目录探测真实二进制。旧 worker 在准备期间服务；探针不读真实凭据、不迁移真实数据库、不启动模型任务。复用 `StageWorker`／`InspectWorker` 等现有工具，保留 Apple codesign 和已有发布签名，不降低到仅看哈希。

按 Lody 采用有限准备预算（约 8 分钟、控制等待 10 分钟）和过期意图；断线只查询同一操作。准备失败／取消／过期保持旧版，不先停止旧服务。跨渠道、降级和不可逆数据变化继续要求相应明确动作，不以普通自动更新扩大授权。

## 7 正常升级：排空后切换

1. **取得切换资格。** 在跨工作区的同一派发边界核对 reservation，并原子暂停新轮次和队列派发；默认只等真实执行，immediate 标记中断原因。准备期间仍需在最终接纳前重验目标和权限。
2. **持久化切换意图。** 写本次操作、原实例、目标和阶段。收到回执未知不能生成新 ID 再停止一次。
3. **主动关闭环境。** 对全部实际会话 runtime 及其登记工具执行统一强制退休；目录／登录等辅助生产者也按自身所有权收尾。后台进程存活不再在这一步之前否决升级。
4. **完成最后持久化。** 先终止事件生产者，再等待轮次 finalizer、请求／操作释放、最后输出和事件落库。保持业务库与附件 writer 开放到这些写入结束，不先禁用事件回调导致尾部消息丢失。
5. **核对 drained。** 确认本次登记范围收尾和持久化成功；生成绑定实际旧实例的 drained 回执，关闭业务 writer，旧 worker 退出。只有根 PID 消失、退出码或 socket 断开不作为 drain 证明。
6. **启动候选。** supervisor 保持服务控制身份；候选先取得原 owner 锁、打开同一设备数据、完成本地读取／事件控制健康检查，接纳暂不开放。外部模型、账号登录或 Tailnet 暂时离线不应代替本地 ready 条件。
7. **提交并开放。** supervisor 核对实际 PID、BuildID、DeviceID 和本次操作，持久化 selected 与 applied 后开放候选接纳；客户端查询同一回执才显示更新成功。普通队列按原许可恢复派发，Stop／手动暂停和未知输入不自动继续。

上述步骤表达依赖关系，不是每步重新领取完整等待时间。更新排空开始时记单一单调时钟 `T0`，提前持久化本次 retirement 意图和队列暂停状态；所有会话并行收尾，同一会话的 app-server、exec-server 与登记工具在封闭启动后并行终止，各自观察取 `min(5 秒, 剩余总预算)`。不得串行每个会话等 5 秒；也不把正常 Stop 的 5 秒取消等待或正常 close 的 TERM／KILL 预算塞进这条 force 路径。

整个 worker shutdown 共用 `T0 + 7 秒` 硬截止，前 6 秒内并行等待原始执行释放、进程回收以及它们逐步解锁的 finalizer／尾部事件。依赖完成的历史仍必须在关闭 writer 前提交，不能把最后事件丢弃来赶时间。到 `T0 + 6 秒` 仍未完成时，worker 的退出协调者直接通过 store 将原已接纳但未结清的操作记为 unknown／退出未确认，并暂停其队列；预留最多剩余 1 秒进行这一批失败记录写入，不依赖已经卡住的 finalizer。开始排空时已保存的意图保证这一步再次失败也能被下次读取；不承诺最后一秒磁盘一定可写。

只有进程结果、释放回执和最后持久化全部成功且仍在硬截止内，才发成功 drained。硬截止到来时不给 drained，由 supervisor 的独立操作记录保留未完成／blocked 事实；下一次读取意图与源历史核对，未知输入不重发。supervisor 外层正常等待 30 秒、KILL 核对 5 秒是保住服务控制与处理无响应 worker 的外层上限，不能反向增加 worker 的 7 秒预算。Go SQL 事务的取消／收尾须正确区分，硬退出不能让另一个仍存活的 writer goroutine 被当成已释放；实际 owner 锁仍是新 worker 的最终边界。

本流程不保留 Node 内存；“已停止会话的常驻环境不再卡升级”由后台主动排空实现，不靠新宿主保存管道。

## 8 候选健康、存储兼容与回退

直接采用 Lody 的 preparing／waiting／switching／observing／applied／rollback-stop／rolled-back／failed／blocked 阶段。候选本地 ready 最多 3 分钟；超时先请求退出，8 秒后强制结束准确候选、观察最多 5 秒。未确认候选已释放 writer，不启动旧版或第二候选。

候选失败且已确认 drain，可回到保留的兼容旧版一次；旧版回退再失败则落到明确失败状态，停止反复切换。普通崩溃采用 Lody 的 5 分钟／10 次窗口，健康运行 60 秒后重置计数与退避；1 秒起指数退避，上限 60 秒，±20% 抖动。该窗口不跨 supervisor 实例累计；升级交接日志的持久 blocked 独立保留。不照搬 V8 OOM 计数作为 Go 内存判据。

候选在提交前不能做不可逆真实数据迁移。存储兼容不仅看 schema 数字，还要验证旧版往返读写不丢 Accepted、Explicit、退出范围等字段。需要不兼容迁移时单独接纳、先做 SQLite 一致备份并阻止旧版本重写新库；不拿过时备份覆盖升级后已有新历史。

更新日志和选中版本按 Lody 的原子文件发布、文件与父目录持久化、按 ID 长期结果防重放实现；复用现有字段与小型控制记录，不另造多套日志／通用事务系统。缺少 selection 只代表首次安装，损坏或引用文件缺失不能静默变成 fresh install。

## 9 失败路径与固定入口恢复

| 故障 | 直接采用的行为／可执行下一步 |
| --- | --- |
| 下载、签名、平台或协议检查失败 | 旧版继续；普通重试更新 |
| 默认策略下仍有真实任务 | 等待实际结束或取消意图；用户明确立即更新时转对应策略 |
| 常驻 MCP／Node，业务已闲置 | 主动清理，不返回无限等待空闲 |
| 已登记对象自行退出／信号竞态 | 最终复查，已退出即收敛；PID 复用不杀新对象 |
| 已登记对象无法终止或没有成功 drained | 不伪造更新完成、不并行写库；保留失败和现有普通重试入口 |
| 候选失败、退出和落盘可确认 | 兼容回退一次，显示真实结果 |
| 准备／等待阶段固定入口重启 | 失败旧意图，继续已选版本；不自动重放原请求 |
| switching／observing／rollback-stop 中根服务中断 | 沿用 Lody blocked 保留拥有权；不声称可以无条件自动恢复 |
| GUI／SSH 断连，操作已接纳 | 设备独立执行，重连查同 ID；草稿和未知输入保留 |
| 磁盘满、数据库损坏、系统拒绝启动 | 保留原件与具体原因；释放空间、恢复系统授权或使用可信兼容安装器修复 |

极端 blocked 的恢复采用 Lody 已有系统级路径：停止该产品的自启动／冲突实例，重启执行设备，保留并归档本次操作指针与选择，使用可信兼容版本重新安装；长期按 ID 的回执、业务库、凭据和制品不删除。Shioji 使用现有安装／系统设置入口和具体错误说明，不恢复复杂的环境页，也不自动重启远端设备。

这是一条明确恢复路径，不是新增热恢复系统。用户接受的未登记后代不再额外触发全设备 fence；真正的服务所有权、writer 或已接纳输入未知仍按上述事实处理。不要把“接受覆盖范围”扩大成“可以并行启动两个 writer”。

## 10 归档与恢复

归档生命周期采用 Lody 的独立释放路径：已接纳归档立即生效，后台回收该会话的 runtime、工具及会话拥有的辅助资源。归档不等环境退出才把 RPC 一直挂住，退出失败也不撤回已接纳归档；保存失败对象和清理待办，后续重试。

### 10.1 归档立即回收运行环境（用户已确认）

会话归档后立即退休 app-server、exec-server、MCP、Node 内核及其他已登记工具；工作区归档覆盖全部所含会话。没有环境的会话直接完成，不启动一个环境来执行回收。不等 20 分钟 GC，也不等归档到期删除。

沿用 Shioji 已有业务准入：活动轮、待审批／回答、真实未决投递及非空队列先处理。健康常驻服务不因仍活着被当作不准回收。归档动作授权其已登记运行范围的退休，不增加 PID 选择或重复强制确认。

归档元数据与代次回收待办同一事务保存；使用已有执行记录或一张直接的退休待办表，不误用“永久删除归档”的 outbox 去删除历史、附件或源线程。中断后按相同操作、原代次继续；归档清理不会重建会话。

阅读归档与恢复归档不自动启动进程、续答或发送队列。下一次实际发送按原 SessionID／ThreadID 重建环境。恢复／再归档与旧回收并发时，旧回收只操作原捕获实例，不能误伤新 runtime；原代次登记对象仍未确认退出时，先重试该对象，不把新输入默默投给旧 Agent。

## 11 首次迁移与历史故障覆盖

2026-11-17 用户决定：本轮仅对齐升级准入、清理失败释放和崩溃策略；不再为首次迁移增加兼容或自动回退，后续由用户手动处理。以下保留已有迁移实现与历史证据，不扩展迁移范围。

旧 worker 不一定提供新维护 RPC，固定入口准备与候选探测不能依赖那个能力。采用 Lody 显式安装迁移思路：旧服务仍活着时准备；确认原注册和准确 writer；同一派发边界封闭准入、排空原环境、保留一致备份，再启动固定 supervisor。旧版没有原子准入时，先结束准确旧 writer 并取得原 owner 锁，重读最终接纳记录后继续；不能拿早先快照边扫描边杀。

保留原执行服务签名／启动偏好、设备身份和状态目录，不注销独立网络服务或关闭 SSH。已有 launchd job 只在确认本产品归属后显式替换，避免旧 job 停止时结束新服务。迁移失败且数据兼容则恢复原签名制品／注册；不兼容则保留数据并向前修复。

旧回执只读提取、保留原件，转换幂等。设备更新结果与会话执行资格分别处理；新记录明确退出范围，旧程序不得覆盖丢字段。普通运行不再因为任一历史 partial 文件直接在启动前全局退出；真实 writer 争用与当前未决投递仍不放松。

## 12 界面删除与呈现

1. 先实现统一退休与活动分类，替换 GC 和 Stop 的重复逻辑；用隔离真实进程验证两类 server、MCP、Node 与登记组终止。

4. 同一交付删除旧页面和入口，更新原生交互测试及操作文档；不因删 UI 删除未完成清理记录。
5. 验证通过后再经明确的设备更新动作在本机、MBP at Work、MBA at Home 迁移验收，不用研究期间会话试杀生产环境。

必验：GC 活动重检与后台保护；业务闲置但 MCP／Node 存活可更新；Stop 取消 ACK 后原请求仍未结束；初始化迟到创建；归档回收失败不丢历史；已退出 PID 与复用；正常清理和强制分支；两个客户端同操作；准备失败旧版继续；drain 前退出不能误报；候选超时与一次回退；selected／applied 持久化失败；旧 partial／缺失字段迁移；断连不重发；尾部输出先入库；系统授权／磁盘错误有真实下一步；Tailnet、SSH 和独立会话不被扩大终止。

不要求证明所有未登记后代都被回收，不扩展测试成完整 OS 后代追踪项目。测试、签名包与三台真实验收分开报告；界面截图、HTTP 200 或仅版本输出不能代替进程与数据证据。
