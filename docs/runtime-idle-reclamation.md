# 空闲会话运行时回收

默认连续空闲约 10 分钟后回收，owning worker 每 5 秒核对一次。空闲窗口从 worker 首次同时确认会话记录与托管进程均空闲时开始；会话或队列修订变化会重新计时。只读查看、切换会话和 GUI／SSH 连接断开不重置这个窗口，worker 重启后的新运行时重新计时。

只处理声明可接续原会话、具备完整托管执行覆盖的运行时。共享 Agent 目录服务不参与会话回收。运行／未知轮次、未确认消息、待处理问题／授权、子 Agent、后台任务、非空队列（含暂停队列）、历史修改／分叉准备及未完成压缩均阻止回收。来源或能力无法证明时保留运行时；旧协议和其他 harness 不会被猜测为可回收。

数据库检查不分页读取历史，而是按 SessionID 查询全部相关状态，避免漏掉首屏之外的请求、轮次或后台任务。会话和队列分别保留修订基线，短暂活动即使完整发生在两次检查之间，也会打断空闲计时。操作、子执行投递和活跃历史操作使用匹配索引，查询计划回归阻止定时检查退化为全局历史扫描；只新增兼容索引，不改变数据库版本或已存内容。

每次空闲观察复用 `managedexec.Scope.FenceIfIdle` 核对真实进程归属与生命周期，随后恢复准入；因此未上报到会话的命令也会重新计时。到达期限时保留该 fence，在与提交／队列／历史操作共用的 dispatch 锁下复核数据库，再通过现有托管清理关闭运行时并验证后代已停止。逐会话释放调度锁，不把整批关闭串成一个大临界区。清理失败保留归属证据，进入已有执行核对流程，不假定停止成功。

正常回收不生成消息或完成通知，不修改 SessionID、源历史引用、正文、标题、配置、附件、队列或客户端草稿。清除的只是已停止运行时及其绑定缓存；下一次已接纳输入经已有 adapter 的 Resume 继续原历史，不创建新会话、不重发旧输入。界面沿用既有正在准备／进行中与发送动画，不增加睡眠提示条。

验证包含中立 driver 的十分钟前后边界、短暂活动与队列编辑后的重新计时、忙碌／未知／待请求／暂停队列／历史准备与未确认启动、迟到丢失事件隔离，以及发送与关闭并发。真实固定版本 Codex App Server 与执行器使用隔离本地确定性 provider，确认操作系统进程退出、托管后代全部停止、历史与源 ThreadID 保留并成功接纳下一条输入；另一项真实进程测试覆盖会话未上报的后台进程。仅加速 worker 的测试时钟，不使用用户凭据或付费模型。

验证结果：全量 `go test ./...`、聚焦 `go test -race ./internal/worker -run '^TestIdleRuntime' -count=1`、`go vet ./...`、查询计划回归、设计冻结与第三方声明校验通过；开发版构建和签名校验通过。架构审查提出的历史扫描问题已修复，安全审查无发现。测试使用的临时服务和进程已退出，本轮没有启动预览服务。
