# 空闲会话运行时回收

默认连续空闲 20 分钟后回收，owning worker 每 30 秒核对一次。空闲窗口从 worker 首次确认会话业务状态空闲开始；会话或队列修订变化会重新计时。只读查看、切换会话和 GUI／SSH 连接断开不重置窗口，worker 重启后的新运行时重新计时。

只处理声明可接续原会话、具备完整托管执行覆盖的运行时。共享 Agent 目录服务不参与会话回收。运行／未知轮次、未确认输入、待处理问题／授权、活跃子 Agent、运行中的后台任务、非空队列（含暂停队列）、历史修改／分叉准备及未完成压缩均阻止回收。原生 background 工作已处于 waiting 时，采用 24 小时空闲保护期；它仍阻止普通业务停止接纳，但 GC 可在保护期后按准确实例回收。来源或能力无法证明时保留运行时。

数据库按 SessionID 查询全部相关状态，不分页读取历史。会话和队列分别保留修订基线，短暂活动即使完整发生在两次检查之间，也会打断空闲计时。操作、子执行投递和活跃历史操作使用索引，避免定时检查退化为全局历史扫描。

按 Lody 机制，健康常驻 MCP、Node 内核和其他受管进程是回收对象，不因仍然存活而否决业务空闲。GC 不再逐轮调用 FenceIfIdle 或扫描后代作为空闲门槛。在与提交／队列／历史操作共用的 dispatch 边界复核业务状态后，通过已有准确代次清理流程关闭 runtime、终结受管组并核对退出；物理等待期间释放全局调度锁。失败时分离旧实例、保留原生调用和物理清理的所有权，后台重试，不把旧实例挂在后继实例上。

已退休实例的 WorkActivity 用 worker 自有 retired 标记释放执行所有权：准确代次停止得到证明后，旧活动投影才写 stopped；未能证明停止时保留 unknown。失败分离和 worker 重启后，这些旧记录不再持续否决后继实例的 GC。当前实例的 unknown 仍受保护；真实的新 active 观察会重新取得所有权。旧历史记录和未确定的执行结果不会被改写成执行成功。

正常回收不生成完成通知，不修改 SessionID、源历史引用、正文、标题、配置、附件、队列或客户端草稿。清除的是旧运行时及其绑定缓存；下一次已接纳输入经 adapter Resume 继续原历史，不创建新会话、不重发旧输入。界面沿用已有准备／进行中与发送动画，不增加强制关闭或睡眠页面。

归档先持久化意图并暂停队列，再由 owning worker 退休会话资源。永久删除先落墓碑，旧 runtime 迟到退出按墓碑幂等收尾，完整 gate 退休会释放逻辑派发等待和配置锁；物理清理继续由后台持有。自建 worktree 仍沿用备份、共享使用者检查和延迟重试流程。关闭后台服务采用可撤销的新启动暂停，再核对真实业务；闲置常驻进程交给正常退出处理，已知反注册不可用会恢复原实例准入。

本轮验证覆盖 20 分钟／30 秒与 24 小时边界、短暂活动、队列与历史准备、旧失败代次、后继 GC、删除迟到事件、真实 Node 父子组和已签名 worker 私有控制重试。测试使用隔离状态与本地确定性 provider，不使用用户凭据或付费模型。各轮的原始成功、失败和适用源码见同主题验证报告；三台正式设备未部署，不能据此保证所有未来故障都不阻塞。
