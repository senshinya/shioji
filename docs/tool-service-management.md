# Device-owned tool services

MCP services are read from the selected harness's effective configuration on the owning device. Shioji displays their real discovery/authentication state and provides explicit browser authorization and refresh/retry. It does not create a parallel MCP configuration or credential store.

The neutral contract describes tool-service identities, names, readiness, tool counts, authentication availability and transient authorization attempts. Concrete method names, wire payloads, source login IDs and OAuth handling stay inside the adapter. Service IDs are opaque and scoped to the harness/runtime. Devices without this capability or older workers do not expose active controls.

Selecting an Agent replaces the device detail with its full configuration page, sliding in from the right; Back slides the configuration out to the right and restores the device page. The device collection remains stationary. Configuration is not an indented disclosure, and returning preserves the current Agent's unsaved draft. The page uses General, Models, Skills, MCP, Advanced tabs, with MCP available only when the harness reports support. First-run and add-device configuration do not expose MCP management. The list occupies the available tab height and scrolls internally; it no longer has the model list's 3.5-row limit. Opening it loads current services without clearing previous rows while refreshing. Eligibility and cached results follow the accepted runtime configuration rather than staged editor values. Rows retain the shared 40-DIP height, 13px names, 12px statuses, baseline symbols and 28-DIP actions. Tabs and the list/editor pages slide horizontally with no opacity transition; the shared selection marker moves. Editor actions stay outside the scrolling fields. Loading captions retain the same spinner clock; Reduce Motion is respected.

Protocol minor 24 adds native configuration management: command/HTTP services, literal argument rows, environment variables, inherited variables, working directory, HTTP headers, token environment reference and startup timeout. Service name edits rename the native entry atomically. Add/edit, enable/disable, delete and explicit refresh run on the owning worker, selected by opaque harness/service identities. Configuration writes and authorization starts are serialized; an active authorization blocks edits. The UI never retries an unconfirmed write automatically and keeps the editor available for inspection. Discovery after a confirmed write adopts native reload behavior without stopping running turns; connection failure does not undo saved configuration.

The Codex adapter reads native configuration layers and writes only the user configuration via an atomic, version-checked batch write. An opaque catalog revision rejects stale editors; the native file version closes the read/write race. Other layers and profile-controlled entries are read-only. Existing unexposed fields survive edits, including renaming; unrelated settings are untouched. Environment/header values return only a retained marker, and unchanged markers resolve inside the adapter against that revision. Raw config, native key paths and secrets never enter the neutral read contract. HTTP addresses containing private URL parameters are shown sanitized and remain read-only; no parser guesses which query values are secret. Unsupported native runtime/schema capabilities do not expose writable controls.

Authorization is an explicit worker-owned, bounded operation, independent of GUI/SSH lifetime. Duplicate starts reuse a stable operation ID, lost replies are queried rather than resent, and completion is matched to the concrete source login ID. Authorization URLs/callbacks remain transient and never enter saved client state or journals. Remote loopback callbacks and loopback authorization providers use the existing controller-owned SSH forwarding mechanism before exposing the browser action. HTTPS is required except for an explicitly local loopback provider. Credentials remain on the execution device. No native cancellation operation is assumed; authorization expires under the source timeout instead of pretending that hiding a panel cancels it.

A successful authorization is followed by fresh service discovery. It does not prove a server is connected merely because credentials exist. Native global inventory does not always report live thread connection state: nonempty successfully discovered tools can be shown as available even if optional OAuth has not been completed; a missing runtime state and empty inventory remain unverified. Disabled services stay disabled. Source errors become safe user-facing status rather than raw diagnostic payloads.

Codex implements discovery via its MCP status API and authorization via its MCP OAuth API. Refresh uses its supported configuration reload; already-loaded native threads adopt reloaded MCP configuration at their next active turn. Independent Shioji session runtimes retain their process ownership and running turns are never stopped for management refresh. The UI calls this Refresh/Retry, not an immediate reconnection guarantee.

Validation uses isolated native configuration, local fixture MCP servers and controlled OAuth endpoints. No real account authorization, user configuration edits or MBA enrollment are required by tests. Native light/dark screenshots identify fixtures explicitly and are shown on a LAN-only acceptance page.

Implementation validation: isolated native HTTP MCP discovery and full OAuth callback/token exchange pass against installed Codex. Fresh review found and fixed optional-reload handling and accepted-configuration identity. LAN acceptance screenshots use native layout fixtures; remote SSH forwarding has automated failure/safety coverage, without changing MBA credentials.

## Workspace sources and existing sessions

Protocol minor 26 adds `runtime.tools.inspect`, a read-only operation separate from device discovery/reload and authorization. Workspace settings shows General / Skills / MCP. Project and inherited sources are grouped by actual configuration file. Project files stay read-only; inherited user entries navigate to the existing device Agent MCP page. Return preserves the workspace draft, directory/session scope, query, selected source and reading positions and re-reads configuration. Welcome and add-device flows remain unchanged.

The owning worker resolves only saved workspace folders; a selected session uses its accepted directory and opaque source reference. A client cannot supply a native thread reference or override session directories. Reads do not create/resume a session or reload services. Only a matching existing runtime may report connection state. Missing runtimes, unsupported scoped APIs, stale callbacks and disconnections never substitute device-level discovery for a session observation. Configuration presence, configured enablement, and actual session adoption are distinct.

The Codex adapter reads effective configuration plus native source layers using the selected directory. Disabled project layers remain identified with their reason. Environment/header values are retained markers and private URL parameters are removed. When the installed native schema offers thread-scoped inventory it is used explicitly, including pagination and tool descriptions. Unknown observations remain unknown. The new shared request and response contain only Shioji concepts; native file layout, trust policy, method names and field encoding stay in the adapter.

Native list/detail and inherited-management navigation reuse the existing horizontal panel transition and tab marker. Status notices animate actual height; refresh keeps a stable rotating indicator. The footer, source labels and action glyph slots share the header's right edge. The supported native minimum remains 850 × 600; design-preview phone boards do not expand platform support.
