# 执行环境强制恢复实现与验收

2026-11-16。实现依据为 [已确认设计](ryugi/specs/2026-11-16-worker-force-recovery-design.md)。用户已在对话中确认验收，并授权 commit / push。实现与验证已完成；本轮未部署到现场设备，未关闭原有用户会话。

## 待核对如何恢复

1. 关闭运行环境后，worker 自动核对实际退出及旧轮投递。属于已证明退出代次的轮次可标为已中断，不能标为成功。
2. 源历史仍显示旧轮运行时，保留“结束旧轮记录…”入口。用户确认后将未确认的本地旧轮记录结束为 abandoned；文件不回滚，历史、附件与草稿保留，待发队列保持暂停。
3. 来源支持恢复时，可以在原会话继续；原线程不可用时保留在新会话整理接续草稿的路径。恢复操作不自动续答、不重放未知输入、不自动发送队列。

## 已实现的控制

- 设备详情的执行服务“更多”菜单、环境处理页，以及会话菜单均可进入恢复。正在运行、归属不完整和未登记进程不再只剩导出诊断。
- 可直接强制关闭所选环境，不必先等待正常关闭超时。确认范围及风险后才发送；其他进程支持按名称/PID 搜索和逐项选择，SSH 控制链及独立 Tailnet 服务受保护。
- 旧版或卡死 worker 通过签名恢复程序的独立模式处理，不依赖旧 RPC。使用准确 PID、开始时间、UID 及设备侧观察，不按名称批量终止。
- 流式正文和用量事件不使关闭确认失效；新输入、轮次、线程或运行代次改变则要求重新确认。已知环境中的后代与单独选中的未知 PID 分开授权。
- 操作在设备侧持久化，回执未知时只查询原操作；恢复的保留记录覆盖新服务启动与握手全过程，避免第二个客户端同时接纳恢复。
- 单独恢复固定原签名构建并核对实际服务注册实例。失败重试保留原构建、原 plist 与暂挂状态；改用当前应用构建需要单独勾选。取消先前的自动更新意图，设备恢复不顺便升级。
- 关闭证明绑定旧运行代次，供启动后的自动核对使用；不能释放新代次的执行保护。

## 实施取舍

- 恢复使用现有脱离连接、持久化日志的 runner，而非新建每操作 launchd 注册；runner 崩溃显示部分结果，需要用户发起新动作。
- 原构建恢复使用兼容 SQL 隔离，不为了恢复旧版而运行新版数据库迁移；原构建不可验证时需明确选择替换版本。
- 代码审查与完整验证并行执行，审查修正后重新运行检查。
- 目录无法读取时，确认明确说明将覆盖设备全部执行环境；用户接受后可能中断无法列出的任务。目录可读时，新任务/轮次/代次变化必须重新确认。
