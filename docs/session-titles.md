# 自动会话命名

新会话接纳首条输入时，同一事务保存临时名称和独立命名任务。所属 worker 的后台消费者执行任务，与普通回复、输入队列、GUI 和连接生命周期分离。任务阶段为 `pending → running → completed / failed`，保存在 schema 7 的 `title_jobs` 中；重连不创建新任务，重启保留未启动任务，将已启动但结果未知的任务置为失败，不重放模型请求。已有会话不会批量补命名。

中立契约只有可选的 `harness.TitleGenerator` 和 `TitleInput`，不含模型家族、具体协议或命令参数。具体 harness 的命名策略、认证及隔离执行由适配器负责，不支持此能力的适配器保留临时名称。

Codex 从自身 `model/list` 返回的非隐藏目录中选择 Luna：优先目录标记为默认的 Luna，否则取目录顺序中的首个 Luna；支持 low 时使用 low，不改变正常会话的模型、推理或权限。无 Luna、请求失败或结果无效时保留临时名称，不暗中改用其他模型。目录存在不等于账号调用已成功，模型拒绝同样按失败处理。

命名使用独立的 `codex exec --ephemeral`，在临时工作目录中以只读沙箱运行。保留原有 Codex provider、认证和全局用户指令，不修改用户配置；对子进程禁用 hooks、插件、Apps、MCP、宿主回调、项目指令发现及执行类工具。命名材料最多 4,000 个 Unicode 字符，只取用户原文；仅附件／引用输入使用接纳时的名称作为描述，不推断未读取的图片内容。输出采用单字段 JSON schema，标题限制为单行、80 字符，提示词要求 40 字符以内。

辅助进程使用单独的受管执行目录，正常完成、超时及 worker 退出均清理其进程组并退休内存记录。启动时只隔离清理失败的旧命名 scope，继续处理其他会话，错误留诊断。命名请求总时限为 60 秒；失败不改变会话执行状态，也不生成聊天消息、工具项或完成通知。

结果写入前重新核对标题修订号、手动覆盖、已有源标题和首条输入身份／正文，避免迟到结果覆盖手动命名、原生标题或历史修改。写入后的名称通过既有事件日志同步到会话列表、顶栏与搜索。侧栏和顶栏文字用 160ms 原位交叉淡化，不改变原有字体、基线、行高或容器尺寸。

验证包括：真实固定版 Codex 配合本地确定性模型端点、所属 worker 的端到端自动命名、辅助请求与普通轮次隔离、手动／原生名称优先、历史输入修改、重启去重、异常 scope 隔离、进程记录回收，以及亮暗模式标题动画与输入焦点／草稿／布局保留。没有调用真实付费模型，也没有重启用户正在使用的 worker。原生动画验收宿主只演示真实标题事件的呈现，不冒充一次真实模型生成。

按用户要求补录约 10 秒的亮暗模式标题动画，位于忽略目录 `build/title-recording/web/recordings/title-motion.mp4`。录制采集同一套 Go/MyGo View 的原生渲染帧，通过标题事件展示侧栏／顶栏交叉淡化，不采集其他窗口，也不冒充真实模型命名耗时。局域网验收页使用模块加载前的 UUID v4 兼容补丁；实际 HTTP 地址已验证画面、交互和页面错误记录。

另补录从首页空白开始的完整流程，位于 `build/title-home-recording/web/recordings/title-home.mp4`（约 18.5 秒）。首次发送由正常 controller／worker 接纳，实际 Codex 主轮次与独立命名进程请求本地确定性模型端点，结果经持久化事件更新顶栏和侧栏；没有直接注入标题事件。录制等待源标题实际返回，再保留 3 秒；本地端点的等待时机由验收工具控制，不代表在线模型耗时。

上述两段均为测试夹具录像，不满足用户要求的真实在线对话录屏，不能作为该项验收通过的证据。用户授权 macOS 录屏后，已从独立正式应用的空白首页完成一次真实在线请求：正常回复使用 gpt-6.1-sol / medium，独立命名按实际目录选择 Luna，顶栏与侧栏更新为“通俗解释红黑树左旋右旋”。原始连续窗口录屏位于忽略目录 `build/live-title-recording/real-home.mov`（约 59.5 秒，2480×1640，实际平均约 56 fps），直接采集 ScreenCaptureKit 窗口帧，未使用本地模型端点、重放或注入回复；未更改用户 Codex 配置。用户已验收。
