# 已有会话的导入

欢迎流程在工作区创建成功后提供可跳过的导入步骤。后续入口在工作区的目录菜单与右键菜单。跳过保留首页草稿，不创建空会话；返回工作区后再次继续复用已接纳的工作区，修改则进行 revision 检查的更新。返回并切换设备后重新接纳工作区；并发修改保留当前表单，需明确重新载入后再继续。

协议 minor 32 提供 `conversation.list`、`conversation.preview`、`conversation.import`。查询固定工作区、revision 与 harness；预览和导入还带来源引用与目录。设备 worker 验证目录归属及当前版本，客户端不解析远程路径。目录分页最多 50 项，UI 保留最多 1000 个匹配结果并在内部虚拟列表滚动。

`harness.ConversationReader` 只发现和读取来源，不能绑定、恢复或执行原进程。Codex adapter 使用当前安装协议支持的 `thread/list`、`thread/read`、`thread/turns/list`，过滤并规范化设备上的目录；不自行解析 rollout 文件。原索引可能保留符号链接路径，因此按分页元数据的真实目录核对归属后才返回共享层。

读取最多 50 轮 / 200 项 / 384 KiB 源内容预算；内容不足或超限会给出只读原因。导入后只保存有序历史、原已知模型与来源信息，不激活过去的审批、子工作、后台命令或用量，不补发完成通知。来源引用按工作区与 harness 去重，成功结果原子提交；未知导入结果可安全按同一来源重新查询 / 导入，不重复执行任何模型输入。存储 schema 11 防止旧 worker 把导入记录当作空会话运行。

导入不会立即创建执行进程。原生 `ResumeRef` 是 adapter 生成的不透明历史边界，包含该 adapter 核验前缀所需的信息。用户首次发送时，由可选 `harness.ConversationContinuation` 重新核对前缀并准备独立上下文，worker 持久化新来源后才通过正常受管运行实例接续。Codex 使用已导入的最后完整轮次建立私有 fork，再释放、恢复；不接管外部 CLI 的原线程。来源变化时明确失败，不退化为无历史的新线程。目录、Git、模型和权限仍走现有提交检查。历史导入不声称已接纳来源过去的 Git 分支；首次明确输入时，正常提交检查读取当前所属 checkout，并与输入接纳原子持久化该分支基线，后续照常检测分支变更。

原生界面复用共享表单、Tab、字面度量、滚动和动效组件。列表与预览整体左右滑动 260 ms，筛选与移动选中线同步。底部操作保持固定，进度标签原位更新且不重建旋转时钟。异步结果必须匹配模块实例、设备身份、连接 epoch、工作区 revision 和查询代次；退出或跳过后迟到结果不改变导航。

自动验证覆盖真实 app-server 的发现、预览和前缀准备，真实 worker RPC 的原子去重、外部历史不变与首次续聊，以及原生测试器的筛选、预览、部分重试、跳过、断开和第一行对齐。屏幕验证使用真实原生 View 与 worker / app-server；隔离本地模型夹具仅提供样例内容，不代表真实模型生成行为。

最终独立审查发现并修复首次 Git 续聊、欢迎返回换设备、迟到目录回复改写导入批次三处问题，均有 RED→GREEN 回归。全量 Go 测试、相关包竞态检查、生产构建和冻结稿校验通过；局域网 HTTP 实际渲染、UUID 回退、图像加载及视频回放已检查。真实 SSH 远端、系统输入法组合输入及完整键盘操作仍需人工验收；减少动态效果和状态变化不重启旋转沿用已覆盖的共享控件。
