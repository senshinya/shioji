# 完成回复与待我处理

完成回复仅在本次 App 启动后才进入「待我处理」。启动前已经完成的会话、旧客户端保存的未读记录和历史重放不产生完成提醒；授权与问题保留原来的待处理规则。启动时忽略旧完成不会把其他客户端的提醒标记为已处理。

所属 worker 在会话中持久化最新自然回复的完成记录：独立的完成 ID、历史引用、轮次、实际完成时间和未处理状态。正常执行与断线恢复使用同一条完成判定。压缩、停止和失败不产生完成记录，迟到的用量与重复完成事件不重置已处理状态。历史替换与分叉清除原完成记录。

客户端打开会话时向所属 worker 提交 `session.completion.read`，携带该次完成 ID。worker 原子保存已处理状态并发布会话事件，其他客户端随事件清除提醒；重连快照也携带同一状态。旧回复的确认不会清除新回复，重复确认没有额外副作用。确认失败会恢复本地提醒并显示同步错误。

客户端每次启动维护独立的时间边界，不从客户端状态文件恢复完成提醒。首次快照提供 worker 的时间；客户端在发起请求时取样，换算到该设备的时钟，避免后续 readiness 查询或 UI 队列延迟将启动前的回复纳入。设备时钟不一致时，首次快照请求的传输区间保守排除。后续快照保持原边界，因此可找回本次打开期间断线后完成的回复。

共享确认要求 worker 协议 2.39。旧 worker 仅保留客户端实时完成提醒，需升级 worker 才能同步已处理状态。

验证覆盖客户端重启、旧状态迁移、跨设备路由、时钟差、延迟快照、断线恢复、持久化、重复事件、过期确认、写入失败和两个客户端的实际 RPC / journal 同步。原生录制使用 MyGo 生产组件与确定的 worker 投影夹具，分别检查亮暗模式；不代表两台物理 Mac 的端到端验收。
