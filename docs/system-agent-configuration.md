# System-owned agent configuration

Shioji follows the selected harness configuration on the owning device. Existing account authorization, custom providers, effective configuration homes and profiles remain authoritative. Public account/provider metadata is displayed without credentials. Only an unconfigured runtime offers initial account or API configuration. Existing custom configurations with missing credentials are reported without silently replacing them.

The harness-neutral setup contract carries a public connection summary and an explicit API setup request (endpoint and transient credential). The adapter reads and writes native configuration; Shioji never persists the API credential or a parallel provider configuration. Codex uses config/read with layers and config/batchWrite with the current user layer version; only new native provider fields and model selection are written, preserving unrelated settings. No reload of running sessions is requested. Native configuration owns credential persistence and file permissions.

A missing configuration can be initialized with an HTTPS Responses API endpoint (HTTP permitted only on loopback) and optional API key. Connect fetches the advertised models and chooses a valid default automatically before the native save. Models remain in the independent Models panel. Codex's native direct bearer-token setting is used for this provider, never its ChatGPT credential cache. Empty credentials are supported for local unauthenticated providers. Configured providers, account credentials, managed settings and session overrides prevent this initial setup path from overwriting them. Conflicts require refreshing before retry. Source protocol names and config structure remain inside the Codex adapter.

Refresh rereads effective configuration through a newly started catalog runtime. Existing session runtimes are retained. Setup before saving an SSH device uses the same owning worker path as ordinary device details. Public status/query responses, persisted UI state, operation journals and errors must not contain the credential.

Existing configured Agent account rows remain in place. Configured API providers disclose compact read-only endpoint, model and credential status plus refresh. Unconfigured runtimes offer Account authorization / Custom API segments. Browser/device-code selection stays inside Account with a separate login action. Custom API offers address, key and Connect only. New forms use existing actual-height disclosure animations, native aligned rows and masked credential input. No new navigation or explanatory cards.

API model discovery uses the owning device and the selected provider credentials/headers against its model endpoint. Only advertised IDs enter the selectable catalog; native metadata is retained for matching IDs, without inserting configured names that were not returned. Browser/device account authorization and native helper/OAuth discovery use Codex model/list. Failed/empty API discovery is an unavailable state, not a bundled-model fallback. Confirmed account/configuration remains visible when discovery fails; retry reads models without repeating authorization. Previous models are read-only during refresh or after failure. API credentials in native file/direct keyring storage are read only inside the adapter; no OAuth tokens are used by the HTTP discovery path. Current Codex 0.167 rejects --profile for app-server, so that CLI limitation is not silently bypassed by flattening profiles into another file.

Account model availability is the native runtime's advertised model/list result. Its protocol does not expose whether that result came from a successful online refresh or a native cache. Shioji does not infer verified online freshness from a shared cache timestamp, copy OAuth tokens, or substitute a handwritten catalog. Custom API discovery queries the configured service directly and fails explicitly when it cannot return a model list.
