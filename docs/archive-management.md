# 归档管理

归档由所属 worker 接纳，同时持久化准确运行代次的回收待办、暂停待发队列。后台立即回收 app-server、exec-server 及已登记的 MCP、Node、工具进程；工作区归档覆盖其中会话。退出失败保留所属代次，分离旧实例后重试。恢复与阅读不自动启动环境或续答；未知输入不重发。闲置环境仍按 20 分钟、30 秒扫描回收，正在执行的轮次与真实未决请求不会被当成闲置。

工作区菜单的“已归档…”打开完整归档页。搜索、Tab、列表位置与普通草稿保留。点击会话直接阅读；工作区可以查看其中全部会话，恢复工作区不会恢复其中单独归档的会话。

## 永久删除

确认框只有“取消”和“彻底删除”，不再区分普通与强制删除。确认仍绑定所属设备、稳定对象与 revision；恢复后的对象不能删除。暂停队列、遗留执行状态或退出失败不否决明确的永久删除。worker 先原子删除应用记录、写入防重放墓碑，并把进程与资源清理移交持久化待办，再返回删除回执。慢退出不会拖住回执或持有设备级派发锁。无法确认归属时保留记录并返回警告，不按进程名称或宽泛 PID 列表清扫。

回收待办按条独立重试；某个旧进程、文件或备份失败，不阻止其他会话清理。完成前保留进程身份与所属代次；完成后释放 runtime、idle 与绑定缓存，移除 executions、runtimes 下该会话的登记文件。自动命名使用独立的短任务范围：仍可写入时保留目录，任务结束后再回收 title-executions；删除会话的迟到结果不影响后续命名。

原项目文件、原 Git 仓库、长期凭据及 harness 独立保存的源历史保留。附件、文件引用与 Diff 评论快照只在最后一个应用引用消失后移除；依赖边先落盘，避免中途退出丢失子资源。最小操作墓碑持续拒绝重放已删除输入。

## 自建 worktree

Worker 记录自己创建的 worktree 路径、Git common directory、实际分支与备份提交。归档或删除后，只有全部使用该 worktree 的独立会话／工作区都归档或删除，并且所属运行代次物理退出，才开始回收。独立分叉或将它用作附加目录的会话也计入使用者。一个遗留代次不会挡住其他 worktree。

回收先把 tracked 与未被忽略的 untracked 内容提交到实际分支，再移除 worktree 目录；保留分支，不修改原项目 checkout。备份使用固定归档身份，关闭签名与 hooks。分支被改名时保存实际名称；detached HEAD 先建立保留分支，避免备份失去引用。**与 Lody 一样，Git 忽略的文件不备份**；确认框明确说明此范围。备份、Git 锁、权限或删除失败时保留目录，按 30 秒起、倍增至 1 小时的退避重试，不把未完成清理当成成功。

恢复会话只恢复记录。下一次明确发送、继续、历史修改或重载时，在原路径重建 worktree 并接续原线程；普通查看历史和 Git 状态查询不重建。重建与回收通过该 worktree 的闸门串行，Git 等待不占设备级派发锁；恢复发生在备份中途时，后续输入等待该目录就绪，无关会话仍可接纳。

早期版本的自建 worktree 通过已接纳操作 ID 的路径摘要、已保存执行目录与实际 Git 归属恢复登记。没有创建回执的同名目录不自动接管。所有权记录独立于会话，永久删除与所属已删除会话的关联同事务保存，确保重启后仍能重试备份。数据库 schema 为 15；旧 worker 不获授读取新版数据库。

## 保留期与批量操作

“外观 → 对话 → 归档内容保留”提供 7 天、14 天、30 天和永不，默认 30 天。分别从会话或工作区归档时间计时；阅读不延期，恢复取消该次归档的到期待办，再归档重新计时。所属 worker 启动及每 30 秒检查；到期后采用同一删除意图和后台回收链路，不再被保留的暂停队列永久挡住。

“删除全部”作用于当前会话／工作区 Tab 或已进入的归档工作区，包括搜索未显示项。确认后新到的归档不进入当次批次。各项分别交给所属设备，离线和失败项保留，成功项立即移除，重试只处理失败项。

本轮仅改源码与隔离验证，没有操作本机、MBP at Work、MBA at Home 的正式服务或用户会话。原始重现、最后测试输出、原生删除框截图及验证范围保留在本机 `verify/worker-upgrade-lifecycle`。

## 手动删除与强制删除（2026-11-16 修订）

确认弹窗使用 16 DIP 内边距，直接提供普通删除与“强制删除”，并说明强制删除可能中止任务、无法关闭的进程可能继续运行。普通删除可正常回收已闲置会话的运行环境，不再仅因 Codex 配置包含 hooks/plugins 永久拒绝；自动过期清理仍沿用原来的闲置与完整托管覆盖检查，不获授关闭未知活动的许可。

强制删除允许越过执行状态、覆盖证明与持续变化的内容 revision，仍在所属设备确认对象存在且当前仍属于归档。恢复后的对象不进入删除范围。所属 worker 先原子删除记录、保留最小操作墓碑，再按捕获的进程身份结束该会话环境；不按进程名称清扫。无法确认或结束的环境不会阻止记录删除，回执返回警告，持久化清理待办及进程归属记录继续保留。清理完成后先释放该 generation 的内存监控，再移除执行记录；残余清理不会重建会话或阻止 worker 启动。

归档列表提供“删除全部”，作用于当前会话／工作区 Tab 或已进入的归档工作区，包含搜索未显示的该范围内容。确认绑定当时的对象集合；确认后新到的归档不进入本次批次。各项分别交给所属设备，离线与失败项保留，成功项立即移除；重试只处理失败项。归档工作区删除包含其保留会话。项目文件与 Git 仓库不受影响。

本机只读抽查：67 条归档中检查最近 8 条及较早位置的 4 条，12 条均通过数据库闲置检查，9 条被当时运行的 worker 诊断为存在脱离进程，3 条未报告该阻塞。截图会话还保留 `node_repl`、`codex-code-mode-host` 等运行环境进程。这是状态／进程条件核对，没有对用户数据发起实际删除或停止进程，也不把诊断无阻塞视作实际删除成功。

修订验证：`go test ./cmd/... ./internal/...` 全部通过（UI 309.483 秒、worker 138.756 秒）；归档专项、强制删除／批量删除相关 race、相关包 vet、命令构建及 6 个冻结设计文件校验通过。根目录 `go test ./...` 曾因忽略目录 `build/worker-recovery-20261116` 中多个独立探针的 `main` / `ident` 重名而失败，未改动这些其他任务的本地探针；首轮新增测试缺少 Work 元数据的夹具错误已修正并由上述完整源码回归覆盖。

原生证据保存在本机 `artboard/verify-archive-deletion`，包含修改前后、批量确认、直接强制入口、深色窄窗口及 45 秒原速确认／取消录像。局域网 HTTP 页面与嵌入画板实际打开，媒体完整播放至结束，暂停／跳转可用；Chrome 控制台为 0 条消息。没有以这些隔离 UI 证据宣称已对用户会话执行删除。原生验收时源码尚未提交，未替换现有 App 或重启其 worker；后续合入以 Git 记录为准。

合入前独立审查补充了删除提交与停止接纳之间的崩溃回归：真实所属进程拒绝正常退出，数据库已提交删除但停止尚未接纳，然后重新打开 owning worker。清理只凭该 SessionID 的已提交删除墓碑与该 generation 原有的操作、进程身份和强制许可，恢复同一停止操作的接纳；启动时的 worker 更新恢复不得撤销归档清理的既有许可。普通关闭的预备记录不会被自动接纳或升级为强制关闭。

设备策略有独立 revision。明确修改设置会持久化对已知设备的同步意图，离线时等待重连；正常重连不覆盖其他客户端的新策略。冲突与保存失败在设置窗口显示，需要重新选择。新设备未改过的默认策略可以继承当前偏好。
