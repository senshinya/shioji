# 归档管理

工作区菜单的“已归档…”打开完整归档页。会话只显示标题与 Workspace，工作区显示名称与所属设备；搜索不受原侧栏历史条数限制。点击会话直接阅读，返回保留查询、Tab 与列表位置。工作区可以进入查看全部保留会话，恢复工作区不会恢复其中单独归档的会话。

恢复与彻底删除由所属设备处理。删除确认绑定稳定对象 ID 与 revision；工作区删除包含其中全部会话。离线项保留缓存并禁用写操作。删除只移除 Shioji 的记录与自有附件、引用资源，不删除项目文件、Git 仓库、凭据或 harness 独立保存的源历史。最小操作墓碑仍用于防止未知输入重放。

“外观 → 对话 → 归档内容保留”提供 7 天、14 天、30 天和永不，默认 30 天。分别从会话或工作区的归档时间计时，阅读不延期，恢复后取消该对象的清理，再归档重新计时。旧归档没有时间时从升级首次补记起算。缩短保留期适用于已有归档。

所属 worker 在启动时及每分钟检查到期归档，不依赖客户端窗口或连接。清理先核对活动轮、请求、队列、历史操作、子任务与真实托管进程，不为清理停止任务；工作区包含任何未闲置会话时整组保留。数据库删除原子执行，资源清理由持久化待办重试，事件序列保持连续。

存活运行时缺少完整托管覆盖证明时拒绝删除并等待核对。自动命名的迟到结果不会阻止后续会话命名。Diff 评论删除前持久化其源快照依赖，保留其他评论或会话仍引用的资源，最后一个引用移除后回收快照及保留标记。

设备策略有独立 revision。明确修改设置会持久化对已知设备的同步意图，离线时等待重连；正常重连不覆盖其他客户端的新策略。冲突与保存失败在设置窗口显示，需要重新选择。新设备未改过的默认策略可以继承当前偏好。
