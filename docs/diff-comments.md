# Diff 比较与精确评论

右栏的基准、目标选择器共用于文件列表与文件详情。默认比较 HEAD 和工作目录，也支持本地分支、已获取的远程分支之间的 tip 对 tip 比较及交换方向。所有读取在工作区所属 worker、会话已接纳的仓库执行，不进行 checkout、fetch、stash 或其他 Git 修改。

worker 将分支解析为固定提交，文件列表与正文使用同一组版本。切换时保留原内容，等新比较与当前文件一起返回后更新；迟到结果不会覆盖新选择。当前文件不在新比较的更改列表时，保留文件名、返回入口并显示无差异状态。分支名称互换独立于固定控件，使用 260 ms EaseOut 动画；减少动态效果时立即更新。

在 Diff 中选择部分文本或跨行文本，松手后显示评论按钮；点击才展开原位评论框。选区保留每个片段的来源侧、原始 UTF-8 字节范围与行号，支持删除文本和 CRLF。原生复制与评论选中文字一致，不扩展为整行，也不附加周边代码。

“加入消息”插入普通 composer 的原生行内标签。评论是现有不可变资源系统的具体 `diff-comment` 类型，复用引用位置、草稿、队列、Steer、历史修改与分叉的完整链路。完整的两侧文件作为独立 `diff-snapshot` 资源，仅用于恢复界面；适配器只收到明确类型的评论内容、所选片段与当前执行分支，不能把完整快照当文件附件发送给模型。上传入口拒绝伪造这些 worker 内部资源类型。

模型输入写明基准与目标分支/提交、选中侧、文件行号及列、精确选中文字、评论和实际执行分支。工作目录还记录基于的提交与文件快照身份。执行分支不因比较选择而改变。最多 8 条评论，评论与普通文件分别计数；普通文字与评论输入共同受文本大小限制。

打开的评论编辑器保留其原始文件快照；切换比较或文件再返回不会把草稿挂到更新后的代码上。已有引用独立于后续刷新；点击它从所属 worker 下载已保存快照，恢复原比较并平滑定位。当前工作目录已变化时，旧评论不会按最新文件的同一行号定位。

协议 minor 33 增加 `git.compare`、`git.refs`、`diff.comment` 与比较文件快照。旧 worker 保持原 HEAD/工作目录只读 Diff，不显示可提交的精确评论入口；客户端拒绝将新评论资源发送给不理解它的旧服务。

原生选区扩展在 MyGo 的 Diff 组件内；产品继续使用 Go / MyGo 原生绘制，无 HTML 或 WebView 替代。实际 Git 与 worker RPC、原生窗口截图采用隔离测试仓库；静态示例对话不代表一次真实模型回复。

被动预览按工作区最多保留 64 份、总计 32 MiB 的未引用快照。开始评论时通过 `diff.snapshot.retain` 明确保留原版本，已创建的评论也保留其来源；这与现有不可变附件输入一致，取消后由用户的原件清理操作回收，不会因另一客户端仍在编辑而删除。混合 LF/CRLF 按原始文本映射字节边界，定位引用保留全部离散片段，展开折叠上下文不扩大选中文字。只读 Diff 不显示编辑插入光标，已评论行高度为 32 DIP。

验证覆盖本机与真实 SSH worker 的固定版本读取、局部文本评论和 checkout 不变；远端测试使用独立临时目录，结束后关闭服务并清理。原生截图覆盖亮暗模式、评论插入、分支交换与当前文件无差异。评论图标以共同路径在 13/14/16 DIP、1×/2× 下检查顶部留白；有差异内容退出时保留旧渲染器直至动画结束，避免空状态切换重置仍在绘制的对象。
