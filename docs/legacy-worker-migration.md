# 旧版执行服务的应用内迁移方案

状态：方案，尚未实现。目标是让首次连接和普通重连可以在应用内完成旧服务迁移，保留已完成的 SSH 认证与设备原有数据。

## 两条更新路径

支持现有安全更新接口的 worker 继续使用现有空闲准入、执行隔离、SQLite 备份与进程替换流程。忙碌时等待，不停止任务。

已确认的旧协议 v1 服务没有这个接口。应用不能把只读快照中的“已完成”解释为已经封闭所有新任务入口。此类服务提供一次明确的“停止旧版并升级”操作，由用户授权停止旧服务；不再要求用户查找 PID 或登录远端终端。已知有任务时默认等待；状态不完整时说明停止可能中断旧任务，不能冒充安全空闲更新。

未知协议、无法验证的设备或进程不能沿用这一迁移入口。支持范围以实际验证过的旧协议和数据格式为准。

## 用户看到的流程

SSH 认证成功后保留地址、名称、端口与当前步骤，进入服务准备。

- 正常新版本：直接进入 Agent 配置。
- 支持安全更新：显示“正在更新服务”，完成后继续。
- 不支持安全更新的旧版本：显示“需要更新设备服务”和“停止旧版并升级”操作。这里的确认授权停止旧服务，不宣称已经证明设备完全空闲。
- 已知仍在工作：显示等待状态，不默认停止任务。

旧版迁移的进度依次为停止旧服务、备份数据、启动新版、核对设备。完成后进入 Agent 配置，不重新询问 SSH 密码。每个阶段复用现有行内状态和文字过渡；内容变化使用实际高度动画，后续步骤沿现有左右滑动进入，尊重减少动态效果。

## 迁移边界

迁移由运行在目标设备上的签名 Shioji helper 完成，本机与 SSH 共用同一实现。控制端只发起操作和查询进度，不解析远端数据库、不停止控制 Mac 上的同名进程。

1. 先核验候选二进制签名、摘要、协议及数据库兼容性。保留源 DeviceID、私有目录、已确认的源服务身份和本次操作 ID。
2. 通过所属设备的 Unix socket 与操作系统身份确认旧 owner；核对当前用户、进程启动时间和目录。正常停止仅限该次明确授权的旧 owner，不按进程名批量停止，也不自动使用 SIGKILL。
3. 等待旧服务退出并取得同一目录的独占 owner 锁。旧服务未退出、身份变化或其他进程抢先成为 owner 时中止接管，重新核对状态。
4. 持有独占权后，生成包含 WAL 的一致 SQLite 备份，再进行数据迁移。所有设备、工作区、会话 ID 保持不变；不改 Agent 账号与 SSH 密钥。
5. 将独占权交接给新版 worker，在新服务完成身份和目录验证前不允许它派发新任务。遗留队列先暂停；无法确认的旧执行保留待核对状态，不自动重放输入、不伪造完成。
6. 验证原 DeviceID、目录及会话目录后回到初始化或正常连接。全过程不创建替代的空数据库。

首次操作产生稳定标识。断线后查询同一次迁移的阶段，不重复提交停止动作；GUI 退出不应使迁移失去记录。停止失败保留旧现场；新版启动失败保留备份和明确恢复入口。数据库已经迁移后，不让旧二进制直接读取新数据库，也不无条件回写旧备份覆盖新状态。

现有 `docs/local-worker-updates.md` 中“旧版不支持安全更新时手动重启”的限制由这一明确授权的迁移入口承接；正常安全更新仍维持 worker 自己的原子准入。

## 实现前必须证明的事项

用隔离的真实旧 worker 验证 owner 身份与正常停止、WAL 备份、锁交接以及新版本恢复；用并发客户端覆盖停止前后提交的竞态，明确区分已接纳、未接纳与无法确认的输入。另覆盖任务忙碌、未知执行、PID 重用、重复点击、SSH 断开、停止超时及新服务启动失败。

通过这些检查后再用于 MBA。真实迁移必须验证既有会话保留，不能用模拟成功回执代替。

## 实现与验证（2026-11-09）

当前自动迁移范围为已实际运行验证的协议 1.3；其他旧协议仅报告状态，不提供停止迁移。现代服务仍走既有安全更新准入。

- 迁移 helper 在设备端保存稳定操作记录和不跨 IPC 的临时启动环境。连接中断、重开客户端仅查询同一操作；失败后显式继续沿用原备份，不重复发出停止信号。
- 普通 worker（包括已经等锁的后台服务）取得 owner 锁后、打开数据库前再次检查迁移记录，避免绕过未完成的备份／核对。初始化与设备详情共用进度；独立客户端可从未连接设备的“检查服务”发现其他客户端留下的迁移。
- 隔离的历史源码 `16018d4` 编译为真实 1.3 worker，执行了正常停止与新版接管；核对原 DeviceID、工作区、会话、消息、含 WAL 备份及暂停队列，未确认的旧接纳恢复为 indeterminate，没有重发输入。
- 原生界面同时验证了真实旧服务迁移前后，以及 MBA 上只读诊断得到的明确升级入口。随后按用户明确指令，在原生实例中点击 MBA 的“停止旧版并升级”。迁移完成并进入 Agent 配置，原 DeviceID、工作区、会话及 14 条消息逐项保留，备份已生成，未重发输入。

验证记录与原生截图存于忽略的本地验收目录，不纳入 Git；全量 Go 测试、针对性 race、vet、签名构建及设计冻结检查分别保留执行结果。
