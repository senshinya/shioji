## 实际边界处理

历史操作先保存 intent，再保存新的源 ThreadID，最后原子替换本地投影并接纳一条新输入。相同操作 ID 不重复分叉或发送；断线与重启只查询。已保存 fork 可用原 ID 显式继续完成，也可取消尚未本地提交的操作；已接纳输入不会因取消查询被撤回。worker 重启将未确认 prepared intent 标为失败，原会话保持不变。

每次实际提交（包括 forked 恢复）都重新做目录、Git、配置与附件检查。分叉创建端设置零卸载延迟、unsubscribe，并确认线程已卸载，再交给目标会话的独立 runtime 和 executor；不会沿用源会话的进程控制身份。原会话切换线程时，历史事务与 normalizer 解绑在事件锁内完成，旧线程迟到事件不能复活后缀。

投影按 worker 拥有的轮次顺序与归属保留，而不是按消息落盘位置截断；因此前轮迟到工具输出仍保留。历史替换事件同步清理 items / turns / requests / plan，多客户端和跨页补放使用同一边界。发送待确认时历史编辑区只读；实际 operation confirmed 回执恢复普通草稿，不依赖普通 Pending 提交表。

协议为 Major 2 / minor 9，数据库 schema 6。旧客户端无法解释权威历史替换，因此拒绝旧协议连接；新功能需要匹配的客户端和 worker。本轮只运行隔离验收 worker，未升级或停止原有用户 worker、连接、账号或设备。

## 分叉时的临时恢复提示闪动

原生逐帧记录复现：点击分叉后约 0.25–0.35 秒，普通在途请求被错误显示为“会话操作结果待核对”；输入框 Y 从 706 变为 670，再回到 706，跳动 36px。原因是操作标识在网络请求前持久化，而恢复提示只排除了历史重开的动画，没有排除分叉的动画及在途请求。

分叉沿用相同的显示边界，正常退场及请求处理中不插入恢复提示。断线或结果不明后仍展示核对／取消动作，不给正常分叉添加占位空间或额外动画。新增回归先观察到 36px 位移失败，再验证正常在途时布局不变、连接错误后恢复动作仍可用。

修复后原生采样未再出现该提示，输入框 Y 始终为 706；分叉回复即时及历史加载后锚点偏移均为 0px。新亮色视频为 14 秒／60fps／840 帧、队列零丢帧、无插帧；保留修复前真实视频并排。全量测试、vet、冻结稿与开发包构建通过，仍待人工视觉验收。
