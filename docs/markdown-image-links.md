# Markdown 图片入口

截图中的灰色矩形来自正文的 `![替代文字](设备路径)`，不是工具附件，也不是模型生成的按钮。对话没有设置 `LoadImage`，MyGo 原先只显示替代文字；独立图片和混排图片都没有把点击交给文件链接处理器。原 PNG 仍然存在。

正文现在自动显示与工具图片相同的原生缩略图，复用 `outputImageCard` 的 224 px 宽、80–180 px 高、加载／失败／重试、实际高度动画和缩略图放大行为。独立图片直接显示；混排正文保留原生文字、链接和选区，在该段下方显示图片。MyGo 的窄 `Options.Image` 回调接纳已完成的图片地址，不替换普通 Markdown、代码块或 Mermaid 渲染。未完成的流式地址不会发起读取。

图片地址仍经所属 worker 的文件链接链路校验；设备路径不会在控制 Mac 直接打开，也不自动请求外部 HTTP 图片。下载副本按已有摘要验证，缓存最多保留 32 个 512 px 缩略图、两个并行传输；仍可见的图片不因达到上限而反复重读。仅打开查看器时解码大图。会话、连接、已接纳目录变化、关闭副窗口或退出会取消旧任务，迟到结果不能填入新会话。普通草稿与焦点不随加载改变。尚未安装到正式 App。

`internal/ui/markdown_images_test.go` 覆盖亮暗模式、独立与混排图片在点击前真实绘制图片像素，经隔离 worker 读取、缩略图放大、失败后重试、草稿／焦点、会话与副窗口生命周期、缓存上限，以及流式地址从未完成到完成的交接。排队等待不消耗单次传输的超时；虚拟时间回归覆盖等候超过两分钟后仍能进入可重试结果，取消时同时释放旧缓存。测试先复现缺失行为，再验证修复。提交内容在隔离工作树通过完整 Go 回归；最终专项 race、UI vet、协议录制、设计冻结及敏感信息检查通过。

验收使用真实 macOS MyGo 窗口、截图中的原始 PNG 和隔离 worker；会话为夹具，未调用模型。亮暗各一段 7.5 秒录像，覆盖图片自动展示、两张图片、混排图片的放大与关闭。局域网页面完整播放、暂停、跳转、HTTP UUID v4 补丁及错误检查通过，画板检查为 CLEAN。冻结设计的 6 份仓库文件保持一致。仓库裁剪了 MyGo examples，使用已有 counter-native／hello 最小样例进行变更前后体积比较，分别为 9,407,266／7,011,490 字节，均零增长且二进制摘要一致。
