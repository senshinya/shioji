# 添加设备时准备执行服务

按已确认的 `artboard/device-service-preparation` 实现。连接页保持 560 DIP 内容区，复用现有字段、底部操作和步骤切换；不新增说明卡片。用户补充：加载图标与中文文案按实际字体度量对齐；连续加载状态保留同一图标节点与旋转时钟，只更新文案。

## 流程

“连接并准备服务”继续执行严格 SSH 认证和已确认的指纹／密钥流程。检查现有 worker 后，兼容且无需更新直接进入 Agent；较新兼容服务保留，不降级。只有设备报告安全更新能力，才使用现有签名暂存与 `worker.update` 准入。协议 1.3 保持独立、明确确认的旧服务迁移入口，其他未经验证的旧服务不强行停止。

更新意图绑定设备、SSH 目标与端口、目录、原构建及候选摘要。连接检查、准备文件、等待空闲、更新／重新连接、核对结果使用明确状态。worker 拒绝忙碌后才能等待并重试准入；待处理请求和未知执行仍由 worker 的原子准入决定，不从 UI 快照推断空闲，不停止任务。

客户端按所属设备分别保留准备意图，切换或添加另一设备不能覆盖未确认更新；同一设备的其他 SSH 别名只接续原操作。客户端先保存待提交状态，再提交更新；断线或 GUI 退出后恢复为只读核对，不重发不确定的更新。观察到实际候选构建或可兼容的较新构建后，重新加载同一设备的 Agent 目录再前进。已确认尚未提交的传送／本地保存失败允许重新准备；已发出但未收到结果时只提供重新连接，保留原 SSH 认证、草稿和目标。普通返回／切换页面不会把迟到结果应用到另一连接。

复用现有安全更新实现，不增加 worker 协议或第二套服务管理器。保存的是客户端的准备意图，worker 始终拥有更新准入、备份和替换。没有旧版可查询的更新操作状态时，只读核对实际构建，不能把仍见到旧构建当成未接纳证明。

## 界面与动效

连接选项收起、进度区域高度使用现有 240 ms 实际高度动画；状态文案单独过渡 160 ms；进入 Agent 使用既有 260 ms 水平滑动，整页不渐隐渐显。加载图标统一使用文字基线和 `Font.InkBounds` 的汉字／大写字高度量；刷新文字不重建图标或重置角度。减少动态效果停止旋转与位移。
