# Hook 管理

设备 → Agent → Hooks 管理全局来源；工作区设置 → Hooks 管理主目录的项目来源，并只读显示全局继承项。会话的运行配置菜单也有 Hooks 入口，按已接纳的执行目录检查当前进程；配置查看不会创建或恢复会话。列表提供搜索和刷新，详情展示完整执行定义、来源和条件。现阶段只管理已有定义，不新增、编辑或删除定义。

“信任此版本”与启用独立。信任绑定发现时的定义版本；外部修改后须重新审核。受策略管理、未知或审核内容不完整的来源只读。当前原生 MCP Hook 列表仅给出 server/tool，缺少实际 input 参数，因此工具型 Hook 只能查看，不能启停或信任。工作区入口不能修改继承的全局项，需通过“管理”进入设备页，返回保留工作区草稿、查询、详情和阅读位置。会话入口返回后保留普通输入草稿。

## 所属设备与协议

Worker 协议 2.46 增加 `runtime.hooks.list`、`runtime.hooks.change`、`runtime.hooks.operation`，使用 `domain.HookRequest`。空 WorkspaceID/SessionID 表示当前设备的全局管理；其他请求由 worker 根据持久记录解析工作区主目录或会话已接纳的 CWD。客户端不能指定文件目标或任意目录。工作区、会话、Agent 和设备身份须一致，归档入口只读。

`HookCatalog` 表示发现范围、配置修订、条目与实际会话加载状态。`HookEntry` 的 ID、DefinitionRevision 和指纹均是不透明展示/定位数据，共享 worker 与 UI 不解析。`HookManagement` 与 `HookInspection` 是可选能力，不支持时不影响普通对话。每项另有 CanEnable/CanTrust 能力和只读原因。

写入仅支持 `setEnabled` 与 `trustDefinition`。接纳前重新发现和核对列表修订、精确定义与所属范围；与其他原生配置写入共用配置锁。SQLite schema 14 的 `hook_operations` 保存稳定 OperationID、完整请求和回执。相同 ID 不能换成另一个来源、范围或定义；重连只查询并核对，未确认请求不重发，也不套到新定义上。未确认回执可独立核对；目录仍可权威刷新并保留旧回执身份，用户重新审阅最新定义后才可发出新操作。旧批准不会重放。

## Codex adapter

具体 `hooks/list`、`config/read` 和 `config/batchWrite` 字段只在 adapter 内。运行时生成 schema 决定可用接口。全局查询先核对设备 HOME 的实际配置层，若 HOME 自身包含活动项目配置则明确不可用，不将该目录发现当作全局来源；工作区和会话查询保留实际来源。项目列表中的插件若不能通过经过范围验证的独立全局发现确认归属，就只读显示为未知来源。

状态写入原生用户配置的精确字段，使用原生配置版本校验，不改定义文件、不覆盖私密配置。保存前后的定义仍须相同。批准精确旧版本不会构成“始终信任”。

保存后对本 worker 的独立 Agent 进程执行配置重载，不停止活动轮、不提交 prompt。无法确认某个进程时，回执区分“已保存”和“尚未确认采用”；每次创建、恢复和下一次输入前仍重载配置，失败则不发送这一轮输入。配置修改与该输入边界串行，活动模型轮不占用配置锁。

## 验证边界

本机隔离 CODEX_HOME 与本地确定性模型覆盖发现、禁用、首次信任、变更后失去信任、陈旧请求拒绝、继承只读、重启回执和独立进程刷新。真实活动会话验证在修改期间保持原线程运行，下一轮恰好执行一次已批准的无副作用夹具 Hook。所有可执行夹具仅写测试临时目录，不触碰用户 Hook。

原生 UI 使用生产 MyGo View、系统字体和 raster 渲染，隔离目录响应覆盖亮暗、中文/英文、窄窗口、滚动、失败和断线。它证明本机构建的布局与交互，不代表已部署到用户安装包或已完成另一台 Mac 的 SSH 实机验收。设计与实施记录见 [规格](ryugi/specs/2026-11-17-hook-management-design.md)。
