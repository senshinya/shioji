启动首页与新建会话

启动应用、点击“新建会话”和 ⌘ N 进入同一个全页草稿界面。工作区旁的加号进入同一页并预选所属工作区，进入页面本身不创建任务、不启动 agent。沿用现有灰阶、左侧悬浮导航与表面语言：主区域只有一个新会话输入区，不重复展示侧栏任务，也不增加问候语、logo 或推荐任务卡片。

内容列最大 736 px，整体位于视口中部偏上。32 px 的中央标题直接包含可切换的工作区名称，不再使用左对齐的“新建会话”标题加右侧独立选择器。选择器展开后同时列出工作区所属设备。首页输入框与消息界面共用背景、边框和阴影，包含聚焦状态；浅色使用白底，深色沿用消息输入框的表面。初始正文高度从 112 px 缩至 72 px，保留多行增长能力；常态不显示框外快捷键说明。输入框内顶部左侧展示可搜索的分支选择器，旁边用“新建 worktree”复选框控制是否基于所选分支创建独立工作目录；仍属于当前工作区。主目录和附加目录统一在工作区设置，输入框不再重复目录信息或提供独立选择入口。底部保留附件、Codex 模型、推理强度与发送。首页和消息界面的主操作统一为 28 px 圆形按钮、20 px 图标槽；发送使用更饱满的箭头，停止使用实心圆角方块，避免图形在圆形内过小。设备连接状态仍在窗口工具栏右侧，随工作区同步更新；窄窗口也保留该设备入口。

普通新建继承当前工作区；切换工作区保留任务文本，各工作区独立保留所选分支与 worktree 选项；新会话直接继承工作区的主目录与全部附加目录，路径不得跨设备沿用。首页草稿与已有会话草稿独立，离开首页查看任务后仍可返回继续。任务通过发送按钮或默认的 Enter 创建，成功后才清空首页正文，并进入新会话继续输入。分支 main 和 worktree 在此为界面样例，真实应用需查询目标设备的仓库与能力。

1. 视觉与工作方式

克制、冷静、精确。采用接近 macOS 的中性灰与白色表面，深色模式使用炭灰；用户明确要求不显示 logo，不使用灰绿色基底，也不用蓝色选中态。选中依靠单色明度变化与细线，按钮使用黑／白。颜色用于清晰的运行、等待和 diff 语义提示；不把状态色扩散到表面或选中态。会话状态标记保留原来的 4 px，仅通过饱和度与对比度提高辨识度，浅色使用饱和绿 #138a43 与橙 #c66a00，深色使用亮绿 #32d769 与橙 #ff9f0a。完成使用中性灰勾，暂停使用双竖线；不闪烁、不发光。首期面向个人，不加入团队账号和协作权限模型。

Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining

默认专注一个任务，其他 agent 后台工作。会话导航保留在侧栏，顶部不重复排列任务 tab；需要比较时并排打开两个会话。移除重复的“全部任务”入口和列表页；工作区侧栏保留全部未归档任务，包括已完成任务。⌘ K 支持跨工作区查找，“待我处理”带人回到具体审批或问题。没有待处理任务时保留当前会话和输入，仅轻量提示。工作区主目录与附加目录统一放在顶部工作区菜单与管理页，输入区不再重复目录入口。

2. 信息架构与边界

设备→工作区→多文件夹＋并行会话→轮次 / 活动 / 改动
  • 设备是执行目标；地址与连接方式可以变化，但设备身份不能靠当前 IP 决定。
  • 工作区绑定一个设备，多个工作区可以引用同一设备。目录必须从所绑定设备选择和校验。
  • 会话保存工作目录、harness 标识、远端会话标识和 Git 上下文，切换视图不影响执行。
  • 本机与远端共用领域模型，本机执行无需 SSH。
  • 多文件夹保留各自的仓库与权限。加入 workspace 不自动授予所有会话读写权限。

3. 页面与主要操作

界面核心任务关键交互
主界面阅读、输入与跟进当前任务左侧工作区与会话；中间专注对话；改动面板按需打开。用户消息靠右，工具活动以紧凑行展开，输入区与对话共享宽度。
双栏并行同时跟进两个独立任务首期同一 workspace 内并排；每栏独立输入、滚动和停止操作，不隐式广播消息。
改动审阅边阅读改动边与 agent 交流保留左侧对话与输入区，右侧查看 diff、切换文件、添加行评论。文件与行号带入原会话草稿，确认后发送，不自动关闭审阅。
设备连接、查看与诊断执行目标可搜索的设备列表与持续显示的详情并排；一个添加菜单提供 SSH 与 Tailnet。详情展示连接身份、环境状态和关联工作区，Tailnet 作为集合内的独立入口。
工作区管理同设备的多个文件夹先选设备再选目录；添加目录不变更已有会话的 cwd。移除不会删除设备上的文件。
等待处理及时回答 agent 的请求审批与问题共用底部翻页区，保留各自提交路径。单次允许、拒绝和文本回答具有明确范围；断线时禁用回复。
断线理解不确定状态并恢复连接保留内容、时间与草稿；执行状态待确认。恢复连接不重放历史命令或原始 prompt。

连接信息放在设备上下文中

侧栏底部保留“设备”和设置入口。应用内 Tailnet 的登录、节点与网络状态放入设备页；当前工作区的设备名称出现在顶部，点击查看连接方式、主机与 Codex 就绪情况。本机和直接 SSH 会话不显示无关的 Tailnet 状态。

设备页：集合与详情

设备页使用固定设备集合与选中详情的布局。左侧设备采用 32 px 单行，16 px 图标与名称对齐，活动数和 4 px 状态点位于右端；连接方式、主机等详情留在右侧。集合按本机与远程分组，可搜索名称、主机与系统；选中态保持中性灰。右侧按连接、运行环境、工作区组织信息。工作区入口可直接进入管理页，也可在当前设备上新建工作区。窗口工具栏中的统一添加菜单提供直接 SSH 与从 Tailnet 添加。

设备页使用横向全高布局，标题和添加入口进入窗口工具栏。应用内 Tailnet 位于设备集合中；选中后在同一个右侧详情区管理节点、网络设备、登录与退出，避免在主区域上方叠加网络板块。网络状态与设备 SSH 连接、运行环境就绪各自表达；退出应用网络不会把本机和直接 SSH 设备标成离线。

离线设备保留上次同步信息、禁用环境检查和新建目录相关操作。重试不可达设备保持离线并展示失败原因，不伪造连接成功。新添加的设备先显示待检查，环境检查完成后再显示就绪。窄窗口在设备集合与详情间切换，详情有明确返回入口。

延迟与连接路径

远程设备的单行列表显示最近 RTT；本机不显示网络延迟，离线显示“—”，没有样本显示“待测”。连接详情显示 RTT，Tailnet 设备额外显示直连或 DERP 中继区域名和代码。演示样例包括 Mac mini 直连 12 ms、SSH 构建机 18 ms、Devbox 通过香港 DERP（hkg）48 ms，以及离线设备的上次东京路径（tok）。这些数值与路径均为界面演示数据。

原生实现通过应用内节点的探测与状态接口取得当前对端路径、往返耗时和观测时间，不调用系统 tailscale。选择能够返回路径的探测类型，并使用固定版本的 DERP map 将区域代码映射为名称。不能仅因 PeerStatus 中存在 Relay 字段就宣称正在中继，也不能把客户端到 DERP 的延迟当作到目标设备的 RTT；Peer Relay 与未知路径应单独表达。断线或测量失败时保留已知样本并标记过期，不伪造零延迟。连接类型说明；PingResult 的 RTT、Endpoint、PeerRelay 与 DERP 区域字段。

底部待处理区：审批与问题

以现有审批卡片为样式基准：中性灰底、12／14 px 内边距、紧凑清晰的标题、白色内容块，以及底部左对齐的操作按钮。问题区向这一样式对齐。审批也移到消息框上方，保留命令、权限范围和工作区／设备上下文，允许这一次与拒绝仍是独立操作。

同一会话同时出现审批与问题时，共用一个翻页区域，每次显示一项，避免上下堆叠。审批与提问不合并响应协议；允许或拒绝只处理该审批，回答只提交原请求的一组答案。剩余任意待处理项都会保留侧栏的提醒状态。审批原位置也保留可定位的轻量记录，处理后原位显示结果。

所有待回答问题集中到消息区底部、普通消息输入框上方，不再散落在聊天记录中。一个会话的不同请求按到达顺序合并成一个翻页区，每次显示一题；标题行提供上一题、当前位置／总题数、下一题与收起入口，提交操作放在卡片底部左侧。仅一项时不显示翻页控件。第一页和最后一页禁用对应方向，不循环跳转。键盘聚焦翻页控件时可用左右方向键切换，编辑回答时方向键保留原有输入行为。

文字题、单选、多选与“其他”输入使用相同容器，题目完整显示在回答上方。题目内容最高为视口高度的 28%，且不超过 240 px；长题、长选项在区域内滚动。消息输入框始终保留，问题区与待发送队列分别管理自身状态。文字草稿、选择与多选项在翻页、切换会话和断线后保留，填写与选择均不自动翻页或提交。

提交仍按原请求成组进行，当前请求的全部题目有效时才启用提交；尚未填完时按钮提示剩余题数。提交成功后只移除该请求的页面，其他请求和草稿保持，提交回执保存在聊天记录。回答提交不会将任务标成完成，普通消息也不会消除待回答问题。离线时回答可继续编辑，提交禁用；重连不自动提交。

提问发布的原位置保留一条轻量事件记录，标明提出了几题，点击可打开底部对应请求中的首个未填写问题。agent 后续继续输出时，记录仍保留原来的时间顺序；提交成功后在原位置替换为可展开的回答回执，不把记录移到对话末尾，也不重复展示完整表单。预览工具栏“继续输出”可模拟后续内容。

分支归入消息框内部的左上角，放在待处理卡片与消息队列之后；长名称截断，悬停显示完整值。首页的分支选择器与“新建 worktree”复选框位于相同位置。已有会话仅在连接正常、任务不在工作且没有待处理请求时允许切换分支，保留输入草稿。工作目录与附加目录由工作区统一配置，输入框不再提供目录入口。

默认展开与新问题到达

首次遇到问题时，仅在用户跟随最新内容、没有编辑消息草稿时展开；用户主动收起后保留状态。后续问题追加到翻页总数中，不跳离当前题、不抢焦点、不强制滚动。点击“待我处理”会定位首个未填写问题；全部填写后定位提交按钮。收起状态也保留当前页，左右翻页可重新展开。

预览工具栏“追加提问”仅用于演示新请求。多选题是界面能力样例，真实适配需要核对固定版本的 app-server schema，不将原型的 multiple 标志视为 Codex 协议字段。保留 thread、turn、request 和 question 标识，按完整请求提交答案；通过 serverRequest/resolved 与轮次生命周期撤销失效表单。

菜单与信息弹窗的密度

工作区目录、发送选项、添加设备三类操作菜单共用 menus.css：26 px 行高、13 px 标签、14 px 图标、3 px 外围留白和 7 px 外圆角。20 px 的过密版本已撤回，阅读空间来自行高与字号；整体紧凑感由小外围留白、统一的管理行和轻量边界保持。

两个目录与管理入口共 84 px；发送选项 91 px；添加设备 58 px。目录与管理入口同高，不设单独的高底部区域。快捷键维持 11 px，长目录名单行截断并保留完整路径悬停，目录较多时在清单内滚动。设备状态与本轮用量保留 10 px 内边距及可读的信息行；设备底部操作恢复至 26 px。查看当前菜单与弹窗截图 →

右侧栏与顶部工具栏的边界

右侧计划／改动栏是贯穿窗口高度的独立分栏，竖向分割线从窗口顶部到底部连续绘制。右栏自己的顶部放计划／改动切换和关闭按钮，与会话工具栏保持同高：桌面 48 px，窄窗口 44 px。会话工具栏只占会话列，止于右栏边界，不再跨过右栏顶部。

当前设备按钮保留在会话工具栏右侧，位于计划、双栏及右栏开关之前，展开右栏时随会话列一起收窄。连接状态弹窗依附该按钮；设备上下文不进入计划／改动栏。左侧导航继续保持原有的 8 px 留边卡片。右栏不改成悬浮卡片。

回复中的“查看改动”和顶部工具栏的侧栏按钮打开同一份改动侧栏，宽度与样式一致；从计划切换到改动也保持该容器。点击具体文件，或明确选择“审阅”，才进入宽幅 diff 阅读区。窄窗口的计划与改动共用同一抽屉，覆盖到窗口顶部，自带关闭入口。此次只调整面板与工具栏归属，不改变任务处理、归档或侧栏可见性的规则。交互稿新增“侧栏 · 改动”场景，可直接检查分割线与设备按钮位置。

消息区左侧对话导航

在阅读区左缘展示短横线刻度，不占用工作区会话侧栏。每个已发送用户消息对应一条刻度；间距 10 px、线高 2 px、静止线长 6 px。当前阅读位置提亮，点击跳转到对应消息。待发送草稿、agent 正文与工具增量不增加刻度。较窄面板隐藏导航，优先保留阅读与输入空间。

悬停线长 26 px，两侧三条刻度按 0.7／0.4／0.2 的强度逐级延长，使用 160 ms 的缩放过渡。停留 200 ms 后显示消息预览，连续查看无需重复等待；预览宽 320 px、内边距 8 px、圆角 12 px，用户消息单行截断、回复保留三行。保留本产品的中性灰阶，不新增书签等未规划的操作。悬停不改变阅读位置或抢焦点。上下键、Home、End 切换刻度，Enter 跳转，Escape 关闭预览，并遵循减少动态效果偏好。

滚动条与底部输入区

消息滚动容器覆盖会话面板至窗口底边，右侧滚动条经过输入区外侧，滚到底时滑块也抵达轨道底端。输入区固定于底部，滚动内容按输入区实际高度加 24 px 预留底部空间；问题、审批、队列和多行草稿变高时同步更新，因此最新正文与轮次统计不会被遮住。用户已经在底部时继续跟随输出，阅读历史时保留原位置。

连续工具调用的展开与折叠

连续的工具调用归为一组。该组仍是最新工作动态时默认展开，显示调用列表与当前输出；工具执行完成不触发收起。后续非空的 agent 正文到达时，前一组自动收成“ N 次工具调用”摘要行，调用与输出完整保留，可手动重新展开。正文之后再次出现工具调用，另起一组并展开。

空白文本增量、普通消息草稿、用户补充消息和延迟到达的工具结果均不视为新的 agent 正文。每组只在由最新工作转入历史时自动收起一次；用户重开的历史组不会被下一段正文反复关闭。用户主动收起最新组后，后续工具更新保留该选择。组与条目的展开状态按会话和稳定标识保存，不按列表下标恢复；真实实现依赖 harness 的有序结构化事件。

预览增加“工具调用 · 最新动态”与“工具调用 · 正文之后”场景。工具栏“追加工具调用”和“继续输出”可演示连续调用、正文触发折叠，以及正文之后的新调用，均为演示事件。

回复底部状态与用量

回复顶部和后续正文不再显示 Codex、头像、时间戳或“正在工作”标题。每轮仅在实际内容末尾保留一行：运行中使用 4 px 状态点、“正在工作”和已工作时间；结束后显示绿色小勾与“本轮完成”，后接耗时和本轮输入、输出、缓存三项 token，用量可点击查看精确数值。计时只更新当前活动轮的文字，不重绘正文或抢走输入焦点。

等待批准、等待回答、已停止、执行失败和执行状态待确认分别显示，不能把断线当作任务结束。工作耗时排除已知等待用户的区间；完成后冻结。用量未回报时显示未知，后续回报再补齐；已回报的零值可以显示为零。底部不再以单个 token 合计代替明细；三项顺序为输入、输出、缓存。缓存命中属于输入子集，不能再次叠加。字段未回报时显示“—”，不能当成零。实际 adapter 必须按固定版本 schema 归一化，不能把会话累计量、上下文占用或不同口径的字段当作本轮消耗。

新一轮开始或队列推进时，上一轮的底部摘要保留在原处，新一轮独立计时。原型的完成确认、耗时和用量均为演示数据；真实状态、轮次结束与统计必须由实际 lifecycle / usage 事件驱动，发出停止请求不等于已经停止。

6. 焦点、动效与可访问性

  • ⌘ K 查找会话；⌘ ⇧ J 跳到下一个等待处理的任务；⌘ ⇧ H 返回上一个会话。
  • Enter 发送或保存编辑，当前轮运行时加入该会话队列；⌘ Enter 单次立即介入；Shift Enter 换行。三项按键可在设置中调整并保存，冲突组合不可重复分配；输入区、按钮提示和发送菜单不显示快捷键说明。
  • 工具行可展开，输入框、菜单与对话框有键盘焦点。图标按钮提供可访问名称，减少可见标签不等于省掉辅助信息。
  • 短促按压与焦点强调使用 120–150 ms 的透明度或缩放变化；遵守减少动态效果，不使用常驻闪烁吸引注意。
  • 真正的 MyGo 实现需单独验证中文输入法组合文本、跨块选择、复制、VoiceOver 和系统快捷键，浏览器原型不能代替这些验证。

7. Git 与多目录并行

Git 主仓库默认勾选“新建 worktree”；取消勾选后在当前目录使用所选分支，勾选后以所选分支为基准创建任务分支与独立工作目录。该选项仅用于新建会话，不静默移动已有会话。真实应用从所属设备查询可用分支和仓库状态，检查未提交改动及 worktree 占用；不强制覆盖改动、不伪造切换成功。非 Git 文件夹直接使用原目录，隐藏分支与 worktree 控件。附加文件夹不会因为主仓库隔离而自动隔离，首期应明确授权和并行写入策略；不能在界面上宣称整个多仓库 workspace 都已隔离。

新会话以工作区主目录作为 cwd，并继承全部附加目录；保存创建时的执行上下文，后续工作区目录变更不静默扩大已运行会话的访问范围。附加目录的访问、特殊权限和只读支持由 Codex adapter 的实际能力决定，无法表达的权限不显示成可用设置。

10. 运行中消息投递

采用 Lody 的贴合输入框的队列清单，以及 T3 Code 按内容与投递动作切换主按钮的方式。灰阶按钮和表面沿用当前界面，不复制参考产品的彩色停止按钮。

运行中且输入框为空时，右下角显示停止；输入内容后切换为加入队列，旁边小菜单提供加入队列、立即介入和停止当前轮。Enter 默认排队，⌘ Enter 单次立即介入；菜单操作与快捷键使用相同路径，输入法组合阶段不提交。立即介入保留当前轮及剩余队列，不通过停止后重启来模拟。

队列固定贴在输入框上沿，默认只有 32 px 的“待发送 N”折叠行。展开后每行 32 px，超过区域高度时在清单内滚动；长消息以单行摘要呈现，编辑时可查看全文。每条消息悬停或键盘聚焦后显示立即发送、编辑和移除，触屏下始终显示操作。停止当前轮、切换会话和重连均保留队列；折叠状态按会话保存。

编辑回到主输入框，保存更新原有消息，取消不改动队列。开始编辑前暂存原有消息草稿，保存或取消后恢复，不丢弃未发送内容。待发送消息不进入已发送记录；投递确认后才进入会话。问题表单、回答草稿、普通消息与队列各自保留状态。

本稿所有投递确认均为演示。预览工具栏的“完成本轮”模拟轮次结束，只取队首一条开始下一轮；停止和恢复不会隐式消耗队列。原生实现须由固定版本 harness 的确认事件驱动，失败保留原文与可重试状态，不能把本地乐观状态视为执行成功。

界面依据：Lody 队列容器、T3 Code 输入栏按钮。先前的投递机制研究作为技术补充，不作为本轮 UI 对照。

11. 输入框运行选项

采用用户在实际界面对照后选择的 Lody 菜单组织方式。输入框底部保留运行配置与 Permission 两个入口。运行配置显示 Codex、当前模型和推理强度；Plan、Fast 开启时分别追加小图标。首页与会话共用同一组件，发送和停止保持 28 px 圆钮、20 px 图形槽。

运行菜单宽 240 px，外边距 4 px、行高 28 px、圆角 9 px。上方按 Agent、模型、推理强度排列，设置名左对齐、当前值右对齐；模型与推理强度通过右侧子菜单选择。首页允许选择 Agent，目前只有 Codex；会话中展示固定 Agent，不提供切换箭头。不加入 Role、模型卡片、滑杆或重置入口。

分隔线下是 Plan 与 Fast 直接开关，使用中性色。选择模型或推理强度后回到主菜单，主菜单继续打开；点击开关也不关闭，方便连续调整。所有操作只修改下一次提交的配置，不发送消息、不清除草稿。Fast 与 effort 独立，切换模型时依能力隐藏不支持的控件并清理不兼容值；模型及能力数据仍为设计样例。

Permission 保持独立、始终显示短名称，展开只读、默认权限、Auto Approve、YOLO 列表。Auto Approve 保留配置的沙箱，YOLO 同时关闭审批与沙箱；真实映射和组织限制以固定版本 harness 为准。改权限不会解决或撤销已有审批和问题。

Plan 配置首页与会话分别保存，新建时复制到会话。它与右侧展示结构化执行计划的面板独立，不追溯改写进行中的轮次；原生实现要等待运行时确认。

鼠标悬停延迟展开子菜单、不抢键盘焦点；点击和右方向键可进入，上下方向键与 Home / End 浏览，Enter / Space 选择，左方向键或 Escape 返回。再次 Escape 关闭并恢复入口焦点。子菜单先向右，空间不足则向左；两侧都放不下时原位展示选项并提供返回。长名称换行，长列表内部滚动。窄窗口将运行配置与 Permission 放到单独一行，附件和发送留在下方。

12. 后续实现与设计守则

  • 保持“工作区 → 任务”的短路径；设备详情在连接与诊断时出现。
  • 主内容使用 MyGo 原生组件，局域网 HTML 仅用于评审。
  • 对话事件逐块更新，不为每个 token 重建全部历史；离屏输出与日志设置上限。
  • 滚动、草稿和选中文本属于具体会话；查看另一个任务不会清掉这些状态。
  • 传输断开、任务失败、用户中断、等待审批与任务完成必须各自建模。
  • 新的 harness 通过能力边界接入；先做 Codex，不提前堆一个泛化插件平台。
  • 设计稿与研究资料只在本机和局域网提供，不启用云发布或公网转发。
