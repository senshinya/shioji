# AGENTS.md

## Product

Build a native macOS application for controlling parallel coding agents across multiple devices, using a self-contained Shioji worker on execution devices.

The confirmed requirements are:

- Support direct SSH connections to devices.
- Embed a Tailscale node in the application so users can join a tailnet and add reachable devices without installing or running the system Tailscale client on the controlling Mac.
- Organize work by workspace. Each workspace belongs to exactly one device and can contain multiple folders on that device.
- Render agent conversations and working content natively, with t3code and Lody as interaction references.
- Initially support Codex through Codex app-server. Keep a clear extension boundary for additional agent harnesses.

## Project constraints

- Product name: Shioji (潮路 / しおじ); commands use `shioji` and `shioji-worker`. Preserve existing historical filenames and signed artifact identities rather than renaming them retroactively.
- Target macOS on Apple Silicon (`darwin/arm64`) for both client and execution devices. Intel, Linux and Windows are out of scope. The minimum supported macOS version remains undecided.
- Implement in Go with MyGo native UI (`github.com/egoist/mygo/ui`). Prefer its native text, Markdown, code and diff components. Keep the main interface native; do not substitute HTML, Electron or a WebView.
- Use a complete, self-owned Go worker, including for this Mac as a local target. Do not require, bundle, install or invoke herdr-core as a runtime dependency.
- Embed official `tailscale.com/tsnet` behind the transport interface; its network work and lifecycle stay independent of UI rendering. Support authorized inbound and outbound connections without assuming the system SSH listener is exposed by the embedded node or automatically enabling Remote Login.
- Preserve the frozen design. Verify repository inputs with `python3 scripts/verify-design-freeze.py --repository`; the command without flags also checks the full local design archive.
- Keep confirmed requirements distinct from engineering defaults and unresolved choices. Research probes and mockups do not establish production support; implementation must validate the actual runtime and platform behavior.
- Keep the Git baseline focused as described in `docs/research/README.md`. Do not force-add local research archives, screenshots, reference captures, prototype tooling or generated state.
- Keep credentials, existing user nodes and device permissions intact. Joining a tailnet does not authorize control; additional node enrollment and execution access require the corresponding explicit user action.

## Domain boundaries

- Device: a stable execution target, independent of its address or connection method.
- Connection: the transport and authentication used to reach a device. Direct SSH and tailnet connectivity must not create incompatible workspace models.
- Workspace: a named collection of folders on one device. Multiple workspaces may reference the same device.
- Folder: a device-scoped path. Resolve and validate it on the owning device; never interpret a remote path as a path on the controlling Mac.
- Agent session: a conversation and execution context inside a workspace, with an explicit working directory and harness identity.
- Parallel execution must not depend on which session is visible or selected in the UI.
- Workspace folder membership does not itself grant an agent access to every folder. Translate access and working directories through the selected harness's capabilities and permission model.
- A workspace's folder collection does not imply shared Git history. Preserve repository and worktree boundaries.
- Local and remote clients of device B use B’s same authoritative worker/state and stable device/workspace/session IDs. Installing Shioji locally on B must expose the same B-owned workspaces previously accessed from A. Each client lists only itself and devices it explicitly connects to; do not inherit another client’s connection list or replicate worker catalogs across devices.

## Architecture

避免过度抽象和过度防御。优先用直接、清晰的实现满足已确认需求；出现实际重复或明确扩展需求后再提取抽象。校验与错误处理应针对真实的输入、信任和故障边界，避免为假想场景堆叠接口、配置、重复检查或静默兜底。

Keep these responsibilities separate:

1. Native presentation: windows, navigation, conversations, input, approvals, changes, and execution status.
2. Application domain: devices, workspaces, folder membership, sessions, and persisted selection/layout state.
3. Device transport: direct SSH, embedded tailnet connections, authentication, and reconnect behavior.
4. Device worker: process/session lifecycle, app-server ownership, operation acceptance, persistent queues/events, device-local files/Git, and recovery.
5. Harness adapters: Codex app-server initially, with capability-based extension points for future harnesses.

The worker owns harness processes independently of GUI and SSH connection lifetimes. Run the Codex adapter within the worker and expose versioned normalized commands, events, and snapshots to the app over authenticated device connections. Keep app-server stdin/stdout as a dedicated pipe protocol, separate from diagnostic logs. Validate deployment, crash recovery, and request lifecycle; neither process persistence nor saved thread history guarantees recovery of an in-flight turn.

Multiple agent harnesses are a confirmed architectural requirement; Codex is only the first implementation. Keep a harness-neutral intermediate contract between the application/worker orchestration and concrete adapters now, rather than deferring that boundary until a second harness is implemented.

- The intermediate layer owns Shioji's commands, events, capabilities, lifecycle states, content, requests, usage and errors. It must not import a concrete harness or contain its protocol method names, wire structures, permission policies, executor types or error types. Do not reproduce Codex's protocol with generic names, or hide native payloads inside untyped maps to bypass this boundary.
- Each adapter translates in both directions: neutral commands/configuration into the concrete harness, and concrete events/results/errors into neutral semantics. Keep source request encoding and harness-specific recovery/history mechanics inside that adapter. Source identifiers may cross as opaque references scoped by harness and runtime; shared code must not parse them or infer semantics from their spelling.
- Shared worker orchestration depends on neutral interfaces and declared capabilities. Concrete adapters are selected only at the composition/registration boundary. Harness process/executor setup belongs behind the adapter; the worker retains authoritative operation acceptance, persistence, queues, execution ownership and safety checks.
- Capabilities describe the actual adapter/runtime/model support. Unsupported steering, planning, history operations or configuration choices must be explicitly unavailable; never emulate one operation with another silently. Harness names, icons and model labels are catalog data for generic UI rendering, not hardcoded Codex branches in shared presentation.
- Avoid a speculative universal plugin framework or implementing additional harnesses without a concrete requirement. This limits abstraction size; it does not weaken the required neutral boundary. The implemented boundary and verification criteria are recorded in `docs/agent-model.md`.

Run agent tools against the workspace's owning device. The exact remote app-server supervision and transport strategy must be validated before implementation; the UI must not assume the agent runs on the controlling Mac.

## Embedded tailnet

- Embedded connectivity must work without shelling out to a system `tailscale` installation.
- Integrate `tsnet` behind the device transport interface within the Go application. Keep its lifecycle and network work independent of UI rendering.
- Treat the embedded application node's identity and authentication as separate from any system Tailscale installation.
- Show recent RTT for remote devices in compact device rows. In device details, show the active Tailscale path and the DERP region name/code when relaying. Keep current measurements distinct from last-known samples and unknown/offline values; do not present unknown latency as zero. Use the embedded node APIs, never the system CLI. Do not infer DERP use merely from a configured/home relay, and do not substitute local-to-DERP latency for end-to-end peer RTT. Account for direct, DERP, peer relay, and unknown paths using actual reported observations.
- App-local tailnet connectivity is not system-wide routing. All application connections to tailnet devices must use the embedded transport or an explicitly implemented bridge.
- Joining a tailnet does not automatically authorize SSH, deploy the Shioji worker, or install/authenticate Codex on peers. Check device readiness separately.
- Device discovery must respect the embedded node's actual peer visibility and access policy. Do not require an administrative API token just to connect to a known peer.
- Persist node identity securely and keep credentials, private keys, and authentication URLs out of logs.

### 图标与中英文对齐

- 图标按钮的命中区域、图形槽位和实际笔画边界分开处理。本项目紧凑按钮为 28 px，图形槽位为 16 px；同组图标统一线宽、实际可见高度和视觉中心，不能仅凭相同 SVG viewBox 或元素宽高判定已对齐。
- 图标紧邻文字时采用共同的文字基线及字体度量，不用整行盒子的几何中心代替字形中心。拉丁文参考大写字高（`H`），中文参考实际系统回退字体的汉字可见字面（`国`）；中英混排按汉字字面校准，保留文字原有基线与行距。这里的 `H` / `国` 是本项目的测量策略，不是外部规范指定的固定字形。文件／Skill 候选行的图标可按实际名称的 `Font.InkBounds` 校正字面中心。行内标签的文字必须使用稳定基线：拉丁字母统一按包含大写字高与下伸部的 `Hg` 字面留白，中文按 `国`；不得按每个名称的笔画包围盒上下移动文字，否则 `check` 与 `design` 会因是否有 `g/p/y` 而错位。图标保留共同槽位，并用实际名称验证。
- 多行任务、菜单与工具行的图标/状态点对齐第一行文字，不对齐整段高度。复用 `internal/ui/typography.go` 的 `inlineFontMetrics`、`inlineSymbol`、`inlineIconText` 和使用同一度量的 `statusDot`；使用原生 `Font.InkBounds`，不按单个文案堆叠 padding 或 `translateY` 魔数。
- 独立图标在按钮内居中，文字旁的图标按字面光学校准；同组需要的光学修正统一写入图标路径或公共排版计算，不因 hover、选中、状态变化或 Shimmer 改变位置。
- 核对亮暗模式、中文、英文、混排与多行的真实原生截图，检查笔画而非只看布局框；同组可见高度、中心和首行对齐误差控制在 1 逻辑像素（DIP）内，并保留相关原生回归检查。
- 参考：[Apple SF Symbols 的字体尺度与光学对齐](https://developer.apple.com/design/human-interface-guidelines/sf-symbols)、[Apple 自定义符号的基线和字高导引](https://developer.apple.com/documentation/uikit/creating-custom-symbol-images-for-your-app)、[W3C 对拉丁与表意文字基线度量的说明（工作草案）](https://www.w3.org/TR/css-inline-3/#baseline-metrics)。借鉴其排版原则，原生界面仍使用 MyGo，不引入 CSS/WebView。

### 设置

- 设置使用独立原生窗口，分为外观、消息输入、通知、快捷键和关于。侧栏分类切换保持即时，不加内容动画或选中底色移动；内容顶部不重复“设置”总标题、分栏或“当前 Mac”。
- 设置与主窗口共用红绿灯位置和 8 px 侧栏内缩。侧栏图标与文字左对齐，搜索紧接窗控区域。设置行以水平分隔线组织，不加整组外框或底色；选择器右端、开关右端和分隔线右端对齐。
- 开关采用无阴影灰阶胶囊，系统通知总开关使用相同样式。主题选择保留正常文字颜色，仅用中性边框和对勾表示选中，不依赖原生 Selected 覆盖文字颜色。
- 外观预览使用真实 Markdown 与当前文字配置；消息输入页不重复静态输入框示意。设置即时持久化，当前设置窗口必须显示保存失败。快捷键保持原生输入、选区和 IME 行为，并拒绝冲突。
- 前台通知默认开启，保留用户明确关闭的选择。系统通知须经 macOS 授权，按真实生命周期事件发送；历史重放、停止和补到的用量事件不产生完成通知。通知处理不依赖窗口可见或重新绘制，保留对象与去重记录须有界。

- 设备 Agent 行点击后进入完整配置页，替换当前设备详情内容，不在列表下展开或增加子级缩进；左侧设备列表保持固定。配置页从右侧滑入，返回时向右滑出并恢复设备页；返回不丢弃未保存的当前 Agent 草稿。配置按“常规、模型、MCP、高级”排列，MCP 位于模型之后、高级之前，仅在设备设置展示。MCP 列表使用 Tab 的剩余高度，超出后内部滚动，不沿用模型的 3.5 行上限。添加和编辑留在该 Tab 内，底部操作固定；横向切换与选中标记同步移动，不做淡入淡出。配置直接写入所属设备的 Agent 原生配置，核对修订版本并保留未编辑的私密值；不覆盖项目／策略配置，不因改配置停止当前回复。

### 配置组件

- 设置、设备、欢迎与添加设备流程复用 `internal/ui/configuration_forms.go` 的表单行、文本／多行输入、选择器、分组标题与操作按钮，以及共用的灰阶开关；排版数值集中在 `configuration_layout.go`。保留原生输入焦点、选区、IME、撤销和密码行为，不建立通用表单描述／验证框架。
- Tab 统一使用 `configuration_tabs.go`。横向标题下的内容（包含表单、状态与错误，共用的取消／保存操作保持在切换区外）以及账号/API 分段选择所关联的完整表单按项目顺序作为整体左右滑动，选中线／底色连续移动，使用 260 ms EaseOut，不用透明度切换；设置侧栏的纵向分类保留同组的原生交互与样式，但即时切换内容和选中态，不加位移动画。首次展示不播放切换动画；减少动态效果时立即切换。快速反向选择承接当前位移，旧页退场期间不可交互；选中底色绘制在所有文字下方。
- 动画不重置配置草稿、不发起或取消授权、不影响后台任务。实际高度的动画只有一个负责者，避免内容页与外层折叠区叠加缓动。
- 工作区主目录与附加目录均提供文件夹选择入口。本机使用系统目录选择器；远程使用由所属 worker 提供列表的原生弹窗，不打开控制 Mac 的文件选择器。目录导航只滑动列表，标题、路径栏与取消／确认操作保持固定；空目录可选，失败保留返回和重试。取消不改草稿，迟到结果不得跨设备、连接或草稿回填。详见 `docs/directory-browser.md`。

### 会话分叉与历史修改

- 分叉创建独立会话；修改历史用户消息则在原 SessionID 重新开始，替换该消息及后续对话。保留原普通草稿、手动名称、启动目录和暂停的待发队列，不自动回滚文件或创建 Git worktree。修改首条已发送消息后重新生成自动标题，后续消息修改不触发命名；新标题返回前保留旧名称，并沿用既有标题切换动画。
- 用户消息下方右对齐排列编辑、复制和发送时间，复用回复 footer 的灰色文字、图标与间距；操作行不进入正文选区，发送时间使用 worker 持久化的接纳时间，历史缺失则显示未知。历史消息在原位展开独立编辑框，保留附件；底部 composer 与普通草稿保持独立可用。展开和收起使用真实高度动画，保持编辑消息的阅读位置。原位编辑底部仅保留取消与回车图标确认按钮，不展示说明文案。确认后编辑框立即以真实宽高动画收回为修订消息气泡，与后续消息的顺风散沙退场同时开始；原生内容从左向右风化为细颗粒并向右飘散，不做整块模糊或水晕。最后颗粒退场后再收拢高度，完整退场结束时显示“进行中”并提交重开；减少动态效果跳过碎散。历史 reset 与新输入到达之间保留本地修订消息气泡，新消息承接原消息的阅读锚点。分叉放在回复底部复制右侧、时间与用量之前；所选回复之后的内容先渐隐，分叉视图承接同一回复的位置，避免空视图和默认滚动到末尾。新分叉的预填内容只能来自与 worker 确认的源 ThreadID／revision 对应的不可变历史前缀，并由正常权威加载更新。发送待确认时锁定历史编辑区，失败恢复原内容和编辑草稿。源协议只有轮次边界，轮次内的 Steer 追加消息不能冒充可单独截断的消息。
- 所有历史操作由所属 worker 接纳，持久化稳定操作标识，重连只查询，不重发未知输入。每次实际提交历史替换（含已保存 fork 的继续完成）都重新核对 revision、执行目录、Git、配置及附件；旧线程迟到事件不能恢复被替换内容。
- 保留历史按 worker 拥有的轮次顺序与归属确定，不按消息落盘位置截断，以保留前轮迟到输出。历史替换事件必须同步清理各客户端关联的 items、turns、requests 与 plan。
- 工具历史默认折叠与滚动位置重置分开处理。后台初次／再次加载历史不得释放当前阅读锚点；仅实际切换会话时重置旧滚动状态，分叉和历史修改再交接到指定消息位置。

### 运行环境升级

- 安装变化只刷新所属设备的模型与能力目录，不中断正在执行的会话。当前轮的停止、Steer 与核对能力以实际会话进程为准；下一轮与队列配置按新目录核验，闲置会话接续新版前仍须确认没有活动轮、待处理请求或后台工具。
- 已选模型下线时保留原选择、普通草稿和队列，不自动切换默认模型。仅将不可用的模型名标红并禁用发送，不额外展示提示条或按钮；保留模型菜单入口，悬停说明原因，颜色变化复用现有动画；新配置通过验证后才接纳下一轮，历史重开也在提交截断前重新校验实际目标进程。

### 输入框引用

- `@` 在当前工作区所属设备搜索文件；已有会话只使用其已接纳目录。读取和预览由 owning worker 处理，不在控制 Mac 解析远端路径。选择后保存不可变快照，发送与队列保留选定内容；不得因目录变化扩大既有会话的访问范围。
- `/` 是跨 harness 一致的 Skill 菜单入口。目录与实际支持情况由所选 harness 提供，选中后保存 typed SkillReference 与所属设备／工作区／harness；具体命令语法和原生 skill 输入由 adapter 翻译，不拼入共享正文或解析 opaque ID。
- 文件与 Skill 选中后在触发位置形成“图标＋名称”行内标签，参与原生光标、整块删除、换行和撤销；不另起输入框上方的引用条。草稿、队列编辑和已发送消息保留引用位置，重开历史与分叉不得丢失；历史原位编辑使用独立的引用草稿，允许增删引用，不改动底部普通草稿。正文选区与整条消息复制包含标签名称。位置属于中立的输入展示数据，不传给 harness。
- 候选列表过滤时保留同一弹窗与既有结果，异步刷新不反复播放开合动画；旧查询回调不能覆盖新查询或重新打开已关闭弹窗。
- 候选列表保留输入框焦点，Enter／Tab 选择、方向键导航、Esc 关闭，IME 组合不触发选择或发送。异步文件／Skill 结果不得污染其他会话或抢回用户后来转移的焦点。标签与弹层复用既有灰阶密度和实际高度动效，尊重减少动态效果。详见 `docs/composer-references.md`。

### 界面行为

- Target the confirmed workflow: individual developer workflow, one focused session with background agents, optional two-session viewing, light/dark system appearance, keyboard-first interaction, next-attention navigation, and this Mac as a local execution target.
- 首次使用以无侧栏整窗显示设备 → Agent → 工作区初始化，采用已确认的 560 DIP 居中内容区。上下步与完成进入首页使用左右滑动，不做淡入淡出；其他展开与控件动效复用设置页／设备页。只有 owning worker 接纳 Agent 配置与工作区后才完成初始化，不创建空会话，保留首页草稿；旧客户端状态不因升级强制重新初始化。
- After setup, app startup opens the same full-page draft composer as New session and Cmd+N. Workspace-specific plus actions open that page with the owning workspace selected. Do not open a creation modal or create an empty runtime session just by entering the page.
- Serve design previews on the local network only. Do not publish designs or enable cloud relays; project-level artifact auto-publishing must remain disabled.
- The user wants no logo in the application UI. Use a restrained, cool monochrome appearance with macOS-like neutral surfaces. Do not use gray-green surface tints or blue selection fills; selected states must remain neutral.
- Keep branch information at the top-left inside the message composer, below pending actions and queued turns. Truncate long branches with the full value available on hover. Home places a searchable branch picker and an adjacent 新建 worktree checkbox in the same position. The checkbox controls isolated Git worktree creation inside the current workspace; it does not create an application workspace. Preserve branch and worktree choices per workspace. Existing sessions can switch branches only when idle and connected, with no pending requests; never switch an active agent’s branch or silently relocate an existing session. Repository state, checkout conflicts, and actual worktree creation must be confirmed on the owning device. Branch choices belong to that device and execution directory, not to all folders in a workspace; changing the main repository resets the home base branch to a valid repository default. Removing a primary folder must persist its replacement so readding it does not silently promote it. Do not repeat directory metadata or offer a directory picker in composers; new sessions inherit the workspace main and additional directories.
- Confirmed branch-switch behavior: treat changing a branch as a mutation of the actual shared checkout, including the main working directory. Navigating between sessions never checks out a branch. Home branch selection records draft intent; validate and perform any required checkout on the owning device at accepted submission time. Block switching if any session sharing that checkout is running, awaiting approval/answers, holds a dispatch reservation, or has indeterminate execution; switching and queue dispatch share the same worker validation/serialization boundary. Initially require a clean index and working directory, including untracked files, when actually changing branches; do not apply that restriction to ordinary same-branch submissions. Never auto-stash, force checkout, reset or discard changes. ## Conversation protocol

- Prototype fixtures are illustrative rather than live runtime evidence. Candidate component styles require user selection before adoption; freezing reference materials does not approve every historical variant.
- Use the pinned Codex contract in `design/protocol/codex-0.166.0/`, accounting for all item, request and notification types. Schema presence does not establish feature enablement or stability; adapters must follow the actual device runtime version and negotiated capabilities.
- Render Skill and file references as compact neutral capsules. Skill references use a visible Skill marker and the skill name, with no dollar sign; file references use the file glyph and filename. Align their height and radius, keep references at their native inline insertion positions with ordinary text, truncate long names and expose the complete name/path on hover.
- Keep Markdown rendering, tool grouping, diff statistics and state aggregation distinct from protocol item types. Deltas update their existing item, and final item/completed payloads are authoritative; do not render both raw and normalized responses as duplicate messages.
- For this snapshot, ordinary tool/requestUserInput questions have no explicit multi-select field. Use MCP array/enum forms for the protocol-backed multi-select example. Respect isBlocking for agent execution while leaving the ordinary composer available, and use serverRequest/resolved for request invalidation. Async agentMessage questions have no JSON-RPC requestId and need a separate answer path.
- In permission requests, keep the permission subset choices separate from grant lifetime. Use the actions 允许本轮 and 允许本会话 to choose response scope turn/session; do not present lifetime as another permission checkbox. Preserve the selected subset and emit only granted permissions in response previews. Keep radio and checkbox geometry isolated from generic text-input styles.
- Keep review interactions faithful to the protocol: mark original request sources handled and append confirmed results in chronological order, retain numeric/boolean form types, validate all supplied fields, and preserve selected permissions plus deny constraints in entries profiles. Scope labels belong to actions. Do not hide Permission on narrow layouts.
- Token usage last means the latest request. Only compose a turn aggregate from a same-thread baseline before turn/started and the matching turn/completed event; otherwise keep the latest-request label and do not invent completion or duration. Compute diff counts and approval file targets from the associated data, never fixed sample labels.
- Preserve native-content boundaries for arbitrary MCP results and UI resources. Provide media/resource/JSON/unknown fallbacks; do not assume an unlimited catalog of provider-supplied business cards or silently embed external HTML.

## Reliability and verification

- Keep network operations, process I/O, and expensive parsing away from the UI thread.
- Bound retained output and rendering work. Avoid rebuilding complete conversation history for each streamed delta.
- Distinguish queue (next turn), steer (guidance to active work), and interrupt (cancellation request) in the domain and capability boundary. Do not silently implement steer by cancel-and-restart. Keep user drafts until acceptance is confirmed; an accepted steer is not proof that the model already acted on it.
- Reconnect and resume without silently replaying user prompts or commands. Preserve source session identifiers and distinguish interruption, transport loss, failure, and completion.
- Keep authentication and host verification explicit in the connection layer. Never disable SSH host verification as a convenience default.
- Use the current official Codex app-server documentation and the schema for the pinned version when implementing the adapter.
- Verify lifecycle and protocol behavior with focused integration checks: concurrent sessions, device disconnection, reconnect, pending approval, cancellation, and interrupted streams.
- Verify visible UI on macOS, including Chinese input, text selection, long conversations, keyboard focus, and multiple active agents.
- Report the checks actually performed and unresolved limitations. Mockups and written designs are not evidence of a working runtime integration.
